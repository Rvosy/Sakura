# Sakura 长期记忆

按角色保存个人画像、相处约定、共同经历和聊过的人与事，统一使用实体、属性、关系三张业务表。插件 ID 为 `sakura.memory.mem0`，升级保留已有设置和数据。

## 使用

2.0 版本需配合 [Sakura 的记忆重构分支](https://github.com/Rvosy/Sakura/tree/refactor/memory-system)使用，宿主包含历史范围读取和工具来源接口。启动开发版的方法见 [源码运行](https://github.com/Rvosy/Sakura/blob/main/docs/guide/setup.md#从源码运行)。

在 [Sakura](https://github.com/Rvosy/Sakura) 中，打开“设置 → 插件 → 更多 → 从 ZIP 安装…”，选择插件包，安装后启用。

也可以下载 [Sakura-Mem0 独立仓库](https://github.com/Rvosy/Sakura-Mem0)的源码 ZIP，通过“设置 → 插件 → 更多 → 从 ZIP 安装…”导入。插件使用 Plugin API v4，所需宿主服务见 `plugin.yaml`。

启用后即可在“设置 → 记忆”中添加、编辑和搜索记录，中文关键词检索不需要模型。在组件页下载 BGE 中文向量模型后，会增加近义表达检索。模型只在主动下载时联网；下载或索引失败不影响正文和关键词检索。

在“设置 → 模型”中选择记忆整理模型。自动整理默认每 8 轮运行一次，已有显式配置继续生效。整理请求只发送本批对话及相关记忆；采用远程模型时，这些资料会发送到所选提供方。

首次安装需要联网下载 `requirements.txt` 中的 Python 依赖。插件包不包含 Python 运行环境、模型权重或用户数据；下载源码后仍需在 Sakura 中安装，并准备所需资源。

记忆页默认打开“个人画像”，展示你的称呼、身份、习惯与偏好。“相处约定”保存交流方式和边界；“共同经历”保存事件、聊过的话题和当前事项，按原文时间排序；“人与事”按对象展示聊过的人、项目、地点及其联系。每条记忆都有独立卡片，可搜索、新增和编辑。编辑时可修改对象、信息项和正文；展开“用途与原文”可查看依据、调整用途或固定内容。固定记录不接受后台整理修改和删除。

标为“不再适用”的记录退出自动召回；当前事项完成后也不再自动加入聊天，仍可主动搜索。

“高级设置”集中提供立即更新、合并重复记忆、修复检索和导入导出。立即更新会处理未达到轮数门槛的待整理对话。合并只处理对象、信息项、关系、正文、用途和状态相同的自动记录，保留原文依据和修改历史；手动编辑或固定的记录保持原样。修复检索重新生成向量，正文不变。

历史记录导入后不会自动重放或提炼。需要补整理时，在记忆页的“高级设置”中展开“从旧聊天补充记忆”，填写包含首尾两天的日期范围，点击“开始整理”。任务支持停止；同一范围再次启动会继续未完成部分，已处理的原文不会重复写入。

导入导出保留正文、时间、属性、证据和删除标记，不调用整理模型。相同 ID 的冲突保留本地值。文件格式见 [Sakura 数据管理](https://github.com/Rvosy/Sakura/blob/main/docs/guide/data.md#导入导出聊天和记忆)。

“从文本提取记忆”使用记忆整理模型处理粘贴的笔记或聊天片段，先生成候选。用户可以修改内容、对象和用途，勾选后一起保存。原文保留为文档证据，确认后的条目属于手动记忆，不伪装成聊天消息。提取失败或停止时不写入记忆，保存失败时整批回滚。

更新保留已有设置、资源和启停选择，操作方法见 [Sakura 插件升级指南](https://github.com/Rvosy/Sakura/blob/main/docs/guide/plugins.md#更新与修复)。

## 存储与召回

`data/memory/memory.sqlite3` 中，`entities` 保存人物、项目、事件等对象，`entity_attrs` 保存对象的信息，`entity_relations` 保存对象之间的关系。证据、版本、删除标记和整理进度由配套表保存。编辑、自动整理、检索和导入导出共用这份数据。

旧 SQLite 记录自动迁入三表，保留 ID、时间、证据和删除状态；旧 Qdrant、历史库和档案的迁移保留原文件。没有对象信息的旧事实放在“共同经历”的未分类内容中，可手动归类或从旧聊天补整理，不凭摘要猜测人物关系。

每轮先读取用户常驻档案和有效约定，手动添加的约定无需固定也会参与聊天。其余内容用本轮输入检索 FTS5 关键词和 BGE 向量候选，通过 RRF 合并排序；对象、信息项和关系也参与检索。记忆工具可按对象、信息项或关系另一方精确查询。自动召回最多补充 5 条相关记录，允许零召回。单次检索失败不阻断聊天，后续请求会正常尝试。

向量保存在 `data/memory/vectors/`，使用 FastEmbed 与 Qdrant 本地 SDK。索引可以重建；新的索引完成后才切换，重建期间的修改随后补入。BGE 模型为 `BAAI/bge-small-zh-v1.5`，512 维。旧的 MiniLM 模型不再用于召回。

自动整理提取对象、单一事实、关系及来源，正文与原文证据分开保存。候选无法核对时保留待处理消息，不推进游标。整理、更新与证据规则见[时间线与记忆规格](../../../docs/specs/timeline-memory.md)。

## 参考实现

参考 [MaiBot](https://github.com/Mai-with-u/MaiBot)、[A_memorix](https://github.com/A-Dawn/A_memorix) 的检索与记忆工具设计、[Letta](https://docs.letta.com/v1-sdk/memory/memory-blocks) 的常驻记忆、[AIRi](https://github.com/moeru-ai/airi/blob/main/packages/stage-ui/src/tools/memory.ts) 的独立事实与按需读取，以及 [Graphiti](https://github.com/getzep/graphiti) 的事实来源和时间处理。Sakura 使用本地 SQLite，不引入独立图数据库。

[Mem0](https://arxiv.org/abs/2504.19413) 和 [MemoryBank](https://arxiv.org/abs/2305.10250) 提供长期对话记忆的研究参考。三表是数据组织方式，效果还取决于事实提取、更新和召回。[LongMemEval](https://arxiv.org/abs/2410.10813) 中的信息提取、跨次聊天、时间推理、知识更新与拒绝猜测，也是检验聊天记忆的重要场景；本项目的业务回归不等同于这些论文的完整评测。
