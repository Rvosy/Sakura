# Sakura 长期记忆

按角色保存长期事实、共同经历和协作约定。插件 ID 保持 `sakura.memory.mem0`，升级可以继续使用已有设置和数据。

## 使用

2.0 版本需配合 [Sakura 的记忆重构分支](https://github.com/Rvosy/Sakura/tree/refactor/memory-system)使用，宿主包含历史范围读取和工具来源接口。启动开发版的方法见 [源码运行](https://github.com/Rvosy/Sakura/blob/main/docs/guide/setup.md#从源码运行)。

在 [Sakura](https://github.com/Rvosy/Sakura) 中，打开“设置 → 插件 → 更多 → 从 ZIP 安装…”，选择插件包，安装后启用。

也可以下载 [Sakura-Mem0 独立仓库](https://github.com/Rvosy/Sakura-Mem0)的源码 ZIP，通过“设置 → 插件 → 更多 → 从 ZIP 安装…”导入。插件使用 Plugin API v4，所需宿主服务见 `plugin.yaml`。

启用后即可在“设置 → 记忆”中添加、编辑和搜索记录，中文关键词检索不需要模型。在组件页下载 BGE 中文向量模型后，会增加近义表达检索。模型只在主动下载时联网；下载或索引失败不影响正文和关键词检索。

在“设置 → 模型”中选择记忆整理模型。自动整理默认每 8 轮运行一次，已有显式配置继续生效。整理请求只发送本批对话及相关记忆；采用远程模型时，这些资料会发送到所选提供方。

首次安装需要联网下载 `requirements.txt` 中的 Python 依赖。插件包不包含 Python 运行环境、模型权重或用户数据；下载源码后仍需在 Sakura 中安装，并准备所需资源。

记忆页默认列出全部记录，附简短分类、固定标记和更新时间。可以搜索，或点击每条右下角的铅笔图标编辑。需要单独核对长期信息或交流规则时，在“查看记忆”中选择“用户画像”或“相处约定”。这两类内容会随聊天上下文提供给角色，其他记忆按当前话题召回。编辑时默认只显示正文；展开“用途与原文”可以调整用途、查看依据，或固定内容，阻止后台整理修改或删除。

标为“不再适用”的记录退出自动召回；当前事项完成后也不再自动加入聊天，仍可主动搜索。

在记忆页切换到“记忆维护”，可以更新最近的记忆、合并重复记忆或修复记忆检索。每项操作只保留一句用途说明和按钮，有待处理内容、任务进度、执行结果或问题时才显示对应信息。立即更新会处理未达到轮数门槛的待整理对话。合并只处理正文、用途和状态完全相同的自动记录，保留来源依据与原条目的修改历史，手动编辑或固定的记录保持原样。修复检索会重新生成向量，记忆正文不变。后台自动更新继续按原配置运行。

历史记录导入后不会自动重放或提炼。需要补整理时，在插件设置中展开“从旧聊天补充记忆”，填写包含首尾两天的日期范围，点击“开始整理”。任务支持停止；同一范围再次启动会继续未完成部分，已处理的原文不会重复写入。

导入导出保留正文、时间、属性、证据和删除标记，不调用整理模型。相同 ID 的冲突保留本地值。文件格式见 [Sakura 数据管理](https://github.com/Rvosy/Sakura/blob/main/docs/guide/data.md#导入导出聊天和记忆)。

更新保留已有设置、资源和启停选择，操作方法见 [Sakura 插件升级指南](https://github.com/Rvosy/Sakura/blob/main/docs/guide/plugins.md#更新与修复)。

## 存储与召回

`data/memory/memory.sqlite3` 保存正文、版本、来源证据、删除标记和整理进度。旧 Qdrant、历史库和档案在首次启用时迁入，原文件保留。旧摘要按原样保留；迁移不能替它们补出原本没有的证据。

每轮先读取常驻档案和有用户依据的协作规则，再用本轮输入独立检索 FTS5 关键词和 BGE 向量候选，通过 RRF 合并排序。自动召回最多补充 5 条相关记录，允许一条也不返回。只有明确承接上文的问句才补入上一条用户消息。

向量保存在 `data/memory/vectors/`，使用 FastEmbed 与 Qdrant 本地 SDK。索引可以重建；新的索引完成后才切换，重建期间的修改随后补入。BGE 模型为 `BAAI/bge-small-zh-v1.5`，512 维。旧的 MiniLM 模型不再用于召回。

自动整理使用一次结构化模型请求。每条事实要能对应到具体原文；助手复述不能作为新的用户事实。档案和约定保留用户原话，防止否定或数字被摘要改写。修改时检查记录版本和证据时间，较旧历史不能覆盖新事实或人工编辑。

## 参考实现

参考 [MaiBot](https://github.com/Mai-with-u/MaiBot)、[A_memorix](https://github.com/A-Dawn/A_memorix) 的双路检索和记忆工具设计，以及 MaiBot 中 [maisaka](https://github.com/Mai-with-u/MaiBot/tree/main/src/maisaka) 的人物档案与中期记忆拆分。按本地单用户场景取舍，没有引入图数据库、访问强化或强制补足召回数量。实现使用 SQLite、jieba、FastEmbed 和 Qdrant SDK，未复制这些参考项目的代码。
