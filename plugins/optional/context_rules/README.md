# 对话规则

在插件设置中填写一段上下文，说明这次希望怎样交流，或补充需要使用的内容。默认内容让回复更简短。
插件通过公开的 Context 和设置接口工作，不修改角色文件；当前角色信息与填写的上下文一起参与对话。

0.2.0 需要支持 Context schema 2 的 Sakura 构建。旧版本不支持时，插件会启动失败并报告
`CONTEXT_RULES_HOST_UNSUPPORTED`。宿主不再要求把内容分成“行为规则”和“参考资料”，也不判断它与角色卡是否冲突。

## 安装与使用

1. 打开 Sakura 的“设置 → 插件 → 更多 → 从文件夹安装…”，选择本目录
   `plugins/optional/context_rules`。收到 `.sakplugin.zip` 包时，使用“从 ZIP 安装…”。
2. 在插件列表中选择“对话规则”，启用插件并确认它已正常运行。
3. 打开“插件设置”，编辑“上下文”。点击“完成”后，再点击设置窗口的“应用”。
4. 回到聊天窗口发送一条消息。保存的修改从下一轮对话生效，当前正在生成的回复继续使用本轮已采集的内容。

内容可以留空。怎样安排要求、背景或引用，由你自行编写。当前设置界面使用普通文本输入框，可以用连续句子填写。

例如，日语练习时填写：

> 主要用日语和我交流。发现我的日语有明显语法错误时，先给出自然的改写，再继续对话。
> 我要求中文解释时，用中文说明原因。
> 我目前正在学习日语过去时，今天练习介绍周末做过的事情。

需要简洁表达时填写：

> 先直接回答我的问题。通常用两到三句说明，不重复问题。遇到需要操作的任务时列出具体步骤。
> 我要求详细解释时再展开。

内容通过提示词影响模型，执行程度取决于所用模型。本插件要求填写的内容完整进入本轮上下文；
加载失败或上下文预算不足时，本轮会报错。

停用插件后，下一轮不再添加这些内容；已有聊天记录和已保存的插件设置会保留。
长期记忆仍按原有方式整理和保存。

## 旧配置

插件 ID 仍是 `context_rules`。旧“行为规则”和“参考资料”按原顺序合并，非空字段之间加入两个换行；
空白与正文原样保留。打开设置不会改写配置文件，点击“应用”后才保存新 `content` 字段，旧字段也保留。
已有 `content` 时始终使用它，清空后不会从旧字段恢复内容。

旧字段各允许 4096 字符，合并后最长为 8194 字符，新的输入框可容纳这些文本。
插件将整段内容声明为必需内容，默认对话实现不会按旧可选片段的字符额度截断它。

## 打包

在仓库根目录运行以下 PowerShell 命令，输出路径必须尚不存在：

```powershell
runtime\python.exe tools\release\package_optional_plugin.py --source plugins\optional\context_rules --output dist\context_rules-0.2.0.sakplugin.zip
```

macOS/Linux 使用 `runtime/bin/python`，路径分隔符改为 `/`。插件没有额外 Python 依赖，不需要下载模型或资源。

开发其他上下文插件时，可以参考 `plugin.py` 的能力检查、`scope: turn` 登记和纯内容返回值。
`scope`、`required` 和失败策略是默认对话实现的消费约定。插件停用时，SDK 和宿主负责撤销登记；
无需修改 Core 来登记业务类别。当前对话仍由默认 Assistant 和 ChatPipeline 执行。
