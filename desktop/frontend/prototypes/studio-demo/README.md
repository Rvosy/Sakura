# 角色工坊 Demo

在现有工坊里评审多形态编辑：同一个角色可以添加第二套立绘，也可以模拟通过插件添加 Live2D 或 3D 模型。
外壳载入评审时保存的工坊 HTML 和控制器快照，并复用当前公共样式；基础信息、人设卡、语音模型、参考语音和配色页面继续可操作。

## 打开

在仓库根目录运行：

```sh
runtime/bin/python -m http.server 8770 --bind 127.0.0.1 --directory desktop/frontend
```

打开 <http://localhost:8770/prototypes/studio-demo/>。Windows 将 Python 路径换为 `runtime\python.exe`。
设置 Demo 的“修改角色”也会进入这里；`?character=sakura` 可以指定演示角色。

## 评审流程

1. 在“角色形态”中点“添加形态”，选择“立绘”，命名为“第二套立绘”。
2. 添加图片或导入文件夹。可以使用示例资源，也可以选择本地图片；修改表情标签、选择默认图，点击缩略图查看图片。
3. 切换两套立绘，检查各自的图片、名称和默认图。需要时将其中一套设为角色的默认形态。
4. 保存角色，再切到顶部“设置预览”。“显示方式”只列出已保存到角色包的形态；“修改角色”可回到工坊。
5. 顶部“可用插件”可以模拟启用 Live2D 或 3D。添加入口随可用插件变化；停用插件会锁定相应编辑区，保留资源。

新建角色、草稿自动保存、关闭后重新打开、放弃修改和添加到角色列表沿用正式工坊的交互。
数据只存在当前页面内存中；刷新页面或“重置演示”会恢复初始状态。切换角色、工坊与设置预览会保留本次演示数据。

## 实现与边界

- `frame.js` 在内存中接入 `snapshot/` 保存的评审时控制器和表单。该快照仅用于历史交互 Demo，不进入正式工坊；公共样式与基础组件仍复用现有文件。
- `surface.js` 管理形态列表和各类型编辑区。每套立绘有自己的资源 ID、表情图和默认图，角色默认形态单独记录。
- `bridge.js` 用页面内存替代 Tauri/Core，不读写真实角色、草稿或设置。选择的本地文件只在本页使用，不上传。
- `model.js` 提供示例数据和保存/放弃行为；设置预览从已保存的角色构造选项，未保存草稿不会混入。

当前类型由 `model.js` 预先定义，页面由 `surface.js` 实现，“可用插件”只切换模拟列表；没有读取真实插件清单或加载插件编辑模块。
Live2D、3D 的字段和文件选择只演示编辑入口，不加载模型引擎，也不校验真实模型包。
示例立绘复用仓库已有的 N.A.V.I. 图片；示例文件夹用同一张图片展示多条表情记录。
真实语音合成、系统取色、原生窗口和 `.char` 归档未接入；导出入口明确改为下载演示 JSON，不生成伪造角色包。
这些演示字段不定义正式资源协议。正式后端实现与验证见[角色能力插件化计划](../../../../docs/plans/character-composition.md)实施。

已明确的方向是由每个表现插件提供资源解释、专属编辑区、模型控制说明与输出格式、解析校验和渲染执行。
工坊保留列表、命名、默认选择、移除、草稿和保存流程；专属编辑区可由插件编写布局与交互，不限于当前固定页面或声明式表单。
立绘的情绪标签和选图属于立绘插件，其他形态可有自己的参数、动作与状态控制；只提供一个设置页面不能完成运行时接入。
选择当前形态与控制该形态是两件事，Demo 不验证后者。架构职责见 [ADR-0046](../../../../docs/adr/0046-composable-character-resources-and-renderer-host.md)。

本次还修复了正式工坊角色下拉菜单的重复关闭问题：移除已聚焦的菜单会触发 `focusout`，关闭逻辑需要防止重入。

## 验证

模型测试验证形态隔离、草稿与保存结果分离、新角色可见性及插件停用后的资源保留：

```sh
node --test desktop/frontend/tests/studio-demo-model.test.js
```

浏览器回归入口复用实际工坊页面，覆盖角色下拉菜单重复关闭、第二套立绘保存和设置预览：

```sh
runtime/bin/python desktop/frontend/tests/studio-demo.journey.py
```

正式工坊使用插件编辑器，真实数值插件与 Core Boundary 的浏览器回归入口是 `desktop/frontend/tests/visual-plugin.journey.py`。
本 Demo 继续验证历史交互，不作为当前资源格式、模型引擎或原生窗口的验证证据。
