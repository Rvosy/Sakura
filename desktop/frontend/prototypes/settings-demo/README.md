# Sakura 设置体验 Demo

先看完整设置外壳，再决定角色能力拆分后的设置是否容易理解。
这是独立的本地前端评审入口，正式程序的设置页面和后端均未改动。

## 打开

在仓库根目录运行：

```sh
runtime/bin/python -m http.server 8770 --bind 127.0.0.1 --directory desktop/frontend
```

浏览器打开 <http://127.0.0.1:8770/prototypes/settings-demo/>。
Windows 将命令中的 Python 路径换成 `runtime\python.exe`。

## 如何评审

顶部“新增设置 / 原版对照”切换两种页面，共用已应用的模拟设置。
切换演示场景或点“重置演示”会重置所有模拟数据；刷新页面也会重置。

| 场景 | 重点查看 |
|---|---|
| 只有立绘 | 原有页面是否仍然熟悉，多一行显示方式会不会增加负担 |
| 多种表现 | N.A.V.I. 的立绘、冬装、Live2D、3D 选项；换到其他角色后只显示其自己的资源 |
| 缺少插件 | 默认资源所需插件缺失时的说明、模拟安装与启用，以及改选立绘的路径 |

“显示方式”旁的“设置”打开正式插件设置弹窗。插件参数遵循原有“完成后暂存、应用后生效”的流程。
下拉框只列出当前角色包实际包含的形态，首次打开时选中包内默认形态。
新增设置页统一使用“角色大小”，适用于立绘、Live2D 和 3D。
角色、显示方式和其他设置可应用，也可在关闭时放弃。显示方式、语音选择和记忆示例按角色分别保留。
“修改角色”进入[角色工坊 Demo](../studio-demo/README.md)，可继续评审多套立绘和插件形态的添加与编辑。

## 复用与模拟范围

`app.js` 直接读取 [正式设置 HTML](../../settings/index.html)，复用其样式、字体、图标和全部页面。
`frame.js` 在内存中加载 [正式设置控制器](../../settings/settings.js)，为显示方式选择接入 dirty、校验、应用和取消；
不会改写生产文件。原版对照不显示新增的显示方式行或模拟表现插件。

`bridge.js` 提供纯内存 Tauri 调用替身。`data.js` 中现有插件的字段、条件显示和高级选项按
`07285a99` 的 GPT-SoVITS、Genie TTS、Mem0、SenseVoice 和手机端声明整理，数值、角色和记忆均为演示数据。
立绘插件、Live2D 和 3D 的设置字段只是待评审示例，不是当前 Manifest、资源格式或 SDK 合同。

文件选择、导入导出、系统操作、网络连接测试、模型下载和插件安装使用模拟响应或入口提示。
角色工坊使用独立的演示数据；从这里进入工坊不会携带本页尚未应用的设置。
不会读取真实用户目录、保存实际设置、连接模型服务、启动语音或使用麦克风。真实桌宠、透明窗口、拖拽、
点击穿透和原生预览需要在正式接入后另行验证。

## 维护与验证

生产设置入口变化时，先核对 `frame.js` 的少量接入点；匹配失败会报错，不静默展示不完整页面。
资源路径依赖整个 `desktop/frontend`，不能单独打开或只复制 demo 目录。

浏览器检查覆盖全部设置分类、应用、放弃、重新打开、切换角色、插件设置、缺失处理、原版对照，
以及 900 px 宽窗口的底部操作区。它证明设置外壳的模拟交互，不证明模型或原生桌面能力。

架构范围与后续顺序见[角色能力插件化计划](../../../../docs/plans/character-composition.md)。
