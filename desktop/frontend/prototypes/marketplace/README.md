# 插件市场视觉验收 Demo

在当前主程序的设置页上增加市场入口。正式 HTML、样式、插件列表与详情、设置弹窗、筛选和底部操作区直接使用
`desktop/frontend/settings/` 中的代码；不复制旧插件页，也不重新绘制设置外壳。

这是需求讨论与视觉验收入口，安装、更新、联网、缓存和运行状态均为模拟；不会读取用户配置或实际安装插件。

## 打开和比较

在仓库根目录执行：

```powershell
.\runtime\python.exe -m http.server 8772 --bind 127.0.0.1 --directory desktop/frontend
```

打开 <http://127.0.0.1:8772/prototypes/marketplace/>。

- 默认打开正式“已安装”页面，标题旁增加“已安装 / 市场”。标题不再显示数量，数量保留在下方“全部”分类中，切换时入口位置固定。
- 顶部“原版对照”使用同一份模拟数据，加载原始设置页面，不注入市场界面和样式。
- “加入市场”恢复新增入口。进入市场后可搜索、按领域筛选，点击卡片下方“详情”打开居中弹窗，查看详情与版本记录。
- 安装完成后，“在已安装中管理”回到正式插件列表并选中目标；启停和设置仍由正式控制器处理。
- “下载失败”场景在首次下载时失败，再次点击重试恢复；“离线”场景展示缓存或无缓存状态。
- 切换对照会重新加载前端并丢弃尚未应用的设置、未完成的模拟任务；已完成的模拟安装保留。
- 刷新整个页面或点击“重置”恢复初始示例。顶部验收工具栏不属于产品界面。

## 本轮建议的用户流程

| 位置 | 建议行为 |
|---|---|
| 已安装 | 保留当前分组列表、右侧详情和插件设置，市场不接管本地管理逻辑 |
| 市场 | 卡片浏览，名称、简介、作者、领域、推荐版本直接可见；卡片统一提供“详情”入口 |
| 详情 | 居中弹窗展示介绍、安装影响、当前兼容版本和版本记录；底部安装、更新或进入管理 |
| 首次安装 | 在详情底部点击“安装插件”后下载并调用安装器，完成后保持未启用，回到已有管理入口启用 |
| 更新 | 展示已安装版本与目标版本；用户主动发起，失败保留旧版本、配置和数据 |
| 兼容性 | 推荐最高的可用稳定兼容版本；新版不兼容时解释为何选择旧版 |
| 撤回与预发布 | 保留版本记录和原因，不作为首期默认安装目标 |
| 离线 | 有有效缓存时继续浏览；首次加载失败时给出连接失败状态 |

Demo 的兼容判断只使用示例 Plugin API 版本。正式选择算法还必须考虑宿主能力、平台、Python 与依赖要求；
不能把这个数组筛选函数当成生产版本解析器。卡片中的包体积不包含模型、浏览器和语音运行组件。

这轮重点验收入口位置、卡片密度、详情方式和状态是否容易理解。更新事务、任意历史版本安装、固定版本、
下架后的已安装提示等行为，需要在正式协议阶段继续细化。

## 与 v2 架构文档的对齐建议

该文档作为讨论资料，其“必须执行”等语句不自动扩大本次实施范围。建议采用 GitHub 治理、Actions 构建、CDN 分发、
客户端消费的主线；角色 Hub 单独安排。本次没有建立 Registry、访问云账号或发布服务。

1. **Catalog 直接由下载 CDN 提供。** 文档一方面要求 VPS 不在关键路径，一方面给出 `api` 域名作为主目录入口。
   建议首版统一为下载域名上的静态 Catalog，目录和包均能在 VPS 不可用时访问。
2. **协议映射现有 manifest。** 当前使用 `api: 4`、`id`、`version`、`entry`、`provides`、`requires` 和
   `presentation`。已有 `playwright_browser` 等 ID 不需要改为反向域名格式。文档中的最低 Sakura 版本并非当前
   安装器已有的兼容约定，需先定义再使用。
3. **普通自定义目录不新增摘要机制。** 文档中的包 SHA-256 和安装记录摘要与仓库当前约定冲突。
   首版建议使用 HTTPS、明确版本、完整 commit 引用、不可覆盖的产物 URL、大小限制、ID/版本匹配与 ZIP 结构校验。
   这些检查不等于发布者身份认证；若确定需要签名，应另行选用标准认证协议并明确验证对象。
4. **审核的是具体版本。** `plugins.json` 中的 ID 与仓库地址只表示收录关系，不能证明后来发现的版本已经批准。
   批准记录需明确版本、完整 commit 和 manifest 快照，构建消费该记录；同版本更换 commit 应拒绝。
5. **更新需要独立实现。** 当前 `LocalPluginInstaller` 会拒绝相同插件 ID，不能把下载 ZIP 后调用安装器直接称为更新。
   更新还需要暂停旧实例、暂存代码与依赖、发布切换以及失败回退。Demo 只演示预期状态。
6. **安装包与运行依赖分别验证。** 从指定 commit 构建 ZIP 只固定插件源码。Python 依赖解析、wheelhouse、
   本地组件下载需要另行约定，不能据此声称全部运行内容均经过同一次审核。

仓库已有的 [插件市场计划](../../../../docs/plans/plugin-marketplace.md) 仍包含软件内投稿和自建 API 方案。
若采用本次 v2 方向，正式实施前需要收敛并更新该计划；当前 Demo 不将讨论中的取舍写成已生效 Spec。

## 后续实施顺序

| 阶段 | 可验收结果 | 主要落点 |
|---|---|---|
| 当前 | 当前正式设置页上的交互 Demo，确定视觉与状态表达 | 本目录 |
| 协议 | Catalog、版本批准事实、包约束、来源记录与兼容选择约定 | 产品 Spec、manifest 与安装器边界 |
| 样板分发 | 一个真实插件从明确 commit 构建，经 CDN 下载到隔离根安装 | Registry CI、打包脚本、下载服务与现有安装器 |
| 浏览与安装 | 正式市场读取 Catalog、缓存、下载、取消、失败反馈及安装记录 | 前端设置页、Rust 桥接、Core 安装入口 |
| 更新与治理 | 原版本可恢复，配置与数据保留；版本撤回和逐版本审核可追溯 | Core 更新事务、Registry、客户端状态 |

源码检查、CI 审核和下载均不可执行未受信任仓库里的发布脚本；具有发布凭据的任务与第三方代码处理应分开。
自动发布新版本、评分、账号、点赞和角色网站不作为首版市场浏览安装的前置条件。

## 实现与验证边界

`loader.js` 读取正式 HTML，`frame.js` 注入纯内存 Tauri 桥接。控制器在内存中只增加现有插件 feature 的引用与
初始化完成通知，以便模拟安装后调用其 `refreshCurrent` 和 `openPlugin`；没有重写其渲染或业务逻辑。
市场样式通过 CSS `@scope` 限定到新增界面。正式插件页以底色区分底部操作区，不再显示操作栏横线。
原版对照完全不加载这些样式。
排序复用正式 `select-control.js` 的主题浮层；排序栏位于列表滚动区外，避免控件焦点边缘被裁切。
下载进度复用正式 `resource-progress`，通知复用正式设置页的 `notify`。操作完成只提示结果，
不追加设置、数据保留等说明，也不在详情底部重复解释安装与启用。

`installed-fixture.json` 的名称、版本、简介和分类来自本次工作树中的 14 个内置插件 manifest。
插件启用状态和配置为演示值；部分设置表单复用既有设置 Demo 的样例，未配置样例的插件不提供完整后台设置数据。
因此可以比较当前程序的页面结构与样式，但不代表用户当前机器上的插件状态、所有插件表单或个性化主题已经复刻。

市场新条目、版本、更新说明、日期与包体积是演示数据，不能作为真实插件的发布信息。
原版与新增市场共用默认 Sakura 主题、本地字体和 Lucide 图标，无远程字体或图片依赖。

验证记录：浏览器中比较原版与“加入市场”的已安装视图，除标题旁新增切换入口、移除数量外，导航、筛选栏、列表、详情与底部操作区的
位置、尺寸、字体、背景色一致；后续视觉修订同步调整了正式插件页的分组样式。已检查卡片统一“详情”入口、居中弹窗底部安装、安装后定位正式列表、取消安装、
更新失败保留原版本及重试、无结果、无兼容版本、两种离线状态、恢复连接和原有插件设置弹窗。
检查了 900 px 窄窗口下的卡片和详情底部操作区；浏览器未报告控制台错误。JavaScript 语法检查与 `docs` profile 通过。
这些结果只证明前端模拟流程，不代表真实下载、依赖安装、更新回滚或原生 Tauri 窗口已经验证。

控件修订后复查了搜索焦点、排序菜单展开与键盘选择、离线禁用与恢复、下载进度和卸载成功提示。
已有插件设置与列表测试 38 项通过，未增加只断言文案或 CSS 数值的测试。

## 分组方式的视觉修订

参考 [JetBrains 插件管理](https://www.jetbrains.com/help/idea/managing-plugins.html) 与
[VS Code 扩展市场](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace) 官方文档中的界面截图。
JetBrains 的条目以间距、图标和选中底色区分，VS Code 的插件头部以字号和间距组织信息；
两者仍在主要面板或标签页边界使用分割线，并非所有区域都无边界。

本 Demo 保留 Sakura 的字体、配色和卡片外框，移除卡片内部、市场状态栏、详情标题与版本记录的横线。
详情资料使用一块浅底色分组，正文和版本用标题、间距组织；固定操作区以底色区分。
正式“已安装”页也已调整：左侧分类标题后的横线移除，右侧启用区使用浅底色，资料与技术信息用留白区分。
这些样式直接修改于 `settings/styles.css`，Demo 和主程序共用；其他设置页尚未统一调整。
