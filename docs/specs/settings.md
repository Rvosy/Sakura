# 设置与配置应用

设置模块让用户查看能力、编辑草稿、保存配置并确认是否生效。页面组织按用户的使用流程安排，配置仍由实际业务模块拥有；把一项能力移到插件，不应迫使用户换一套保存方式。

## 职责与模块联系

| 所有者 | 负责的数据或行为 | 设置模块如何连接 |
|---|---|---|
| Shell | 外观、字幕、窗口、系统开机启动及原生文件选择 | 提供受控读取、预览、保存与系统操作 |
| Core | 当前角色、模型引用、角色数据和业务应用协调 | 校验当前身份，调用领域保存和局部应用 |
| 模型提供方 | 连接、凭据、模型目录 | 通过插件区块及模型目录贡献提供编辑器 |
| Assistant 与其他插件 | 生成参数、语音、记忆、工具等自身配置 | 使用相同的配置和设置接口 |
| 设置窗口 | 导航、主题、草稿、未保存提示、保存结果 | 不直接写业务文件，不复制插件存储逻辑 |
| Collection 所属插件 | 记录格式、查询与增删改 | 宿主提供列表和编辑界面，记录仍由插件持有 |

设置窗口是主应用内的单例窗口。重复打开聚焦已有窗口，不重新初始化未保存输入；关闭设置不退出桌宠。Core 不可用时仍能打开窗口查看故障，恢复后在原窗口重新绑定。

## 页面与能力展示

日常参数放在相应功能页，少用的功能参数放在该页高级设置，运行环境与维护操作放在插件设置；版本、启停、依赖和卸载属于插件管理详情。API 地址和密钥放在模型服务页，不混入模型用途选择。

宿主持有导航分组、页面区域和通用组件。插件可以登记自己的命名空间页面，并把自己拥有的区块放到宿主或其他插件明确开放的区域。相同标题不等于同一身份，卸载或停用只撤销对应 scope 的贡献。

每个区块只有一个主要编辑位置。插件详情提供到功能页的跳转，存在独立维护区块时才显示插件设置入口；不能把同一份配置同时放在多个弹窗，形成互相覆盖的草稿。

界面按实际能力开放操作，不能仅凭插件已安装就宣称引擎可用。资源下载完成、插件运行、模型连接和业务就绪分别表达；缺失能力给出当前原因与可执行入口。

通用表单、资源状态、连接编辑、记录表格和插件前端模块共享宿主草稿机制。组件参数、页面放置及扩展方法见[插件 SDK](../development/plugin-sdk.md#设置区块动作与页面)，不在本规格重复维护字段表。

## 草稿与预览

读取配置形成编辑基线，用户修改形成草稿。修改后又改回原值不算未保存；无意义的对象引用变化或刷新次序不能把页面标脏。

私有编辑弹窗的“完成”只接受草稿，外层“应用”或“保存并关闭”才提交普通设置。取消或放弃恢复尚未提交的编辑，不影响其他窗口的输入。

外观预览只改变允许预览的临时运行状态，不提前写配置。失败、取消或关闭时结束预览并恢复有效状态；保存失败不能留下与已保存值不一致的假成功。系统功能按平台实际能力提供预览，不能用一个平台的效果承诺所有平台。

加载、刷新和异步动作绑定窗口、Core、插件及编辑对象身份。用户切到另一连接、角色或资源后，旧成功与旧失败都不得回填；并发读取合并或丢弃过期结果，不清空用户正在输入的值。

常规刷新保留焦点、滚动、筛选和输入法组合输入。Core 重建后在原窗口取得新快照，以用户实际修改的字段重建草稿，不用关闭重开来代替重新绑定。

## 保存流程与结果

1. 从实际变更中形成提交字段，按数据所属领域发送。未提交字段、未知扩展和其他区块数据保持原样。
2. 所有者检查本次业务输入并保存自身数据。单个文件的替换失败保留原文件；界面不重复实现底层文件事务。
3. 保存成功后应用到运行态，返回实际应用结果。普通热应用不重启无关插件或整个 Core。
4. 回读成功保存部分作为新基线，保留未成功部分的草稿与原始错误，允许用户继续处理。

| 结果 | 界面和业务含义 |
|---|---|
| unchanged | 本次没有有效变化，保留现有运行状态 |
| applied | 配置已保存并用于后续相关操作 |
| restart_required | 已保存，需要局部重载；宿主按当前保存流程处理目标与必要依赖 |
| error | 返回具体失败；若数据已保存但应用失败，必须明确区分 |
| partial | 多个所有者中只有部分完成，指出成功部分和失败对象 |

一次“应用”可能触及多个所有者，不承诺跨插件、跨文件的全局事务。后一个插件失败时不能假装前面的保存没有发生，也不能反向覆盖已成功保存的数据。回读用于确认真实状态，不自动重复执行失败写入。

正在执行的聊天、连接请求或合成任务使用开始时固定的配置；保存影响后续操作。应用失败保留可用旧运行态、已保存新值与恢复入口，下一次聊天不暗中重启或修复。

## 动作与 Collection

设置 Action 是明确执行的操作，例如测试连接、下载、诊断或导入。动作使用当前草稿；返回值只更新它声明的字段，不顺便提交整页设置。已执行的下载或数据库修改不会因后来放弃设置自动撤销。

耗时动作显示本次进度、取消和失败，不阻塞其他无关设置。原生文件选择取消后不执行动作，也不保存输入框中的临时路径或其他草稿。

Collection 用于便签、记忆等记录，不是配置字段的另一种存储。查询、创建、更新、删除由插件回调完成；创建与保存记录成功即持久化，外层“应用”不再次提交记录。

| Collection 归属 | 切换角色或重绑定时的行为 |
|---|---|
| character | 记录与草稿绑定当前角色；存在实际未保存编辑时先处理，不能带到另一角色 |
| global | 记录与角色无关；角色切换后保留仍有效草稿，重新绑定当前插件实例 |

普通目录刷新或同角色重新绑定不丢弃有效记录草稿。切换期间暂停旧请求；迟到查询、异步删除确认和保存结果都要核对原对象身份。删除确认属于对应记录操作，不授权删除其他角色或整个集合。

“保存并关闭”不会替用户自动创建或更新尚未保存的记录；这些草稿需要在记录编辑器中处理。Collection 的接口与归属声明见[SDK](../development/plugin-sdk.md#collection)。

## 模型与凭据编辑

连接、模型目录和消费方的完整分工见[模型服务规格](model-services.md)。

模型提供方拥有地址、凭据和可用模型目录；模型槽只保存 serviceKey/profileId/modelId 引用。模型页可以显示多个所有者的用途槽位，插件停用时隐藏其槽位但保留选择，重新启用后继续使用。

连接编辑采用凭据保持、替换和明确清除语义。已保存密钥不回显为普通表单值；空密钥可用于无认证服务，不因此生成空 Authorization。发现模型、手动编辑模型和测试连接使用当前草稿，只有保存才持久化。

模型发现结果只交给发起它的连接与请求。删除连接、切换对象或重载插件后，旧发现结果及选择弹窗失效；旧结果不能重新创建连接或替用户选中模型。

连接成功应基于实际模型调用结果，不能把进程启动或 HTTP 成功码当成模型可用。错误保留提供方原始原因和可复制详情，凭据不进入普通日志或错误回显。

## 角色选择与局部刷新

角色下拉先形成选择草稿，不写配置、不切换 Core 的正式角色，也不清空角色页。预览不改变 Timeline、语音、记忆和插件的正式绑定。

当前角色外观、语音或角色 Collection 存在未保存修改时，需要先处理再改选；全局设置与全局 Collection 草稿可以保留。暂存另一角色期间暂停当前角色专属编辑，避免把 A 的值提交给 B。

应用时先保存当前角色仍归属的其他配置，再提交角色选择。返回 character_switch 时在当前 Core 内切换会话；visual_rebind 和 character_refresh 只更新受影响部分；只有 core_restart_required 才重建 Core。界面等待快照与目标角色表现一致后再恢复编辑。

工坊保存同一角色后，设置保留相对旧基线实际改过的字段，未修改字段刷新成新的角色内容。打开工坊本身不保存设置，也不改变尚未应用的选择。角色领域的发布与数据规则见[角色与工坊](characters.md)。

## 系统设置与关闭

开机启动由原生平台服务读取操作系统实际状态。用户保存后执行注册或移除并回读；失败保留草稿，不以旧配置值代替系统结果。移动便携版后，用户可关闭再开启以更新启动路径。

桌宠置顶只影响桌宠，不能把设置窗口一并置顶。原生窗口状态与持久化结果不一致时恢复先前有效状态，保留用户草稿与错误。

关闭或退出依据真实未保存内容提供保存、放弃和继续编辑。选择继续编辑保持应用运行；保存失败留在窗口，不进入关闭。退出等待用户决定与保存完成，不用倒计时替用户作出放弃决定。

## 关键业务例子

| 场景 | 预期结果 |
|---|---|
| 改连接地址后点击测试，随后取消设置 | 测试用新地址，持久配置仍为原地址 |
| 修改插件 A，后台刷新插件 B 的资源进度 | A 的文本、焦点和未保存状态保持 |
| 两个插件保存，第二个失败 | 第一个显示真实已保存，第二个保留草稿与错误 |
| 工坊改了角色提示词，设置中另有字体草稿 | 新提示词生效，字体草稿仍待用户保存 |
| Collection 已保存一条便签，随后放弃普通设置 | 便签保留，未提交的普通配置恢复 |
