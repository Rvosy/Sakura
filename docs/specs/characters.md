# 角色、资源与工坊

角色模块管理可分享的人设和资源，以及用户在本机的使用选择。工坊负责编辑与本地保存，表现和语音插件解释自己的资源。角色包是数据，安装的插件提供运行代码。

## 模块职责与联系

| 模块 | 负责 | 上下游 |
|---|---|---|
| 角色配置与目录 | 稳定身份、公共资料、当前选择、包路径 | 向设置、聊天和插件提供当前角色 |
| 角色归档 | `.char`、`.visual`、`.voice` 的导入导出和文件事务 | 接受用户选定文件，保存包内引用与未知数据 |
| 工坊服务 | 工作区、草稿、资源导入、发布与导出 | 前端提出编辑，服务持有草稿和文件，不把路径操作交给 WebView |
| 工坊窗口 | 表单、插件编辑器、预览与未完成操作 | 属于同一 Tauri 应用，使用 Core 工坊接口 |
| 表现宿主 | 资源与提供者绑定、控制目标和资源授权 | 为 Assistant 提供控制说明，为前端提供渲染数据 |
| 表现与语音插件 | 解释各自格式、验证可用资源、提供编辑与运行能力 | 通过公共 SDK 访问角色资源，不接管整个角色清单 |

角色模块不决定模型生成策略，不管理外部语音服务的进程，也不通过包内脚本扩展执行能力。角色工坊的保存是本地操作，不代表在线投稿或发布到市场。

## 数据归属

| 数据 | 所有者与保存位置 |
|---|---|
| 角色 ID、名称、人设、语言、主题 | 角色包公共资料 |
| 表现资源及包默认形态 | 角色包 visuals |
| 模型、参考语音、语气等可分享资源 | 角色包 voice、插件扩展及资源文件 |
| 当前角色、本机形态选择 | 应用配置 config/characters.yaml |
| TTS 启用状态与本机选用引擎 | TTS Hub 私有配置，不随角色分享 |
| 未发布编辑 | data/character_studio/drafts 中的角色草稿 |
| 聊天与长期记忆 | 各数据模块按角色身份保存，不塞进角色包 |

角色逻辑 ID 与磁盘目录名分开。导入、旧数据兼容和 Windows 文件名修复不能把目录路径当作身份，也不能因名称归一化覆盖另一个角色。

公共资料加载不要求某个表现或语音插件可用。资源类型未知、插件停用或资源缺失时保留原数据并报告具体能力状态，仍可查看公共信息和使用文字聊天。

读取旧格式不顺便重写清单。保存只修改当前编辑器拥有的字段，未知顶层字段、嵌套数据、插件扩展及其未识别资源保留。不能因为当前版本不显示某个字段，就把它从分享包或草稿中删除。

## 表现资源与提供者

每份形态有独立资源 ID、可选名称、带版本的类型、资源根和入口。资源根相对角色包，入口相对资源根；资源 ID、格式类型与插件 ID 是不同概念。

包默认值保存在 visuals.default，本机偏好保存在 visual_selections。选择本机形态不改包默认值、人设或语音。清除个人选择后跟随包默认；资源已删除时忽略失效偏好，资源仍存在但插件不可用时保留选择并显示原因。

提供者通过 Manifest 声明支持类型、服务与前端模块。一个类型没有可用实现时报告缺失；多个候选且未明确选择时要求用户选择，不根据排序暗中挑选。包里的插件建议不等于安装授权，停用也不触发替代安装。

表现插件提供控制说明、模型输出 Schema、专属解析、渲染数据和编辑数据。宿主只组织公共资料与绑定，不要求所有形态都是图片，也不规定统一表情标签或动作枚举。

当前内置立绘与可选 Spine 是各自的实现；通用接口存在不代表任意 Live2D、VRM 或其他引擎已经可用。格式和公开接口见[角色资源开发](../development/characters.md)。

## 工坊工作区与草稿

工坊是主应用内的单例窗口。打开已有角色或指定形态时创建或聚焦当前窗口，切换工作区先保存原草稿。打开工坊不保存其他设置，不应用设置窗口里的角色选择，也不切换桌宠。

一个角色复用一个草稿工作区。表单修改保存到草稿，普通自动保存不复制整个角色包、不创建每次编辑的历史副本；导入的大文件单独持有。未发布修改跨关闭和重启保留。

新建角色可以先保存草稿，再添加到角色列表；已有角色可以继续编辑并保存。添加或保存之后不自动切换到该角色。未保存的新角色草稿和已安装角色有不同身份，不能因为草稿存在就让桌宠加载它。

草稿内容是当前编辑的依据。恢复旧版内联立绘草稿时，未发布的封面、表情和图片选择不能被已安装包中的旧副本覆盖；转换为通用资源引用也要保留这些实际编辑。

关闭、切换、导出与放弃都与在途保存协调。保存失败保留窗口和输入；放弃停止后续自动保存，等待正在写入的操作结束后再删除或恢复，旧异步结果不得重新生成已放弃内容。

插件编辑器只持有当前资源数据，使用宿主的资源导入和草稿回调，不另建私有的“保存全部”。切换角色、资源或插件实例后中止旧编辑器，迟到导入、校验和封面结果不能写回新工作区。

## 资源导入

用户选择文件后，宿主把资源复制到当前工作区并返回包内引用，前端不长期保存外部绝对路径。文件夹导入全部成功后一次登记；取消或失败只清理本批新文件，不能删除此前草稿或已存在的同名文件。

表现格式由对应插件解释。插件有能力验证时返回资源名、具体字段和原始错误；未知或停用插件的资源保持原样，不借保存其他字段强迫用户安装插件。

语音资源与本机引擎选择分开。导入独立语音包更新共享资源字段及其同名文件，保留其他资源、未知扩展和 Genie 的显式覆盖；不自动启用 TTS，也不替用户更改引擎。

旧 voice 与当前插件资源扩展在兼容读取处统一。保存共享语音编辑同步必要的兼容字段，不向不拥有这些字段的插件复制模型路径，也不覆盖用户已明确配置的运行选择。

## 保存、应用与局部刷新

1. 工坊收集公共表单及各资源编辑器当前数据，写入草稿。
2. 对可用资源进行插件校验，错误定位到对应形态及字段，其他编辑保留。
3. 比较实际变化，准备本次需要替换的文件和清单；文件事务失败恢复已安装角色。
4. 发布成功后通知角色目录与当前应用，只更新受影响部分。后续界面刷新失败不撤销已经保存的角色。

同角色改名、人设、主题或资源不重启整个 Core。修改表现时更新对应绑定；语音资源更新与相关引擎协调，保留可复用进程。发布未涉及的插件、聊天记录和未知文件不重写。

切换到另一角色先撤销旧会话，停止旧聊天、截图、录音、播放及角色相关后台工作，再建立新角色会话。Core 和可复用的模型、语音、表现引擎保留；在启动时缓存当前角色的相关插件按需要局部重载。

表现切换先准备候选，再替换当前绑定。旧回复绑定旧资源，即使资源 ID 恰好相同，也不能在新绑定上执行。个人选择已保存但绑定应用失败时明确提示可重试，不伪装成旧选择从未改变。

设置窗口在同角色保存后保留用户相对旧基线实际改过的外观或语音字段，其余更新为新资料；另一角色的草稿不能套到当前角色。设置保存与选择过程见[设置规格](settings.md)。

## 分享与归档

| 归档 | 用途与保留范围 |
|---|---|
| 完整 `.char` | 分享角色公共信息及所选资源，保留未知扩展和文件，当前 v2 仍兼容读取 v1 |
| `.visual` | 独立分享一份表现资源，记录类型、入口和兼容插件建议 |
| `.voice` | 独立分享语音模型、参考音频和相关资源配置 |

导出可以把工作区编辑物化到临时包，但不能顺便保存到已安装角色。导入和完整导出检查资源引用留在包内，不能通过链接或相对路径读取包外数据。

插件通过资源声明说明哪些文件属于 TTS。用户选择不含语音导出时，只排除明确属于语音且未被其他资源共享的文件；不能依据目录名猜测并删除未知资源。

组件要求以格式类型和版本表达，插件 ID 仅给出已知兼容实现。导入缺少插件的包仍保留资源，让用户之后安装；卸载插件代码不删除角色包中的数据。

导入重复角色按稳定 ID 处理，不按显示名称判断同一角色。失败或取消不留下半个角色，也不改变原角色。设置中删除角色后，开发种子导入记住用户删除选择，重启不会把它自动装回。

## 失败与关键业务例子

| 场景 | 预期结果 |
|---|---|
| 编辑角色名称，但 Spine 插件未安装 | 保存公共资料，Spine 私有资源完整保留，显示对应能力不可用 |
| 导入参考语音到一半取消 | 保留先前草稿与资源，只清理本批尚未完成的导入 |
| 保存正在使用的角色的人设 | 下次聊天读取新内容，不重启全部引擎 |
| 从形态 A 切到 B，A 的控制解析稍后返回 | 丢弃旧控制，B 不执行 A 的动作 |
| 不含语音导出时某文件同时被表现引用 | 保留共享文件，导出的表现仍完整 |
| 本机已关闭语音，再导入含语音的角色包 | 资源可用，但语音仍保持关闭 |
