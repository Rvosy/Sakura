# 发行、存储与迁移规格

本模块把程序交付到用户设备，并在安装、更新、卸载和旧数据导入时保全用户内容。它同时约束构建工具、桌面更新入口、插件安装和数据导入器；具体构建命令见[发行指南](../development/release.md)。

## 职责与模块联系

| 参与者 | 职责 | 与本模块的联系 |
|---|---|---|
| 发行工具与 CI | 准备运行环境、程序、插件、签名及下载资料 | 产物描述可安装的内容，不能把构建成功当作已发布 |
| 安装器与更新器 | 替换程序文件 | 使用程序域清单，保留用户域 |
| 桌面运行时 | 确定程序根和用户根，启动 Core | 将两根传给后台，见[桌面运行时](desktop-runtime.md) |
| 插件运行时 | 安装和更新插件 | 代码与依赖成对切换，保留私有数据，见[插件规格](plugin-runtime.md) |
| 旧数据导入器 | 检查旧目录、呈现冲突并导入 | 使用独立事务，不借普通启动自动迁移其他目录 |
| 在线服务 | 保存发布草稿与公开更新清单 | CI 导入草稿后由维护者发布，见[在线服务](services.md) |

程序更新不负责清理聊天、记忆、用户插件或角色；插件安装也不能改写整个用户根。角色包的内容与往返规则见[角色规格](characters.md)。

## 程序与数据归属

| 内容 | 归属 | 更新方式 |
|---|---|---|
| `VERSION`、运行环境、Core、内置插件、内置依赖 | 程序域 | 由安装器或更新器替换 |
| `config/`、`data/`、`characters/`、`plugins/user/` | 用户域 | 由用户操作和各自业务模块维护 |
| 默认 `tts/`、自定义 TTS 根、语音缓存 | 用户资源 | 由所属设置和资源操作管理，不随程序替换清空 |

Windows 安装版与 Portable 可以共用一个物理目录，但子目录归属保持分离。macOS 程序位于 `.app/Contents/Resources`，用户数据位于 `~/Library/Application Support/Sakura`；Linux 用户数据位于 `${XDG_DATA_HOME:-$HOME/.local/share}/Sakura`。开发运行可使用独立的 `Sakura Development` 用户目录。

发行 Python 供 Core、SDK 和安装工具使用；插件业务依赖分别属于各插件。用户不能因为某插件缺少依赖而被要求替换主 Runtime 或重装其他插件。

自定义 TTS 根保存在 `config/storage.json` 的 `ttsRoot`。更改位置不自动搬移已有资源；目录失联时保留选择并报告具体原因，不能静默回到默认目录造成数据分叉。卸载不能删除安装目录之外的自定义资源。

## 首次安装

发行包不附带角色或推理模型。没有角色时设置仍可用，桌宠隐藏；导入角色后即可选择。没有模型配置时明确提示聊天待配置，不影响其他设置。

Windows 新安装在欢迎页提供默认勾选的统计选项，用户可取消，首次启动前生效；已有配置和自动更新保留原设置。详情见[隐私政策](../guide/privacy.md)。

首次向导允许用户跳过配置。中途关闭不写完成标记，普通升级保留已完成向导的状态。内置能力可停用，其他能力按需安装，实际分发清单由发行配置维护。

开发用种子角色只用于源码运行。已有同 ID 角色不被覆盖，用户显式删除的种子不随重启自动装回。

## 程序更新

1. 客户端读取公开更新资料，向用户说明可用版本。
2. 用户选择安装后，更新器下载当前平台产物并验证更新签名。
3. 安装器替换程序域，保留配置、角色、聊天、记忆、用户插件和已下载资源。
4. 下次启动先完成必要的插件更新事务恢复，再发现插件和打开业务数据。

Tauri Updater 负责版本比较、选包和验签。项目沿用签名协议，不额外扫描全部文件计算内容摘要。发行清单记录路径、大小和汇总，支持检查交付范围。

Windows 自动更新使用当前程序目录。旧客户端未传入目录时，安装器显示目录选择页，用户需选择原安装目录；程序不自动搬移或合并其他目录中的数据。

每次检查和开始下载读取当时的系统代理及 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY。已开始的传输不切换连接。网络、验签或安装失败保留具体步骤与原始原因，不能影响本地已有版本的普通功能。

Windows 安装版使用当前用户安装和 passive 更新；macOS 更新替换 `.app`，保留外部用户目录；Portable 由用户退出应用后手动更新程序文件。清理退役程序必须明确其归属，不能删除整个安装目录。

## 可选插件

安装包只携带内置插件和对应依赖。可选插件从插件市场或本地安装包安装，通过插件市场更新；主程序升级保留用户已安装的版本、启停选择、配置与私有数据。

插件市场更新使用代码与依赖成对切换的事务，失败恢复旧版本；下次启动先恢复中断的更新，再发现插件。更新完成后的备份清理失败不阻止其他插件运行。

## 导入旧版数据

旧版 0.9.x 目录由用户明确选择，普通启动不扫描其他目录。源目录只读，新旧根不能重叠。

检查先列出可识别的角色、聊天、记忆与资源，再呈现角色关联和内容冲突。目标已有独有内容保持不变；同一身份发生内容冲突时才需要确认。确认覆盖某项内容不表示同意清空该领域所有数据。

来源缺失的配置域保留目标已有值，包括模型连接与选择、系统与屏幕设置、界面、当前角色和插件启停。目标也没有对应配置时才生成默认值；来源中有效的 `.env` 模型配置仍按导入规则处理。

导入优先保全聊天和记忆。无法导入的可选角色或平台不兼容的语音环境分别说明，不能使无关数据消失。已使用新版的用户也可进行增量导入。

写入通过事务进行。失败恢复目标原状态；恢复未完成时保留材料与原因，不让 Core 在混合状态上启动。源数据始终保留，重试不要求用户先清空目标目录。

## 卸载、备份和恢复

程序卸载清理程序域。仅当用户明确选择删除应用数据时，才删除安装目录内归应用管理的用户域；未知文件和外部 TTS 目录保留。更新器内部卸载步骤始终保留用户数据。

普通用户备份应先退出应用，复制完整用户根；运行中的 SQLite 不能只复制主数据库而遗漏 WAL。插件卸载、角色移除和语音缓存清理各有自己的范围，不等同于删除全部应用数据。

## 发行资料与发布结果

版本读取 `VERSION`，当前发布正文读取 `docs/CHANGELOG.md`。下载表只列实际存在的产物；Windows、macOS、Linux 主产物完成后发布，Portable 完成后追加并刷新同一 Release 的资料。Portable 失败不撤回已有安装资产。

国内清单只在控制台确认发布后对用户生效。预发布版不更新稳定入口。镜像复用原产物和签名，只改变下载地址；任何步骤失败都保留已经发布的真实状态，不能宣称其他步骤同时成功。

## 关键业务场景

| 操作或故障 | 应保持的结果 |
|---|---|
| 带已有聊天、角色和插件更新主程序 | 程序更新，已有内容和显式配置保留 |
| 更新一个已安装官方可选插件 | 代码与依赖一致，私有数据和启停选择不变 |
| 没有安装某个可选插件 | 需要时由用户从插件市场安装 |
| 切换安装目录失败或应用被中断 | 下次启动能恢复事务，原因与恢复入口可见 |
| 增量导入旧目录，目标已有新内容 | 只处理本次选中的冲突，目标独有内容保留 |
| 自定义 TTS 盘离线 | 报告该资源不可用，偏好不丢失，文字聊天可继续 |
