# 语音输入、输出与录音留存

语音是文字交互的可选能力。识别结果交还输入草稿；合成和播放失败不撤销已经完成的文字回复。
用户操作见[聊天与语音](../guide/chat.md)，提供方接入形状见[插件能力接入](../development/plugin-recipes.md#语音引擎)。

## 职责与联系

| 模块 | 负责的内容 |
|---|---|
| ASR Hub | 识别提供方目录、选择、任务身份、录音授权与结果回收 |
| ASR 提供方 | 模型和语言配置、资源准备、识别、取消及原始故障 |
| TTS Hub | 按角色选择提供方、路由合成、预热与后台补齐 |
| TTS 提供方 | 引擎配置、角色音色解释、模型加载、合成和引擎生命周期 |
| Core 语音边界 | 将已保存回复的段落交给合成，保存录音并交付播放或导出副本 |
| 桌面宿主 | 本机麦克风采集、音频播放，以及原生资源的结束与释放 |
| 输入栏与回复展示 | 录音交互、草稿插入、字幕与逐段播放时序 |

Hub 不内置具体引擎的模型管理，也不替提供方解释声线参数。
提供方通过公开服务注册，任务绑定取得服务时的插件实例；同名插件重载后不能承接旧任务。
手机等插件取得回复音频时复用宿主语音入口，不另建历史录音库，也不触发桌面自动播放。

## 配置与资源归属

角色资源描述音色，包括模型权重、参考音频、参考文本和语气资源；具体内容由对应提供方解释。
包内资源用相对路径随角色移动，机器上的引擎目录、服务地址、设备和性能档位保存在本机插件配置。
TTS Hub 按角色保存是否启用及所选提供方，不把本机选择写回共享角色包。
ASR Hub 保存识别提供方和麦克风选择；语言及识别模型由提供方保存。
语音缓存目录、容量和空闲补齐是本机偏好，不属于角色可分享资源。
保存某一项只更新提交字段，不能顺便重置其他角色、提供方或设备的设置。

提供方不可用时显示具体状态和恢复入口，不擅自改选另一个引擎。
模型下载由用户发起；设置页读取状态和应用启动不应等同于下载或加载模型。
预热只准备所选引擎和当前角色资源，不合成伪造句子，也不播放音频。

## 语音输入流程

1. 用户开始录音，输入栏记住当前会话、草稿版本及光标位置，进入准备状态。
2. Hub 确认所选提供方的配置版本，准备完成后宿主打开麦克风。
3. 录音期间显示实际音量；再次点击结束采集，随后进行识别。
4. 提供方返回识别文本、语言或明确失败，Hub 交付一次终态。
5. 文本插入当前草稿，用户决定是否发送；识别不会调用聊天发送入口。

草稿未变时，文本插入录音开始时保存的光标位置。
用户在等待期间修改了草稿时，识别文本追加到当前内容末尾，保留用户的新输入。
角色或输入上下文已经改变时，旧结果失效，不能插入新会话。
取消不清空已有文字与附件，也不把取消包装成识别失败。
设置中的录音测试使用独立上下文，只写入测试结果，不修改聊天草稿。

宿主交付单声道、16 kHz、PCM16 WAV，描述包含资源标识、格式、大小、时长和采样信息。
提供方只能读取获授权的录音资源，读取租约结束后释放。
结束或取消撤销新读取权限；已开始的读取退出后再删除文件，避免边读边删。
提供方必须声明在本地还是远程处理，使录音去向对用户可见。
SenseVoice 资源就绪后在本机识别；安装插件依赖和下载模型仍可能需要联网。

## 回复合成与逐段播放

1. 聊天先完成回复与历史写入，保存原始段落顺序及语音禁止标记。
2. Core 按操作和原始段落编号授权合成；界面不能提交任意文本冒充该段回复。
3. 前端依次准备后续段落，TTS Hub 将各次合成交给当前角色选定的提供方。
4. 成功音频先成为有效录音，再交付独立播放资源；生成成功与播放成功分别记录。
5. 每段展示等待音频和可选表现准备，原生播放开始后开启该段字幕与表现。
6. 该段播放结束、停止或失败后推进后续展示，不能把命令受理当作播放完成。

禁止朗读的段落仍可显示文字和表现。关闭语音或某段合成失败时，文字流程继续。
字幕的中文、日文和双语排列只改变显示；缺少译文时显示原文，不为切换语言重新合成或播放。
历史朗读、语音测试和新回复发生播放切换时，旧音频停止，迟到事件不能启动或修改新播放。
开始麦克风采集会停止当前声音并让该回复余下段落保持静音；录音结束不恢复旧声音。
用户停止声音可以保留文字展示；取消整轮或关闭对象则同时结束属于它的合成与播放。

## 引擎生命周期

SakuraTTS 管理自己的整合包和推理进程，可以提前加载当前角色模型，并在空闲后休眠。
未加载或已休眠表示尚未占用推理资源，不等同于插件启动失败。
整合包安装、后端与推理档位、资源切换和更新提醒见[SakuraTTS 规范](sakuratts.md)。

外部服务由用户维护，Sakura 不因连接测试或插件退出停止外部进程。
连接测试不擅自切换外部服务的模型或声线；实际合成按照提供方的明确约定工作。
角色资源更新可由提供方准备和完成原位切换；不能把每次编辑都当作必须重启整个应用。
切换配置、停用插件或取消请求时，提供方结束它拥有的任务；收尾不能依赖界面继续轮询。

## 历史录音与缓存

录音按角色、历史条目和原始段落编号关联，不能用筛选后的界面位置替代原始编号。
历史朗读先读取有效录音；已有录音可在引擎未加载时播放。
缺失或损坏时，以当前角色语音配置生成该段新录音；损坏原因仍进入诊断。
重播不创建新的聊天回复，也不改变历史中的原文。

合成任务文件、历史录音、播放副本和插件导出副本各自释放。
结束播放只能清理播放资源，不能删除用户留存的原录音。
录音与元数据完整提交后才可供查询，未完成文件不能显示为可播放缓存。
每个角色默认保留最近 100 条非收藏录音，同时按缓存容量清理较早的非收藏记录。
收藏录音豁免自动清理；收藏较多时，实际占用可以超过容量设置。
更改缓存目录只改变后续存取位置，不自动搬移或删除旧目录中的文件。
容量不足或留存清理失败应保留具体原因，不能误报为模型合成失败。

## 空闲补齐

空闲补齐默认关闭，开启后只处理当前角色已保存的回复。
仅在没有前台语音任务、设备负载允许且缓存有余量时查找缺失段落。
已有录音、空文本和禁止朗读的段落跳过，不重复合成。
后台补齐只保存录音，不自动播放，也不导出无消费者的音频副本。
前台请求优先；引擎可明确暂缓后台任务，角色切换或功能关闭后旧任务不能继续补写。
缓存已满时不靠不断生成和清理同一批录音维持循环。

## 关键业务场景

| 场景 | 应有结果 |
|---|---|
| 识别等待期间继续输入 | 保留新文字，识别完成后追加，未经确认不发送 |
| 识别时切换角色或取消 | 结束录音和识别，旧文本不回写 |
| 合成失败或播放设备不可用 | 保留文字回复，报告失败步骤和原始原因 |
| 历史第 3 段前有禁止朗读段落 | 仍按原始段落编号命中正确录音 |
| 停用引擎后重播已有录音 | 直接播放有效缓存，不为读取缓存启动引擎 |
| 录音开始时角色正在说话 | 停止声音，保留字幕，不在录音结束后续播旧音频 |
| 插件请求历史音频 | 交付独立副本，回收副本不影响原录音 |
