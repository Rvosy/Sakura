# 模块规格

每份 Spec 是对应模块的业务与协作说明：模块负责什么、输入来自哪里、结果交给谁、保存什么数据，以及失败、取消和对象切换时应保持什么结果。具体方法参数和接入代码放在开发指南，选择模块边界的理由放在 ADR。

先看[架构与模块关系](../development/architecture.md)，再按当前工作涉及的模块阅读。一个模块的内部重构不自动改变其业务规格。

## 按操作阅读

- 一次用户对话：聊天 → 模型 → 历史与 Context → 工具 → 语音与表现。
- 修改配置：设置 → 字段所属模块 → 插件局部应用或后续请求。
- 导入和编辑角色：角色与工坊 → 资源所属插件 → 语音或表现 → 个人选择。
- 安装或升级：发行与存储 → 插件安装与迁移 → 桌面启动；发布资料进入在线服务。
- 定位失败：先看操作所属模块，再用诊断中的身份和阶段关联跨模块结果。

## 与其他文档的关系

[ADR](../adr/README.md)解释当前采用这些边界的原因及代价，不重复方法参数。[SDK](../development/plugin-sdk.md)、[能力接入](../development/plugin-recipes.md)和[角色接口](../development/characters.md)提供可用的接入约定与示例。用户操作从[文档总览](../README.md)进入。

Spec 描述已确认的业务结果和当前有效能力。代码偏差不能直接改写成新规则；确定改变需求时更新对应规格和相关决策，删除作废描述。历史由 Git 保存，不在本目录追加实施过程、阶段状态或验收记录。
