# 聊天受理与 Assistant

Sakura 的所有对话共用 Core 的聊天入口。Core 决定一轮是否受理、属于谁、何时取消以及是否写入历史；Assistant 决定怎样组织上下文、调用模型和工具、生成回复。

桌面输入、手机等插件输入与主动互动保持各自来源，但不能绕过同一聊天受理边界。这样才能让角色切换、取消、历史与语音始终对应同一轮操作。

## 职责与上下游

| 模块 | 职责 |
|---|---|
| 桌面与输入插件 | 提交用户意图，保存尚未发送的草稿，展示实际状态 |
| Core 聊天边界 | 固定会话、角色和操作身份，仲裁繁忙、取消和唯一终态 |
| Assistant 插件 | 历史选择、Context 收集、提示词、模型与工具循环、回复结构 |
| 模型服务 | 保存连接和凭据，执行真实模型请求，交付响应与用量 |
| Timeline | 保存受理后的输入、已提交回复及相关观察事实 |
| 表现与语音 | 消费有效回复段落，负责画面控制、合成与播放 |

Assistant 是普通、可替换的 `sakura.assistant` 服务。Core 不在插件失败时暗中换用另一个 Assistant，也不在宿主中保留第二套对话策略。

## 输入来源

| 来源 | 提交方式与历史含义 |
|---|---|
| 桌面用户输入 | 受理当前文字与附件，作为用户消息保存 |
| 手机等用户输入 | 通过 `sakura.host.conversation` 复用同一受理和历史链路 |
| 主动互动插件 | 通过 `sakura.host.chat` 提交当前会话意图，保留程序或插件来源 |
| 更新通知等事件 | 按明确事件类型保存，不能伪装成用户说过的话 |

主动提交必须指向仍有效且空闲的会话。忙碌或会话已变时拒绝本次意图，不排队等待它在另一个时刻或角色下执行。截图资源的取得与失效见[屏幕感知](screen-awareness.md)。

输入插件只持有自己的任务。取消或释放一个插件的任务，不能结束其他消费者的对话。插件调用者失效后，其迟到输入与结果不能继续交付。

## 一轮聊天的流程

1. Core 检查当前角色、Assistant 会话和忙碌状态，预留本轮操作。
2. 受理时固定角色、session、operation、turn 和附件身份；后续不从界面重新读取这些值。
3. 固定历史快照与当前时间，把用户输入或事件事实写入 Timeline。
4. 将本轮输入、模型引用、角色信息和受控历史读取能力交给已绑定的 Assistant。
5. Assistant 收集上下文，调用模型，并按需要执行工具，直到得到回复、失败或取消。
6. Core 检查原会话与服务实例仍有效，保存可提交的回复，再裁决终态。
7. 已提交段落交给界面、语音和表现；结束通知与临时资源随后按所有权回收。

受理成功不等于回答完成，模型返回不等于历史已保存。输入写入失败时不继续调用模型；有回复但写入失败时不能发布聊天完成。主动观察可以正常结束而没有可展示回复，不为它补造助手记录。

用户输入已经保存后，后续失败或取消可以留下这条输入。不得补一条伪造的助手回复来让历史看起来成对完整。

## 身份与并发

generation 区分 Core 实例，session 区分当前角色会话，operation 区分执行中的请求，turn 关联本轮历史。插件 scope 和服务绑定区分具体提供者实例，插件名称相同不等于身份仍有效。

Core 是唯一受理与终态仲裁者。设置应用、角色切换和回复提交通过同一受理边界协调，不能在检查完成后、实际写入前插入一次失效。

进行中的对话使用开始时的配置和模型绑定。可保存的新配置用于后续请求；需要改变运行态时按[设置](settings.md)等待当前对话结束或执行明确的切换操作。

角色切换先停止旧会话的工作，再建立新会话，保留可复用的引擎。切换成功后旧结果不得写新角色历史、播放语音或覆盖输入草稿，见[角色](characters.md)。

## Assistant 服务契约

| 方法 | 业务含义 |
|---|---|
| `prepare(session)` | 检查本会话是否 ready、degraded、setup_required 或 failed，建立模型绑定 |
| `begin({operationId, input})` | 接受已交付的 JSON Artifact，后台开始本轮 |
| `poll` | 提供进度、序列和运行状态，不能把进度当作最终回复 |
| `result` | 交付完整结果 Artifact 或真实失败 |
| `cancel` | 请求停止本轮模型、工具及相关后台工作 |
| `release(operationId, terminalStatus)` | 接收 Core 裁决并回收任务；尚未退出时如实报告 |

输入携带角色、会话、当前消息、历史快照和来源信息，不携带模型密钥。历史读取授权只供本轮绑定的 Assistant 使用，结果必须从同一实例取得。

回复由有序段落组成，段落可含原文、翻译、语气、表现控制和语音抑制标志。结构格式见[插件能力接入](../development/plugin-recipes.md#实现-assistant)。Core 保留段落索引，使历史、朗读与画面对应同一段。

## 历史与 Context

Timeline 保存实际发生的交互；Context 是本轮模型要看的材料。选择历史、召回记忆或收集插件上下文，不会自动新增历史记录，也不会自动写入长期记忆。

默认 Assistant 按完整轮次由近到远读取历史，并使用固定快照分页。工具调用中新增的本轮消息与历史消息分开处理，不因历史分页把后来提交的聊天混入本轮。

上下文可以包含角色提示、当前时间与状态、近期完整对话、最近两小时内成功分析的屏幕观察和插件贡献。程序提供的观察保留来源，不伪装成用户输入。

Context 提供者声明按 turn 或 step 收集，并声明失败时 skip 或 abort。Assistant 遵守这些声明：可跳过的记忆失败不阻断聊天；必需上下文读取失败则明确结束本轮。

本轮已收集的 turn 内容保持稳定；修改便签、规则或设置影响后续对话。具体数据和来源规则见[Timeline 与记忆](timeline-memory.md)。

## 模型预算与工具循环

默认 Assistant 依据自己的对话预算安排上下文，区分输入额度、输出预留、必需内容和可选历史。未进入本次请求的旧内容仍留在本地数据库。

系统提示、当前输入、图片、本轮工具结果及声明必需的上下文不能为了凑预算被静默删掉。必需内容超出窗口时，返回可定位的预算错误；可选历史与片段按策略取舍，并在 Trace 中说明。

有图片的请求交给适用的模型，不把图片丢弃后继续普通文字请求。模型连接、引用和未知能力的含义见[模型服务](model-services.md)。

Assistant 根据当前工具目录选择工具，实际执行通过宿主注册入口。工具结果回到本轮模型，工具失败保留原因；取消不能被包装成一条普通工具失败后继续生成。

工具循环遵守已配置的步数和调用额度，不能在到达边界后继续执行未获调度的动作。目录失效或提供者被替换时，不把旧调用转交给同名新工具。工具与外部副作用见[工具与 MCP](tools-mcp.md)。

## 提交、取消与终态

每轮只发布一个完成、失败或取消终态。取消请求与回复提交发生竞争时，以 Core 取得的实际裁决为准：取消已经生效时不再写回复，回复已经提交后不把它倒退成未发生。

取消应通知正在工作的 Assistant、模型和可取消任务，并阻止后续步骤。已经完成的工具外部副作用不会因聊天取消自动撤销，结果未知也不能直接重放。

Assistant 返回成功后仍要通过原实例有效性与历史写入检查。面向长期记忆等消费者的完成事实只在助手回复已保存后发布；没有回复记录的正常结束不触发这类通知。

任务结束后释放输入、结果、历史读取授权及临时图片。清理异常保留诊断，不能用清理错误覆盖真正的模型或工具故障。插件失效与资源清理的通用规则见[插件运行](plugin-runtime.md)。

## 展示、语音与恢复

正文提交不等待可选表现解析、语音合成或普通通知成功。语音失败仍可显示文字，表现失败保留可用画面。

桌面逐段播放时，先准备当前段语音和表现，在实际播放开始时同步字幕与画面，该段结束后进入下一段。翻阅气泡历史恢复实际展示过的持续状态，不重放声音或动作；语音所有权见[语音](voice.md)。

Core 意外退出时，界面保留草稿与可展示内容，报告原始原因并提供明确重试入口。恢复连接不自动重发旧输入，也不重复执行结果未知的工具。

进度、模型调用、工具执行、历史写入和终态应通过同一操作身份关联。运行日志说明卡在哪一步，Trace 展示最终模型输入和上下文取舍，隐私与保留规则见[诊断](diagnostics.md)。

## 关键行为

- 桌面与插件同时提交时，由同一入口受理，不产生两套互相覆盖的会话。
- 取消恰好发生在模型返回后，不能出现已取消却新增助手回复的历史。
- 回复保存失败时，界面不会显示完成，记忆插件也不会收到完成事实。
- 角色切换或 Assistant 重载后，旧回复不会进入新会话。
- 必需上下文超预算时明确报错；减少预算不会悄悄删掉当前问题或工具结果。
- 可选记忆、语音或表现失败时，已可用的文字聊天仍能正常完成。
- Core 恢复后仍保留输入草稿，但不会自动重发或重放外部操作。

采用单一受理边界的理由见 [ADR：唯一聊天边界](../adr/single-chat-boundary.md)，失效和重试原则见 [ADR：显式生命周期](../adr/explicit-lifecycle.md)。主要实现入口为 [`real_chat.py`](../../app/core_host/real_chat.py)、[`assistant_adapter.py`](../../app/core_host/assistant_adapter.py) 和[默认 Assistant](../../plugins/builtin/sakura_assistant/)。
