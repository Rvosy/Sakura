# 截图附件与主动屏幕感知

截图让用户把当前画面交给角色，主动屏幕感知则在空闲时结合最近画面发起互动。
两者共用受控截图和聊天能力，图片只服务于所归属的当前会话，不形成长期截图档案。
使用入口见[聊天与语音](../guide/chat.md#截图与主动搭话)，插件接口见[插件能力接入](../development/plugin-recipes.md#主动互动截图和表现)。

## 职责与联系

| 模块 | 负责的内容 |
|---|---|
| 桌面宿主 | 系统截图权限、显示器选择、框选交互、像素采集与临时传输 |
| 截图资源宿主 | 绑定插件实例和聊天会话，交付资源标识，撤销或单次取走图像 |
| 输入栏 | 管理待发送的手动附件、数量、移除与发送状态 |
| 屏幕感知插件 | 开关、采样间隔、搭话间隔、当前批次和空闲策略 |
| 聊天宿主 | 判断能否受理互动，统一产生操作与历史身份 |
| Assistant | 把本轮图像交给视觉模型，生成回复及文字观察 |

主动插件不维护第二套聊天会话，也不自行保存聊天历史。
截图宿主不决定何时主动搭话；调度策略由屏幕感知插件负责。
视觉模型的连接与选择复用模型服务，不由截图功能另存密钥。

## 手动附件流程

1. 用户在输入栏发起截图，宿主打开采集或框选交互。
2. 用户确认后，附件列表显示本次截图及尺寸；取消框选不增加附件。
3. 用户可以继续输入、增加截图或移除单张截图；每条消息最多附加 6 张。
4. 发送时，文字与整组附件交给同一次聊天操作。
5. 发送受理后清除已交付的附件；未被受理的输入保留给用户处理。

附件属于当前输入上下文，不能因另一个窗口的迟到回调覆盖已有附件组。
移除附件要同时释放对应宿主资源，失败时保留现有附件和具体错误。
发送中不允许增删该组附件，避免模型看到的内容与用户提交时不同。
切换角色、后台运行代次失效或输入上下文关闭后撤销旧附件。
截图失败不清空草稿，也不伪造一条没有图片的成功消息。

## 定时采样与主动互动

插件设置包含开关、截图间隔、搭话间隔、批次数量上限和分辨率。
截图间隔用于等待用户活动后的空闲时间；搭话间隔从本批次第一张截图开始计算。
这两个间隔服务于不同目的，不能合并为每次定时器触发都立即聊天。
默认启用，截图间隔 20 分钟、搭话间隔 10 分钟、最多 6 张、原始分辨率。
用户可以在交互设置中关闭功能或调整这些值。

到达采样时机且聊天空闲时，插件请求鼠标所在显示器的画面。
批次满时释放最早的截图，再保留最新画面，不累积没有上限的旧截图。
固定分辨率按画面比例缩小，不拉伸，也不放大小于目标尺寸的屏幕。
可选分辨率为原始、720p、1080p 和 2160p。

本批次已有截图且搭话间隔到达时，插件尝试提交一次主动互动。
受理后沿正常聊天链路生成回复，仍使用当前角色、历史、模型和工具约定。
聊天繁忙、会话变更或互动条件已失效时跳过，不排队等待过时意图重新可用。
系统睡眠恢复后按当前时间作下一次判断，不补跑睡眠期间每个定时刻度。
用户开始新的互动、切换角色或调整设置后重新计时，并撤销不再适用的批次。

## 截图资源与单次消费

截图正文由宿主管理。普通服务调用只传资源标识、尺寸、采集时间和屏幕信息。
资源同时属于后台运行代次、插件实例和聊天会话，其他插件或新会话不能取用。
采集操作与资源各有身份；请求结果尚未返回时，也能通过采集操作取消和清理。

Shell 与 Core 之间可使用运行代次私有目录中的临时 JPEG 传递像素。
Core 消费后删除该传输文件，在内存中持有本轮图像；不能将“内存暂存”理解为完全没有临时文件。
聊天受理时一次取走本批资源，原标识随即失效，不可再次提交给另一轮。
完成、失败、取消、插件退出和会话失效都结束相应资源的使用权。
取消后才返回的截图仍需清理，不能因没有界面等待它而留下资源。

公开截图结果含资源标识、会话、宽高、采集时间和屏幕名称。
主动提交携带目标会话、消息与资源列表；受理结果包含操作身份或拒绝原因。
具体请求字段和调用方式只在[插件接入文档](../development/plugin-recipes.md#主动互动截图和表现)维护。
宿主约束用于确认资源归属和传输有效性，业务调用点不再重复增加同类检查。

## 模型输入与历史

本次采集图像可以作为多模态输入发送给所选模型服务，因此需要支持图片的模型。
图片描述包含采集时刻和屏幕信息，使模型能区分不同画面及其先后顺序。
手动附件和程序定时观察保留各自来源，不能把程序观察写成用户亲口说过的话。
Assistant 可生成文字观察；只有实际成功分析的观察才作为后续上下文依据。

持久历史保留文字观察和必要元数据，不保存截图像素、Base64 或可重新读取的图片路径。
后续轮次从历史读取近期文字观察，不悄悄重新发送已经消费的旧图像。
默认上下文使用最近两小时内成功分析的观察，超出范围的旧记录仍可留在本地历史。
历史描述不能把未分析截图、失败请求或取消操作写成已经观察到的事实。

## 隐私与失败处理

截图可能包含其他应用中的私密信息；发送范围由本次模型请求决定。
关闭主动屏幕感知会停止定时采样和主动互动，不影响用户明确发起的手动附件。
普通日志记录采集步骤、张数、尺寸、会话关联和失败原因，不主动记录图像正文。
运行统计和远程错误报告不上传截图文件；原始异常的诊断范围见[诊断规范](diagnostics.md)。

系统未授予截图权限时，反馈权限步骤与恢复入口，不报告为模型服务故障。
采集失败、模型拒绝图片、聊天繁忙和用户取消分别保留真实状态。
截图能力不可用不阻断纯文字聊天，也不通过反复自动采集掩盖问题。
不凭空引入持久截图恢复队列；后台重启后旧资源作废，用户可以重新截图。
清理失败不覆盖原始采集或分析错误，资源所属对象退出后仍由宿主完成回收。

## 关键业务场景

| 场景 | 应有结果 |
|---|---|
| 用户取消框选 | 草稿和已有附件保留，不新增空附件 |
| 采集期间切换角色 | 迟到图像被释放，不进入新角色聊天 |
| 下一次采样时批次已满 | 丢弃最早画面，保留最近画面 |
| 达到搭话时间但正在聊天 | 跳过本次尝试，不插队或积压主动消息 |
| 提交后模型报错 | 显示真实错误，图像不能被下一轮意外复用 |
| 系统睡眠很久后恢复 | 只处理当前可执行判断，不连续补发多轮互动 |
| 历史上下文引用屏幕观察 | 使用有来源和时间的文字记录，不重新上传旧图片 |

资源归属决策见[媒体资源所有权](../adr/media-resource-ownership.md)，主动互动复用[统一聊天入口](../adr/single-chat-boundary.md)。
