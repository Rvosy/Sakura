# 桌面运行时

桌面运行时把窗口、Core 和插件组织为一个可启动、可取消、可退出的应用。它负责操作的送达和实例生命周期，不决定模型、记忆、语音或表现插件的业务策略。

## 模块职责与联系

| 模块 | 负责 | 与其他模块的联系 |
|---|---|---|
| Tauri Shell | 应用单实例、窗口、系统权限、Core 进程及后代回收 | 为前端提供命令入口，为 Core 提供截图、播放等原生能力 |
| WebView 界面 | 用户输入、编辑草稿、状态展示与当前窗口交互 | 通过 Shell 调用业务，不直接写 Core 数据文件 |
| Shell 生命周期管理 | 启动、停止、重启、状态快照与失败恢复 | 持有当前 Core generation，向所有窗口发布状态 |
| IPC Router | 请求关联、并发传送、响应及事件分发 | 连接 Shell 与 Core，长请求不占用控制操作的执行通道 |
| Python Core | 用户数据、角色会话、聊天受理与资源授权 | 调用插件服务，统一裁决聊天是否完成和是否写入历史 |
| 插件运行时 | 插件发现、独立进程、服务绑定及依赖生命周期 | Core 使用其领域服务；Shell 保留后代进程的最终停止权 |

窗口可以在 Core 尚未就绪或已经失败时继续存在。打开设置、查看故障、处理未保存草稿和退出应用，不以聊天模型可用为前提。

角色切换与设置热应用通常在当前 Core 内完成。只有明确要求重建 Core 的操作才产生新的 generation；不能把整个应用重启当作普通保存或插件错误的处理方式。

## 启动流程

1. Shell 在写入共享用户数据前取得系统单实例锁。已有实例时提示用户，异常退出后的锁由操作系统释放，普通锁文件存在不代表应用仍在运行。
2. 解析程序根与用户根，使用随包 Python 和对应平台资源。正常启动不临时换系统 Python，也不静默联网重建环境。
3. Shell 恢复未完成的旧数据导入事务，再启动 Core。不能在新旧文件混合、回滚尚未完成时继续打开数据库。
4. 建立通信并完成协议握手，随后初始化业务。Core 在发现插件前恢复插件更新事务。初始化可以持续报告进度，设置通道和业务能力按真实状态开放。
5. 发布角色表现、Assistant 与插件的实际状态。已有角色可以先显示；模型未配置、某个语音引擎启动失败，不应把已可用角色一并隐藏。

首次使用由 Shell 主动打开导航窗口，在用户选择普通使用或旧数据导入之前保持业务暂停。没有角色时 Core 与设置仍可用，桌宠隐藏，用户导入后再绑定角色；不能偷偷选择某个默认角色代替用户操作。

程序与用户文件布局、旧数据导入及升级事务见[发行与存储](release-storage.md)。

## 生命周期与就绪状态

进程状态和业务就绪状态分别表达，不用一个“启动成功”混淆二者。

| 状态层 | 当前取值与含义 |
|---|---|
| Shell 进程监管 | stopped、spawning、running、stopping、failed；说明 Core 进程及其回收情况 |
| Core 初始化 | transport_ready、initializing；说明通信已建立或业务仍在准备 |
| Assistant 就绪 | ready、degraded、setup_required、failed；说明聊天可用、可用但有局部限制、需要配置或初始化失败 |
| 插件 | disabled、starting、active、failed；由对应插件的启动和服务发布结果决定 |

Shell 使用当前 Core 返回的快照更新业务状态，通过 generation 隔离不同 Core 实例；快照的 revision 不作为接收状态的条件。角色标识、角色表现与目标角色必须一致后，界面才把它们作为同一份可用状态展示。一个子模块成功不能提前把整个操作标记完成。

初始化等待真实结果、显式取消或实例失效。长时间的依赖准备和模型加载不能仅因统一倒计时结束而被判断为启动故障；传输损坏、进程已退出与明确业务错误仍应立即显示。

## 通信与请求约定

Shell 与 Core 使用长度前缀 UTF-8 JSON 帧。当前协议主版本为 2，事件封套使用 2.2；stdout 专用于协议，诊断通过统一日志入口传递，不能把 print 输出混入协议流。

请求、响应和事件共用 generationId、id、name、payload 等封套字段；响应与事件绑定当前 generation credential。请求优先级区分 control、interactive、background。credential 用于实例认证，不作为界面数据或日志关联字段。

Router 持有通信读写端，调用方只登记等待与发送请求。它负责把响应交给对应请求、把事件交给当前消费者，不负责执行业务，也不以响应到达顺序推断业务先后。

普通请求可以在其他请求等待期间受理。聊天、插件安装、资源导入等长操作不能阻断取消、状态查询和关闭。已经无法接受的请求明确失败，不在未知情况下静默排队、补发或重试。

事件用于通知状态变化；需要完整现状时读取快照。响应和事件可能先后交错，例如聊天终态先于受理响应到达，消费者仍只能完成一次。

协议和 Router 的实现入口是 [core_host_protocol.rs](../../desktop/src-tauri/src/core_host_protocol.rs)、[core_host_router.rs](../../desktop/src-tauri/src/core_host_router.rs)及 [Core Router](../../app/core_host/router.py)。这里的分工不要求业务层再重复校验已解析的内部对象。

## 操作受理与取消

桌面发送、手机等插件提交的用户输入，以及主动插件发起的互动，都由 Core 的 `RealChatBoundary` 统一受理。各入口保留来源语义，不能各自维护一套并行聊天事实。

受理时固定角色、会话和 operation 身份，确认当前能力可以执行。桌面收到受理成功后才清除本次输入；被拒绝或发送失败时保留文本与附件。用户在等待期间输入的新内容，不属于旧操作的清理范围。

一次聊天有唯一终态：completed、failed 或 cancelled。完成与取消在同一业务边界裁决；取消赢得裁决后，迟到的模型结果不能写入助手历史、播放语音或更新表现。已经执行的外部工具副作用不会因为界面取消自动撤销。

取消模型生成和跳过字幕逐字显示是两个操作。前者终止真实请求并使结果失效；后者只加快当前回复展示，不取消已经完成的聊天，也不改变持久化内容。

长任务的受理成功只表示任务已经开始。下载完成不代表安装完成，保存成功不代表运行态已经应用；调用方需要读取对应任务结果或应用结果后再呈现最终状态。

受理与提交规则见[聊天规格](conversation.md)，模型任务见[模型服务](model-services.md)，回复展示见[窗口与表现](window-presentation.md)。公开服务接口见[插件能力接入](../development/plugin-recipes.md)。

## 实例隔离与资源所有权

| 身份 | 隔离范围 | 失效时的处理 |
|---|---|---|
| Core generation | 一次 Core 进程及其通信 | 结束等待，撤销旧快照、事件和临时资源的使用资格 |
| 插件 scope | 一个插件进程实例及其贡献 | 撤销服务、工具、设置、事件订阅与交付资源 |
| 角色 session | 当前角色的一段业务会话 | 取消旧聊天、录音和截图，不能把结果交给新角色 |
| 窗口 generation 与请求身份 | 一次窗口绑定及当前异步操作 | 关闭、重载或切换对象后不再写回旧页面 |

后台任务始终使用开始时取得的绑定。旧插件停用后，即使同 ID 新插件已启动，也不能把旧 jobId 的查询、取消或结果读取转发给新实例。

文件与原生资源由创建它的模块负责生命周期。接收者按交付协议取得使用权，读完释放；插件 scope 或 Core generation 结束时宿主回收剩余资源。文件仍被实际消费者读取时，取消先撤销后续使用，再等待读取结束清理。

## 失败、关闭与恢复

Core 意外退出后，Shell 回收对应进程树，保留窗口、设置草稿及已经完成的回复，展示原始故障与明确的重试入口。不会在后台循环重启 Core，也不会重放结果未知的聊天或工具操作。

插件故障只影响该插件及硬依赖它的消费者。无关设置、聊天文字及其他插件继续工作；用户可以修正配置、重新启用插件或明确重启核心。失败原因通过统一日志保留对象、阶段与原始异常，避免只剩“初始化失败”。

关闭设置、隐藏桌宠和退出应用分别处理。应用退出先解决未保存编辑：取消退出后应用继续正常工作；保存失败保留窗口与输入，不进入后续停止流程。

真正退出时先停止新受理并取消在途操作，再执行业务清理和进程树回收。Windows 使用 Job Object，macOS/Linux 使用受控进程组；只管理当前应用拥有的进程，不按名字终止系统中的其他 Python 或用户外部服务。

若无法确认子进程已经停止，保留具体错误和恢复状态，不宣布关闭完成。非关键的残余文件清理失败不应阻断已经完成的业务或让用户数据被回滚。

## 关键业务例子

| 场景 | 预期结果 |
|---|---|
| 语音模型加载较慢，用户打开设置 | 显示加载状态，设置仍可操作，退出仍能回收任务 |
| 角色 A 的模型回复在切到 B 后到达 | 旧结果被丢弃，不写 B 的历史或播放 |
| 保存模型配置后热应用失败 | 已保存数据保留，显示应用失败及重试入口，不声称全部成功 |
| Core 崩溃，用户尚有设置草稿 | 保留窗口与草稿，用户明确恢复后重新绑定 |
| 用户取消退出确认 | 不关闭窗口，不停止 Core，不丢失待编辑内容 |
