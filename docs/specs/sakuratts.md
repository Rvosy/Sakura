# SakuraTTS 规格

SakuraTTS 是内置的本地 TTS Provider。它管理自己的整合包、推理进程和角色语音合成；默认启用，但是否为当前角色发声仍由本机语音选择决定。整合包和推理模型不随主程序下载或在普通启动时自动安装。

## 模块关系

| 模块 | 交互与归属 |
|---|---|
| TTS Hub | 选择提供方、转交合成任务；公共接口见[语音规格](voice.md) |
| Core 语音边界 | 授权历史段落、接收产物并保存录音；SakuraTTS 不管理聊天历史 |
| 角色资源 | 提供 GPT/SoVITS 权重、参考录音和语气信息，见[角色规格](characters.md) |
| 宿主设置 | 提供配置草稿和安装动作入口，保存、安装与进度由 SakuraTTS 插件负责 |
| 对话入口 | 用户开始对话时通知提前准备；更新提醒走同一受理入口 |
| 引擎整合包 | 执行设备检查、模型加载与合成；其内部缓存兼容性由引擎负责 |
| 宿主日志与统计 | 记录阶段、原始错误和实际结果，见[诊断规格](diagnostics.md) |

插件不能接管桌面音频设备，也不能把模型已加载、资源已安装和插件正在运行合并为一个成功状态。

## 角色与运行配置

角色模型和参考录音沿用角色工坊保存的 GPT-SoVITS 语音扩展。角色显式声明 SakuraTTS 扩展时对应字段优先；读取通过宿主资源接口，不要求角色 ID 等于目录名，也不改写原角色配置。

| 设置 | 业务行为 |
|---|---|
| 运行后端 | 自动、CUDA、CPU、DirectML 或平台支持的后端，按整合包实际能力使用 |
| NVIDIA 推理模式 | FP32、FP16 标准、FP16 低显存、FP16 极低显存；仅手动选 NVIDIA 时生效 |
| 空闲后休眠 | 默认 60 秒；0 表示不自动休眠 |
| 启动时检查更新 | 默认开启，只检查并安排必要提醒，不下载、不安装、不加载模型 |

Windows 自动模式在每次服务启动时执行 CUDA 运行检查：检查明确失败可使用 CPU；检查本身无法执行时报告错误。连续合成复用正在运行的服务，服务停止后再启动重新检查。DirectML 需用户手动选择；macOS 使用 MLX。手动选定后端失败时保留错误，不换成另一设备。

首次 FP16 使用可能需要引擎转换模型，三个 FP16 档共用转换缓存。自动后端不应用隐藏的 NVIDIA 档位；切换设备仍保留用户选择值。

变更实际使用的设备、休眠时间或 NVIDIA 档位时，取消未完成任务并停止旧服务，后续合成应用新配置。关闭自动检查更新或修改当前后端未使用的档位，不中断正在进行的合成。设置保存语义见[设置规格](settings.md)。

对话开始时提前唤醒所选语音引擎；角色缺少语音配置时跳过提前唤醒，实际合成仍提示缺失配置。

## 加载、合成与休眠

1. 语音任务到达时核对当前角色资源和已安装环境。
2. 启动或复用自有引擎，准备所需模型及参考音频。
3. 串行合成段落，把结果交给 TTS Hub 和 Core。
4. 没有工作时按空闲策略释放模型；下一次前台请求按需加载。

应用启动、打开设置、读取状态和 Provider 的普通 warmup 不加载模型，也不延长模型保活时间。用户发起对话时，只有该角色启用了语音且选中 SakuraTTS，才提前准备默认参考资源；预加载不合成并丢弃测试句子。

运行检查、加载和合成等待实际完成或失败，不为本机长步骤设置统一总时限。取消、停用和退出仍能终止自有进程树；等待文件写入停止后才释放产物。

插件状态、引擎状态和安装状态分别显示。已休眠表示释放了推理资源，未加载表示暂未有需要加载的请求，都不表示插件启动失败。

## 历史语音补齐

前台朗读缺失录音可以按需唤醒引擎。后台补齐只在关闭自动休眠、引擎已 ready 且与目标模型一致时执行；不为补齐启动服务或切换角色模型。

不满足条件时返回 `TTS_BACKGROUND_DEFERRED`，由已有语音调度稍后处理。自动休眠模式不受理后台补齐，避免状态查询后又被合成接口意外唤醒。缓存和收藏归属见[语音规格](voice.md)。

## 整合包安装与切换

支持本地 ZIP、7z、tar.gz 导入和 ModelScope 在线安装。当前线上目标为 Windows x64 与 macOS arm64，按平台选择统一包，不按显卡下载不同压缩包。

下载与本地导入使用同一后续流程：准备新版本目录、解压、检查平台与必要入口、执行随包运行检查，再等待当前合成结束，停止自有服务并切换安装指针。只有完整流程成功才报告安装完成，成功后不需要重启应用。

下载期间原安装仍可使用。失败或取消保留原安装；角色权重、转换与参考缓存、运行设置独立于整合包版本目录。成功切换后保留当前与上一版目录，清理更早版本；非关键旧目录清理失败记录警告，不改变安装成功结果。当前没有一键回退操作。

整合包默认存放在用户数据根下的 `tts/sakura/v-*`，引擎缓存和日志存放在 `tts/sakura/runtime-data`。运行检查前去掉压缩包的外层目录。插件启动时，将插件数据目录中旧 `versions` 或 `v-*` 布局的当前整合包和旧 `runtime-data` 分别迁到上述位置，不启动旧引擎、不重新下载，保留角色资源、插件配置和缓存内容。用户指定的外部整合包目录继续沿用。整合包迁移前保存恢复记录；重命名失败时继续使用原目录，移动成功但安装记录更新失败时继续使用新目录，下次启动完成记录更新。缓存直接重命名，下次启动根据源目录是否存在继续处理；目标已有数据时保留两边内容并报告冲突，不覆盖目标。

主程序自身路径较长时，可在“运行环境目录”填写其他短目录，再执行“迁移运行环境”。插件在目标位置创建独立子目录，复制整合包并执行已有运行检查，成功后停止旧服务、切换安装记录。失败或取消继续使用旧位置；原整合包和目标目录内的其他文件保留。后续更新使用新存储位置。外部目录随本机路径记录，移动便携版到另一台电脑时，需要在新电脑重新指定位置并导入或下载安装。

如果旧包已经缺失文件，迁移不会补回文件。可选择短目录后重新导入完整包，或执行“重新下载并安装”；该操作允许安装与当前相同的发布版本，仍保留检查失败时不替换原环境的行为。

7z 优先使用插件携带或本机已有的原生工具，缺少时使用现有 Python 库；解压时不另行下载工具。解压失败保留原始原因，不更换工具重复尝试同一失败操作。

## 下载索引与继续安装

发行索引为固定仓库中的 `latest-preview.json`，插件使用平台条目的 `releaseId/sourceCommit/platform/path/bytes`。下载地址由仓库和发布路径生成；发布端先准备全部目标包，再更新索引。

有发布编号时按编号判断是否与线上相同。旧版或本地导入包没有编号时，只有包内源码提交相同且工作树干净才视为同一发布；编号不同只表示可用版本，不推断自定义本地包的先后。

“下载并安装”连续执行下载和安装。完成下载后保存待安装记录，取消后续安装或重启应用仍可继续；未完成的下载不保留为可安装包，不承诺断点续传。成功安装后清理下载文件。

根据索引检查下载完整性，安装包还需符合索引发布信息。磁盘空间不足等文件操作失败直接说明步骤和原因，不自动重试，不额外添加内容哈希扫描。

## 更新提醒

开启自动检查时，每次插件启动检查一次。已有安装且发现线上包与当前安装不一致后，等待当前角色会话连续空闲 3 秒，通过普通对话入口生成角色口吻提醒；未安装时只提供下载入口。

同一发布编号在同一本地自然日成功提醒后不再重复。只有与本次操作编号对应的完成事件才写入成功记录；其他聊天、取消和失败不能误记为已经提醒。

受理后或受理结果未知时，同一发布在本次插件运行中不应自动重发。因繁忙、会话变化而明确拒绝时，可以重新等待空闲。关闭检查开关停止未发送提醒，不取消已经开始的回复；停用插件回收自己的未完成请求。检查或提醒失败不影响原引擎使用。

## 失败与诊断

日志记录启动、排队、预加载、合成和安装的实际阶段。引擎提供阶段耗时时才展示相应数据；旧包只显示可测得的请求耗时。HTTP 失败保留引擎响应原因，不能只留下通用状态名称。

完整引擎输出默认在用户数据根下的 `tts/sakura/runtime-data/server.log`；缓存迁移失败时仍在原插件数据目录的 `runtime-data/server.log`，安装检查输出在整合包的 `logs/plugin-check.log`。统一日志记录操作结果及诊断入口，不逐条复制普通轮询。

## 关键业务场景

| 场景 | 结果 |
|---|---|
| 只打开设置或启动应用 | 不加载推理模型 |
| 开始一次启用 SakuraTTS 的用户对话 | 可以提前准备，但不生成测试音频 |
| 新整合包检查失败或安装取消 | 原环境和角色资源仍可使用 |
| 下载完成后取消安装并重启 | 可继续安装已下载包 |
| 自动休眠开启时触发后台补齐 | 返回延后，不反复唤醒模型 |
| 更新提醒对应的聊天失败 | 不写成功提醒记录，本次运行不应自动重发同一发布 |
