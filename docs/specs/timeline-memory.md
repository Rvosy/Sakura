# Timeline、上下文与记忆

Timeline 记录已发生的交互事实，Context 组织本轮模型输入，记忆插件维护可长期检索的内容。三者可以相互读取，但不互相替代，也不会因共享一条文字就自动同步增删。

聊天受理与提交时机见[聊天](conversation.md)，用户数据目录、备份与迁移见[发行与存储](release-storage.md)。本页规定数据含义、来源、归属及读取边界。

## 数据职责

| 数据 | 所有者与用途 |
|---|---|
| Timeline | Core 保存用户输入、助手回复、观察和系统事实 |
| 历史界面 | 按角色读取 Timeline 并展示，不决定模型上下文 |
| Context | Assistant 收集本轮需要的状态、记忆和插件材料 |
| Mem0 | 插件维护长期记忆、向量检索及自动整理进度 |
| 便签记忆 | 插件维护用户明确增删改的事实和关键词 |
| Agent Trace | 记录某次模型真正使用的输入与取舍，供排查，不是业务数据库 |

停用某个记忆插件不删除 Timeline，也不阻止其他记忆插件使用自己的数据。更换能力提供者不等于自动迁移私有数据库。

## Timeline 记录

每条记录包含稳定条目 ID、轮次 ID、角色 ID、记录类型、来源、带时区时间和内容。顺序与游标用于增量读取，显示文字不是条目身份。

| 类型 | 记录含义 |
|---|---|
| `human` | 受理后的真实用户输入 |
| `assistant` | 经过 Core 提交的助手回复段落 |
| `observation` | 截图说明、成功分析的屏幕观察或明确来源的插件事件 |
| `system` | 应用提供的系统事实 |

来源保留用户聊天、手动截图、主动事件或宿主等区别。程序观察不能标成用户发言；更新通知也不能伪装成普通对话内容。

图片正文不进入 Timeline。截图记录保存文字说明、时间及必要元数据，成功分析后的观察可以保存语义摘要。临时图片资源由[屏幕感知](screen-awareness.md)按会话回收。

助手记录保留有序段落及必要的语气、翻译、表现与语音信息。历史朗读通过条目 ID 与段落索引定位，不能因界面合并段落改变关联。

系统记录逐条显示时间。插件活动沿用屏幕观察的展开、收起样式：收起时只显示摘要，展开后显示详情和记录入口。入口按来源插件与记录 ID 定位，打开前核对条目所属角色；不把临时端口或回调句柄写进历史。停用插件后仍可看摘要与详情，打开记录需启用对应插件。

插件通过 `sakura.host.chat.record_activity` 写入活动事实，不请求模型、不打断语音，也不等待聊天空闲。棋谱等业务数据由插件保存，宿主只保存摘要、详情与入口。接口见[插件能力接入](../development/plugin-recipes.md)。

## 写入与角色隔离

Core 是聊天事实的写入者。受理后先保存输入，回复通过有效性检查并写入成功后才通知依赖已完成对话的消费者。失败或取消不伪造助手回答。

同一轮的记录必须属于同一角色。单条查询、分页、增量读取和游标都遵守角色边界，不能通过另一角色的条目 ID 或游标读到数据。

聊天取消后已保存的用户输入继续保留。删除角色包不删除其聊天和记忆；重新导入相同逻辑 ID 可继续关联已有数据。删除、迁移和恢复规则不能靠物理目录名称代替角色 ID。

读取或数据库错误必须原样报告并保留原文件，不能为了让启动成功创建一个空数据库覆盖旧数据。明确迁移使用独立入口，普通聊天不会重新导入旧目录。

## 历史读取与快照

历史界面按页向前读取，保留稳定条目身份和原始时间顺序。新消息到达不能让已展开的旧内容重复、跳页或跨角色混入。

Assistant 在聊天开始时取得角色、快照游标和本轮历史授权。`read_turn_page` 按完整轮次提供 conversation、observation 或 proactive 数据流；同一快照的后续页不包含后来发生的对话。

历史授权属于当前 Assistant 实例。任务结束、插件失效或会话撤销后，旧授权不能继续读历史；较大页面通过 Artifact 交付，并随授权回收。

一般插件使用当前角色的只读 Timeline 服务查询条目、最近记录或某游标后的变化。读接口不授予写历史能力，也不允许插件通过回调伪造已完成对话。

游标与数据库和角色关联。替换数据库或跨角色使用游标时需要明确失败，不能把它解释成另一个数据源的合法位置。

## Context 提供者

Context schema 2 描述贡献者身份、收集范围及失败策略。宿主保存注册和真实来源，Assistant 负责何时收集、怎样预算以及最终发送给模型的排列。

| 声明 | 含义 |
|---|---|
| `scope: turn` | 一轮内复用已收集内容，避免工具循环中不断改变同一背景 |
| `scope: step` | 每一步按当前事实重新收集 |
| `failurePolicy: skip` | 可选材料失败时跳过并保留诊断 |
| `failurePolicy: abort` | 材料不可用时结束本轮，不能假装成功收集 |
| `required` | 片段必须完整参与；预算不足时明确报错 |

贡献结果是有来源、身份、正文及优先级等信息的片段。敏感性、时效和预算信息用于组织与诊断，不把第三方返回内容抬高为新的宿主规则。

Context 不自动写历史或记忆。用户在设置中修改对话规则，只影响之后收集的内容；打开设置和读取旧配置不应顺便保存或改变内容。

必需片段不能按可选片段额度静默截断。可选历史与上下文可以按预算取舍，但未被选中不等于从数据库删除。具体预算由[聊天](conversation.md#模型预算与工具循环)负责。

## Mem0：本地检索与自动整理

Mem0 的本地存储、向量模型、手工管理、召回和整理模型分别报告状态。向量模型初始化或下载期间，普通聊天不等待它完成；需要的模型下载由用户明确发起。

未配置整理模型时，已有记忆仍可手工管理和检索。远程 API 不可用影响自动整理，不应把本地数据库和管理界面一起关掉。

未选择角色时，Mem0 可以安装和启用，设置页显示等待选择角色。选择角色后才打开对应记忆库；切换角色先释放原角色的任务与注册项，再绑定新角色。

Core 提交助手回复后发布包含角色、轮次和游标的完成事实。Mem0 根据 Timeline 增量读取并维护自己的处理进度，不从界面气泡或尚未完成的模型响应抓取内容。

自动整理依据插件配置的触发条件和回看范围进行。所选整理模型通过[模型服务](model-services.md)调用，凭据仍属于提供方；失败保留原数据与可定位原因，不假装完成整理。

召回使用本轮问题与必要上下文寻找少量相关记忆，保留条目来源和关联信息。没有命中不代表用户没有相关事实；召回失败按可选能力处理，不阻断普通聊天。

本轮刚生成的记忆不应立即被当成独立证据再次注入同一轮。记忆来源、创建轮次和更新时间用于避免重复强化和区分手工事实与自动提取内容。

整理、模型下载与编辑需遵守同一份数据的写入归属。切换角色、停用或关闭后，旧任务不能写入新角色存储或覆盖新编辑值，后台任务由插件完成收尾。

## 便签记忆

`fact_memory` 保存用户明确维护的内容与可选关键词，使用插件私有 `facts.sqlite3`，按角色隔离。不需要额外模型，也不读取或改写其他记忆插件的数据库。

创建、修改和删除通过 Collection 立即保存；查询与搜索只读。取消普通设置窗口不能撤销已经执行的便签增删，界面应按[设置](settings.md)准确说明动作结果。

有关键词时按关键词匹配，未填关键词时按正文匹配。相关便签通过 turn Context 进入后续聊天，也提供只读搜索工具；聊天不会自动创建或修改便签。

一次召回选择少量相关条目，保留完整事实含义。用户修改便签后，已经开始的回复继续使用本轮采集内容；下一轮使用新内容。

删除便签只删除该插件中的条目。聊天历史、Mem0 或其他数据源可能仍保存同一事实，不能把“删除便签”显示成“已经从所有记忆中遗忘”。

## 数据保留与排查

停用或卸载插件保留其私有数据。恢复和升级保留已有内容及显式配置，不靠清空数据库修复兼容问题。共享数据目录和插件私有目录不能相互替代。

备份需要覆盖完整用户数据目录；运行中的数据库可能仍有未合并写入，先正常退出应用再复制。需要转换格式时由明确迁移入口完成，见[发行与存储](release-storage.md)。

排查“角色为什么知道或不知道某事”时，先看该轮实际使用的历史、Context 提供者和记忆条目。普通日志记录数量、来源、状态和耗时，私密正文只在适当的 Trace 入口查看，见[诊断](diagnostics.md)。

## 关键行为

- A 角色的条目、游标和便签不能被 B 角色查询或编辑。
- 历史翻页时新增一轮对话，不会改变已固定的模型历史快照。
- 模型请求失败后可看到已保存输入，但不会出现伪造的助手回复。
- 整理模型未配置或 API 不可用，手工记忆管理仍正常工作。
- 删除便签后下一轮不再由该插件召回，历史中的同一事实仍如实保留。
- Context 必需内容读取失败会明确报错，可选召回失败不阻断聊天。
- 重载记忆插件或切换角色后，旧整理结果不能写入新的对象。

保留数据的原则见 [ADR：保留数据的更新](../adr/data-preserving-updates.md)，事实提交的边界见 [ADR：唯一聊天边界](../adr/single-chat-boundary.md)。实现入口为 [`timeline.py`](../../app/storage/timeline.py)、[宿主只读服务](../../app/core_host/plugin_host_services.py)、[Mem0](../../plugins/optional/sakura_mem0/) 和[便签记忆](../../plugins/optional/fact_memory/)。
