# 模型服务与选择

模型服务插件负责连接提供方并执行请求；使用模型的功能只持有模型引用。连接、凭据、用途选择和生成策略分别归属实际使用者，避免多个页面或插件维护同一份密钥与配置。

本模块向上服务 Assistant、记忆整理等消费者，向下连接远程 API 或兼容的本地服务。用户配置入口见[模型指南](../guide/models.md)，开发接口见[插件能力接入](../development/plugin-recipes.md#使用模型)。

模型客户端收到响应时，宿主保存提供方返回的用量，供[使用统计](settings.md#使用统计)查询；保存失败记入运行日志，不中断模型回复。

## 配置归属

“OpenAI 兼容模型”（`sakura.model.openai_compatible`）是模型服务的基础插件，提供统一的服务工作台和 API 连接能力。OpenAI Official 等模型服务扩展依赖它，在同一工作台增加登录入口和账号面板；工作台由基础插件提供，宿主负责挂载和汇总设置贡献。

模型服务扩展在 Manifest 的 `requires` 中声明这项硬依赖。基础插件停用或不可用时，扩展也不可用，由插件运行时处理依赖失效；已保存的凭据、模型目录和用途引用继续保留，重新启用基础插件和扩展后可继续使用。

| 内容 | 所有者 |
|---|---|
| Base URL、凭据、连接超时、连接内模型列表 | 模型服务插件 |
| 对话与视觉对话的模型引用 | Core |
| 记忆整理等插件用途的引用 | 注册该选择槽的插件 |
| 温度、Top P、最大输出及对话预算 | 默认 Assistant |
| 某次请求、取消状态、响应与临时资源 | 发起请求的消费者与对应服务实例 |

“模型服务”编辑连接，“模型”选择用途。界面位置不改变配置所有者；宿主不读取密钥后替各插件执行请求，消费者也不复制一套连接编辑器。

## 提供方、连接与模型身份

一个提供方可以登记多套连接，每套连接有稳定 `profileId`。模型名称只在相应连接中解释；不同提供方使用相同模型名称，不代表同一个选择。

每次选择“添加模型服务”中的预设都创建新连接。API 连接与 OpenAI Official 连接按创建时间混合排列，新连接追加在列表末尾，保存和重新打开后保留顺序。每条 OpenAI Official 连接分别管理名称、账号、模型目录和登录任务；修改、退出或删除一条连接不影响其他连接。

消费者保存 `{serviceKey, profileId, modelId}`。三个字段同时为空表示未指定，同时存在表示明确选择。显示名称变化不会改变引用，不能靠列表下标或模型标题寻找原选择。

提供方通过 `sakura.host.model_slots.v2` 登记目录。目录只包含本地已保存的连接和模型描述，不含密钥；打开设置或读取目录不会自动请求远端模型列表。

内置 API 服务允许手工输入模型 ID，也可获取远端列表后选择需要的模型。OpenAI Official 在登录后自动获取并保存全部可用模型，不提供手工增删或勾选。目录同步不改变已有用途选择。列表接口成功只说明能够列出模型，不保证其中每个模型都能生成、处理图片或使用工具。

## 连接与凭据

内置服务支持 OpenAI 兼容接口，连接需要有效 Base URL；仅在服务要求认证时填写 API Key。无需认证的局域网或本地服务可以使用空密钥。

订阅服务可由插件完成账号授权和续期。[OpenAI Official 插件](../../plugins/optional/sakura_codex/README.md)启用后，在“添加模型服务”中提供入口，选择后在同一工作台右侧管理登录。插件保存自己的凭据，通过 Responses 协议调用订阅模型。凭据不进入宿主模型目录；未完成的登录被取消时保留原账号，退出登录保留模型目录和用途。模型同步失败保留已完成的登录，允许重试。普通网络故障不触发重发，明确的 401 认证拒绝允许续期后重试一次。

API Key 编辑使用三个明确动作：

| 动作 | 保存与测试含义 |
|---|---|
| `keep` | 使用当前已保存的凭据，不把空输入解释为清除 |
| `replace` | 使用并保存用户提交的新凭据 |
| `clear` | 明确移除已有凭据 |

普通读取不把完整密钥回显到前端。请求和错误诊断使用本次配置的凭据进行脱敏，不能因连接后来更改而漏掉旧请求中的密钥。

保存一套连接不得覆盖其他连接。删除连接或模型不会替消费者偷偷选择一个替代项；仍指向该对象的引用保留并显示不可用。

## 草稿测试

获取模型列表和测试连接读取当前编辑草稿，包括尚未保存的地址、模型与凭据动作。它们不能顺便保存连接，也不能改变正在运行的聊天配置。

内置连接测试使用该连接列表中的第一个模型。测试成功只说明这一配置组合的请求通过，不推广为全部模型、全部输入类型或之后请求均可用。

测试任务固定提交时的草稿。用户切换连接、修改字段、关闭页面或重新发起测试后，旧任务结果不能覆盖当前对象；取消应结束对应真实请求。

测试错误保留服务状态、原始原因和可复制详情。用户可以取消或修改后再试，不需要先保存一份无效配置才能诊断。

## 选择槽

Core 提供对话与视觉对话槽。插件可以登记自己的用途，声明稳定槽 ID、显示名称、是否必需，以及读写本插件引用的回调。

槽位身份包含所有者和槽 ID。两个插件都声明“整理模型”时仍是两个独立选择，不能互相覆盖。插件停用后隐藏其运行贡献，私有引用继续保留。

可选槽未指定模型时继承当前对话模型，解析时跟随对话选择变化，不把当时的模型复制成永久独立选择。需要固定模型时保存完整引用。

服务停用、连接删除或模型暂不可用时，已保存引用保留并显示原因。用户仍能看到原选择、原样保存其他设置，或明确改成另一个模型。

模型服务页在目录变化后立即提示受影响的用途和模型，并提供前往模型选择的入口。新选择失效时，保存会定位到对应用途，说明需要恢复的连接或模型；这类选择问题按表单提示处理。

保存多个槽时，各所有者负责自己的数据。部分保存失败必须指出已保存和失败的用途，不能将部分结果包装成全部成功，也不能回滚无关插件的数据。

## 模型能力与预算

提供方通过 `describe` 返回上下文窗口及来源、输入类型和工具调用能力。未知图片或工具能力保留为未知，不根据模型名称推断成确定支持或不支持。

窗口使用用户声明或明确标记的默认估计；估计不等于服务商承诺。默认 Assistant 的对话预算由 Assistant 自己管理，提供方元数据不能变成另一份暗中覆盖的聊天设置。

图片请求要保留真实图片并选择适用模型。服务拒绝图片时报告原因，不能删掉附件后假装完成原请求。工具和响应格式的兼容同样基于服务真实响应处理。

请求预算由消费者承担：Assistant 决定历史和 Context 的取舍，记忆整理决定自身输入。模型服务不擅自删改用户消息、工具结果或必需上下文，见[聊天](conversation.md)。

## 请求与响应契约

| 环节 | 约定 |
|---|---|
| 请求 | `messages`，可带 `tools`、`toolChoice`、`responseFormat`、`parameters`、`stream` |
| 开始 | `begin` 接受操作 ID、连接与模型，以及内联请求或请求 Artifact |
| 进度 | `poll` 返回状态、序列和增量进度；丢失部分进度不等于丢失最终结果 |
| 结果 | `message`、`usage`、`finishReason`，可附诊断或结果 Artifact |
| 工具调用 | 保留调用 ID、名称和 JSON 字符串参数，与工具响应逐一关联 |
| 失败 | 保留 `code`、`message` 和诊断，不用一个空成功响应代替错误 |

提供方附带的 `providerData` 作为不透明数据保留，消费者不随意重写。服务商实际 Token 用量与本地估计分开记录，不能拿估计冒充计费事实。

公共 `ModelClient` 负责绑定提供方、传输大请求、轮询、取消和回收。插件优先复用该客户端，不各自维护一套模型 RPC 或 Artifact 流程。

提供方通过公共 `ModelProvider` 复用任务生命周期，协议适配仍在插件进程执行。Responses 消息与结果转换由公共 SDK 维护，账号插件只处理认证和供应商差异。

聊天和记忆整理用 Pydantic 定义结果字段、生成 JSON Schema 并校验返回值。请求优先使用 `json_schema`；兼容服务明确拒绝该能力时，才退到 `json_object` 或提示词约束。带工具的请求跳过 JSON mode，避免部分服务把工具调用写进正文。Schema 本身错误、认证失败或网络错误不触发格式降级。

JSON 的代码块、引号等语法问题交给 `json-repair` 处理，修复后仍须通过业务校验。消费者先检查结束原因；长度截断、内容拦截和拒绝保留原原因，不把补齐的 JSON 当成完整结果。公共辅助入口是 [`sakura_structured_output.py`](../../app/plugin_sdk/sakura_structured_output.py)，依赖由使用它的插件声明。

## 在途任务与配置应用

一次请求在开始时固定连接、凭据、模型和参数。保存连接不会改变已开始的请求；新配置应用后用于后续工作。

任务归属调用者插件 ID 与 scope。Assistant、记忆整理及其他消费者之间的操作互不可读、不可取消。服务重载后旧绑定失效，不能把未结束请求转交给同 ID 新进程。

用户可先保存配置，再按运行状态完成应用。应用需要等待聊天结束时明确反馈；失败保留已保存配置和原始原因，不能把“已保存”显示成“已生效”。

## 失败、取消与恢复

取消通知真实 HTTP 请求或提供方任务，并阻止迟到响应被交付。释放时工作尚未退出，应继续由任务所有者完成收尾，不能要求页面持续轮询才能清理。

HTTP 成功但响应体包含服务错误，仍按失败处理。只有提供方明确拒绝某个可选请求参数时，才能进行对应兼容处理；认证、网络和未知故障不触发盲目重发。

请求超时或连接断开不能证明服务端未执行。恢复入口应让用户看到实际错误并决定重试，不自动重复可能计费或产生外部效果的工作。

缺少模型配置影响需要该模型的能力。记忆整理模型缺失不阻断手工记忆管理，语音不可用也不改变文字模型选择。各模块就绪状态见[插件运行](plugin-runtime.md)。

## 关键行为

- 用新地址和新密钥测试成功后取消编辑，原连接保持原值。
- 删除当前模型后，原用途显示不可用，不悄悄切换到列表第一项。
- 修改对话模型时，继承槽跟随变化，显式选择的整理模型保持不变。
- 一个消费者取消自己的请求，另一消费者的请求继续运行。
- 模型服务重载后，旧响应不能进入新聊天或新记忆任务。
- 未声明图片能力的模型不被凭名称猜测；实际图片请求失败时仍保留原错误。
- 多槽保存部分失败时，界面能分辨哪些用途已经保存。

配置分工的理由见 [ADR：设置归属](../adr/settings-ownership.md)，请求恢复原则见 [ADR：显式生命周期](../adr/explicit-lifecycle.md)。主要实现入口为 [`provider_settings.py`](../../app/core_host/provider_settings.py)、[内置模型服务](../../plugins/builtin/sakura_model_openai_compatible/) 和 [`sakura_model_client.py`](../../app/plugin_sdk/sakura_model_client.py)。

配置迁移与存储位置见[发行与存储](release-storage.md)。
