# 开放插件生态改造计划

目标是让主程序保持简单：宿主负责运行、连接、身份、生命周期和公共资源，插件拥有业务、数据与策略。
当前只改造已有能力，复用现有插件和隔离测试验证。复杂插件优先使用现有插件设置容器；Agent、模式选择器和新业务插件不在当前范围内。

## 现在支持什么

| 范围 | 当前行为 |
|---|---|
| 插件运行 | API v4、独立进程与依赖、具名 Service、配置、资源和清理；`context.bind()` 固定提供者实例 |
| Context | Host 传递有界原始贡献，不判断规则/资料分类；默认对话决定组合与模型预算 |
| 记忆 | Mem0 和可选便签记忆各自拥有存储、检索、Context、工具与设置 |
| TTS / ASR | 现有 Hub/Provider 经公共服务连接，旧任务与迟到结果不能误用重载后的进程 |
| 表现 | 资源、renderer、editor 与控制描述归插件，宿主负责加载和派发 |
| 插件设置 | 结构化字段、Action、资源状态与 Collection；无需为复杂功能默认另开入口 |
| 正常对话 | 现有 Assistant、模型和 ChatPipeline；默认模型与对话策略尚未迁入插件 |

上述能力不等于整个默认对话已经可替换。当前真实调用者仍依赖默认模型客户端与管线，这部分是后续迁移的主要工作。

## 本次收尾

整合分支 `refactor/open-plugin-ecosystem` 从 main `cb804c58` 建立，旧分支
`codex/open-plugin-ecosystem` 的 `e15aba4d` 保留为成果来源。服务绑定、Context、Collection 和可选插件分别核对最终有效改动，
不重放试验与撤回的中间提交。main 的角色会话和设置投影是整合基线。

本次适配保留逐片段 `budgetHint`，不恢复旧 Provider 共享额度；同 Core 角色切换保留引擎，
ASR 在整个切换作用域拒绝新录音，原任务取消后不能因切回同一角色重新交付。Session 完成插件绑定后才发布 ready。
并发停用与 Core 关闭共同等待已开始的插件清理；一项清理失败后仍停止其余插件，最后报告原始错误。

无正常入口的执行器实验已从生产启动和聊天链路删除，包括 Catalog、适配器、备用 Session 字段、进度分支和专注样例。
原实验中持续读取超时、取消后无期限等待，以及坏的可选表现控制导致停止整插件的问题，随该未使用路径一并移除。
正常对话继续沿现有管线处理取消、历史、表现和 TTS；通用进程绑定与回收机制保留。

Collection 的真实修改与数据归属分别处理：

- 打开已有记录或空白新建编辑器不算修改；字段变化才成为草稿，改回原值后解除阻断。
- `scope=character` 的修改阻止角色切换，实际换角色时清理其页面状态；`scope=global` 的草稿跨角色保留。
- 所有集合在角色切换、同角色局部刷新和 Core 重启期间暂停旧请求，重绑定后隔离旧回调与结果，不重放写入；
  即使 Snapshot 内容完全相同，也重新建立请求状态。异步删除确认仍复核编辑对象。
- 旧 Collection-v0 未声明 scope 时保留 character 行为，避免已安装角色记忆插件丢失原有保护；新贡献应明确声明归属。
  scope 不从页面位置或插件名称推断。Mem0 与便签记忆显式声明 character。

公共契约见 [Runtime Spec](../../specs/runtime-v2/sakura-plugin-runtime-v4.md)和 [SDK](../../devdocs/SAKURA_PLUGIN_SDK.md)；
本次取舍见 [ADR-0054](../../adr/0054-retire-executor-experiment-and-scope-collections.md)。main 的 ADR-0049–0051 保留原编号，
旧生态分支的两份早期方案改为 ADR-0052/0053 并归档，当前实现不以其中已替代条款为准。
日常检查使用[已有数据验收入口](../../devdocs/PLUGIN_ECOSYSTEM_ACCEPTANCE.md)，保留原角色、配置及存储。

## 下一项：迁移已有模型调用边界

下一阶段先追踪正常聊天、模型列表、连接测试与 Mem0 辅助模型的实际调用，收口当前直接构造 HTTP 客户端的位置。
以现有模型能力为消费者，逐步形成提供者可替换的调用边界：

1. 保持现有 API 地址、Key、模型选择与继承行为，由默认适配器解释旧配置，用户无需重填。
2. 模型引用和调用不强制还原为 HTTP URL；旧 `model_slots.resolve()` 保留其 HTTP 合同，对无法表达的实现明确报不兼容。
3. 正常聊天与一个已有辅助消费者走同一公开边界，用隔离夹具验证不同协议，不新增业务插件。
4. 沿用现有 Trace 存储和脱敏规则，实际模型调用各记录一次；取消、实例失效和迟到结果沿用现有保护。

迁移必须替换真实调用链并清理失效直连；只增加包装类或同时保留两套常驻调用路径不算完成。
先完成这些调用的兼容与验证，再考虑将默认实现迁入插件目录。

## 后续方向

默认对话的 Agent 循环、提示词、上下文选择与预算、模型解析和工具策略最终由默认对话插件拥有。
它和第三方使用相同公开入口，复用 Host 的 Timeline、资源和进程机制，不导入私有宿主类。
迁移时验证正常工具/MCP、取消、唯一结果提交、历史、TTS 和 Trace；不提前搭建任务恢复或通用授权平台。

插件界面继续按现有消费者暴露的缺口改造。当前字段、Action 和 Collection 不够用时，先评估同一设置容器内的呈现扩展。
自定义 HTML、WebView、独立窗口和插件命令入口都未实现，也不是当前改造的前置条件。

未来 Agent 的规划、命令、工具选择与业务权限由具体插件及实际能力入口负责。Python 插件目前继承用户系统权限，
进程隔离不构成 OS 沙箱，安装或启用插件也不自动扩大默认 Assistant 的工具集合。

## 保留的维护原则

- 沿用现有 API v4、安装器、ServiceProxy、依赖与资源机制，不重新建设插件内核。
- 生命周期保护用于真实消费者，不为未来假设长期维护备用运行路径。
- 不把所有模块拆成独立服务或进程，也不为每个业务建立宿主枚举或 Hook。
- 插件私有数据格式各自拥有；替换实现不自动转换数据库，旧配置能直接忽略的字段不做迁移。
- 相关改动以聚焦回归交付；原生窗口和设备体验与自动验证分别报告。

具体提交和旧版计划可通过 Git 查看，历史通过记录不替代当前验收。
