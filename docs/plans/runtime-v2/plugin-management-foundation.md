# 插件管理页与通用设置页方向

插件页需要容纳逐步增加的功能扩展、能力提供方和基础组件。本次先用独立前端原型验证布局，并记录后续接入产品的方向。
当前交付是演示页面；正式插件页、Manifest、SDK 和 Plugin Runtime 均未改变。

[打开原型入口](../../../desktop/frontend/prototypes/plugins/index.html) ·
[原型启动与操作说明](../../../desktop/frontend/prototypes/plugins/README.md)

## 页面组织

插件使用两个独立的展示维度：角色决定列表分组，领域作为标签和筛选条件。安装来源由安装记录决定，与作者名称分开呈现。

| 维度 | 展示选项 | 用途 |
|---|---|---|
| 角色 | 功能扩展、能力提供方、系统组件 | 分组和快速切换 |
| 领域 | 模型、语音、记忆、工具、连接、其他 | 标签和组合筛选 |
| 来源 | 内置、用户安装 | 说明安装来源，不表示运行权限差异 |
| 状态 | 有问题、已禁用 | 查找故障或停用的插件 |

保留“插件列表＋详情”的结构。列表展示名称、简介、领域、来源和运行状态，启用开关集中在详情中。
系统组件默认收起，入口固定在列表底部并显示数量、异常数；搜索或筛选命中时展开。详情中的依赖项可以跳转到对应插件，
跳转时清除阻挡目标的筛选条件。筛选结果为空时，详情同步清空。

详情以插件身份和概览为中心。正常运行状态放在名称下方，用轻量标记表示；错误或待处理原因显示在介绍之后。
启用状态另有明确文字和开关。配置保存成功不等于插件运行正常，开关也不承担模型加载、下载或故障状态的表达。

## 通用插件设置页

任何插件都可以声明自己的设置页，适用于功能扩展、能力提供方和系统组件。设置页的内容由插件声明，不能由宿主根据
模型、语音、记忆等领域或插件 ID 选择一份专用表单。未声明设置页的插件不显示设置入口。

用户从详情点击“插件设置”，在同一个设置窗口容器中编辑该插件的设置。窗口保留插件名称，支持分组、折叠高级选项和
必要的条件字段；长内容在窗口内部滚动，保存与取消始终可达。关闭窗口后保留背后的选中插件、筛选和列表位置。
取消、关闭及 Esc 丢弃本次编辑；保存后再次打开可以查看已保存的值，各插件的设置互不覆盖。

原型通过每条插件数据中的 `settingsPage` 演示这项声明：

```javascript
settingsPage: {
  title: "插件设置",
  description: "调整这个插件的记录方式。",
  sections: [{
    title: "记录",
    fields: [{
      key: "notebook",
      label: "笔记本名称",
      type: "text",
      value: "Sakura 随记"
    }]
  }]
}
```

当前表单原型覆盖文本、多行文本、密码、数字、下拉选项、滑块、复选框，以及条件显示和高级折叠区。
Mobile、Playwright、Mem0、Genie、GPT-SoVITS 和模型插件示例使用同一渲染路径；模拟安装的 Notebook Companion
也仅靠声明显示自己的设置页。

以上字段名和控件集合用于体验验证，尚未成为正式 Manifest 或 SDK 契约。后续应先复用现有 Settings Contribution 的
字段、读取、保存和动作能力，再决定正式的设置页描述接口。也未在本轮引入插件提供任意 HTML、脚本或独立原生窗口的能力。

领域页仍可提供跨插件的能力选择与编排，例如当前聊天模型、当前语音引擎或记忆内容管理；插件自己的设置项目则可以放入
通用设置窗口。领域页面不是插件获得设置入口的前提。

## 基础设施边界

后续正式展示元数据沿用 `presentation.kind` 和 `presentation.category` 的方向。它们只影响展示，不参与启动顺序、
依赖解析、服务选择、权限或领域业务判断。已有插件缺少展示元数据时仍应可见、可管理，不因新增分类而失去加载资格。

系统组件是可替换的实现，不因分类而成为永远不能关闭的特殊插件。依赖关系来自已有的能力声明与实际可用性，停用前应说明
受影响的已启用插件；执行后区分它们保留的启用意图与依赖不可用状态。不要把展示分类反推为运行依赖，也不要从 ID 前缀猜分类。

TTS Hub 可以作为语音系统组件呈现。模型运行时、Local LLM、Remote API 在本原型中是明确标注的规划示例。
Model Runtime Contract 属于契约文档，只有实现该契约的组件才作为插件条目展示。

不增加插件市场、评分、推荐、依赖图可视化或新的后台恢复机制。
[Plugin Runtime v4](../../specs/runtime-v2/sakura-plugin-runtime-v4.md) 的逐插件进程与可替换能力边界继续有效。

## 实施与验证

当前阶段已提供 5、9、30 个插件的场景、组合筛选、折叠分组、状态展示、依赖跳转、停用影响提示和通用设置窗口。
全部使用演示数据，设置只保存在页面内存中；安装、卸载、启停和保存均不调用真实后端，不读取用户数据。

浏览器中已检查以下交互：

- 正常状态位于插件名称附近；启用状态与启动失败独立展示。
- 组合筛选和空结果同步更新详情；异常系统组件可通过筛选定位。
- 设置按插件分别保存，取消保留上次保存值；错误的端口值阻止保存并聚焦字段。
- Genie 自定义服务字段按声明显示；隐藏且停用的输入不会阻挡保存。
- 未声明设置页的组件不显示按钮；新安装的样例通过声明显示多行文本等自己的字段。
- 弹窗关闭后返回原入口；当前浏览器窗口内表单及保存、取消按钮可见。

这些检查只证明原型交互。原型列表曾在 900、1200、1600px 的浏览器视口检查；通用设置窗口随后在实际预览视口检查。
后续接入正式页面仍需验证目标 WebView、窗口尺寸、真实状态刷新和配置提交失败，不能用演示结果替代产品验收。

后续工作分为两个独立切片：先把展示元数据与分组、状态、依赖说明接到现有插件清单，再把通用设置窗口接到现有设置贡献和
保存链路。正式接入时同步更新相关 Spec 与必要的行为测试，并检查旧插件兼容、插件停用时设置可用性、保存失败和旧结果失效。

原型保留在独立目录，不加载于正式设置窗口。正式接入前可单独移除该目录；后续产品改造应与原型提交分开，以便独立回退。
