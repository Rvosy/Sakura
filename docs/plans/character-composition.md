# 角色能力插件化：完整立绘链路与插件自定义控制

## 实施结果

六个实现步骤已接通：立绘由可替换的 `sakura.portrait` 插件提供，公共角色、回复、渲染宿主和工坊使用通用资源
及私有控制数据。旧包和旧历史保留兼容入口，无图片数值插件已通过真实工坊至浏览器播放的链路。
首次交付遗漏了正式设置的“显示方式”入口，工坊外观也未落实已确认的 Demo。此次补齐个人显示方式的持久化、
应用与放弃，以及工坊的形态卡片、名称、添加弹窗和立绘编辑控件。实现与浏览器验证完成，原生体验尚未全部验收。
当前合同见[表现插件 Spec](../specs/runtime-v2/visual-plugin-boundary.md)，架构依据见
[ADR-0046](../adr/0046-composable-character-resources-and-renderer-host.md)。本文件记录实施，不另设审批或文件白名单。

## 审查与修复

按用户要求，每大步只进行一次子代理只读审查，主代理决定并实施修复，不重复审查。
前四步已经审查，修复了在途绑定撤销、同 ID 安装选择、旧路径兼容、控制累计超预算、独立显示绑定、首次 lifecycle
误清理，以及取消和缩放不同步。第五步没有 P0；两处 P1 草稿串写和三处 P2 均已修复：表单未填完时自动保存、
添加资源的过期回包、插件 scope 失效后的编辑器授权、缺失入口不能编辑修复、API 不兼容阻止公共资料保存。
第六步审查没有发现 P0/P1，三处 P2 均已修复：非图片表现没有应用个人缩放、局部切图失败覆盖当前画面、
合法资产 key 被 Snapshot 敏感字段过滤误拒。六步各进行一次审查，没有复审或委派实施。

设置和工坊补齐各做一次只读审查。设置修复应用后控件未解锁的 P1，以及插件状态和同角色保存后未刷新的 P2。
工坊没有发现 P0；两个 P1（自动保存后再次改名无效、空白或重复标签丢图片行）和一个 P2（旧缩略图覆盖新选择）
均已修复并补回归，没有再次审查。

随后用户反馈点击保存后出现 `ROUTER_QUEUE_FULL` 和立绘撑破布局。此前浏览器验证没有施加桌面 CSP，
同步测试桥也掩盖了真实路由的并发限制。此次改为可在桌面 CSP 下使用的构造样式表，将预览请求串行化并取消
过期排队请求；保存后等待 Core 重启完成再重建编辑器。发布成功后列表读取失败仍更新已保存文档和基线。
按用户最新要求，本阶段已停止子代理审查，继续实施和验证。

设置仍出现过载后，进一步确认共享 Router 在等待队列有空位时就拒绝了第五个并发请求。现由四个 worker
限制执行、八项队列吸收短时请求，排队超时和关闭时的未执行请求会被放弃；设置同时合并同角色的在途读取。
旧兼容立绘缺省名称统一为“立绘1”，已有自定义名称保留。本地验收角色另加“立绘2”，保留部分图片作切换对照。

## 范围与保留项

宿主保留人格、语言/TTS tone、公共回复、历史、播放、窗口与文件事务；同一个表现插件负责资源、编辑、控制说明、
解析与渲染。公共层没有固定图片标签或隐藏选图回退。历史浏览不执行控制，插件失败不丢有效文本。
资源 ID、格式和插件 ID 分开；一名角色可持有多个资源，同时只选择一个。组件导入生成新 ID，修改目标草稿，
不覆盖其人格、语音或已安装包；未知数据不会因普通保存而丢失。

不包含真实 Live2D/VRM 引擎、多音色重构、任意模型转换或整个应用的页面插件平台。
数值替代插件验证通用边界，不作为这些引擎的能力证明。模块来自已安装的可信插件，角色包只提供数据。

原[工坊交互 Demo](../../desktop/frontend/prototypes/studio-demo/README.md)保留评审时的控制器与表单快照，
防止继续依赖已移除的旧生产立绘编辑器。它仍是内存模拟，正式实现以 Spec 和真实 journey 为准。

## 验证与平台范围

Windows/Edge 浏览器已验证实际工坊编辑、保存、重开、A/B 参考语音及主题隔离、添加资源期间禁止切换、插件停用撤销，
并通过真实数值插件的提示词、普通/主动回复、历史、状态、一次动作、取消与重绑。
内置立绘模块也在真实浏览器中验证了准备/提交期间取消、解码与提交失败，旧画面保持且过渡层清理。
数值模型使用生产样式和布局代码验证 50%–150% 缩放，容器边界与命中几何一致。
Rust 回归验证模块来源、过期授权、数据路径、私有资源键及透明 PNG 命中。

此前 `journey-visuals` 的 Python 回归 234 项通过、4 项跳过；本轮前端完整回归 406 项通过。
Rust 资源回归 5 项、显示方式 DTO 回归 1 项、角色设置回归 2 项通过。正式工坊浏览器回归覆盖自动保存后的
连续改名、无效标签重开、修复后发布，以及 1274、820、680 像素宽度；旧 Demo 的工坊与设置联动回归也通过。
浏览器 profile 现有四个入口，新增保存回归使用桌面 CSP、40 张立绘和真实有界 Core 路由，覆盖重启通知先后次序、
保存后的目录刷新失败与布局；原生重启事件由测试桥模拟。Windows 开发版已用 `cargo build --locked --offline` 编译。
新原生命令需要运行本次构建的桌面端，已安装的旧版本不会因源码改变而自动更新。
各组覆盖有重叠，不累加为总测试数。文档检查由 `docs` profile 执行。

真实 Tauri 桌宠窗口的多显示器、DPI、拖拽、透明穿透和真实音频设备体验仍需按平台执行验收；不得把浏览器桥接验证
写成原生窗口通过。macOS/Linux 与真实 Live2D 模型未在此 Windows 会话验证。具体命令见表现插件 Spec。
