# 角色表现与语音组合改造方案

## 目标与当前状态

本方案尚未实施。目标是让角色作者声明表现资源、默认表现方式和默认 TTS，用户能分别更换表现与语音，
同时让已有合法立绘角色包继续直接加载、聊天、编辑和导出。角色 ID、人格、历史与记忆不随同角色的组合选择改变。

第一轮交付只使用现有立绘、GPT-SoVITS 和 Genie，不新增 Live2D、3D、语音引擎或朗读语言功能。
第二种渲染器用于后续验证扩展边界，不把第一轮通过等同于已经验证 Live2D 或 3D。

仓库已有 7 个预装插件与 1 个可选浏览器插件。本轮预期增加 1 个预装立绘渲染插件；插件数量不是验收标准，
不为凑数量新增表现 Hub、提示词插件或工坊插件。通用 Plugin Runtime 不增加按渲染器或 TTS 实现 ID 分支的逻辑。

## 已有机制与实际缺口

## 一、先明确数据归属

### 1. 角色包、用户覆盖、运行结果

角色包保存作者默认、包内资源和提供者配置；用户数据保存按角色 ID 分开的个人选择和参数覆盖；运行快照保存
本次实际使用的提供者、能力和状态。三者不能互相代替。

解析顺序为：用户明确覆盖 → 角色包默认 → 旧协议兼容解释。未设置、跟随默认和关闭语音必须有明确语义。
用户覆盖采用有限的按字段覆盖；移除覆盖才能恢复继承，不能把整个作者配置复制成永久覆盖。
不同 Provider 的私有配置分别保存，不跨引擎合并权重路径、参数或音色。账户凭据和机器配置不进入角色包。

旧包中已经被用户改写的 TTS 选择无法可靠区分是作者还是用户所写，升级时把当前保存结果作为有效基线，
不猜测作者原意，也不自动换回另一个引擎。现有语音兼容修复会带备份补写 manifest；先保留其兼容行为并梳理
调用路径，新增运行描述以读取时归一化为主，不新增升级即批量重写用户包的步骤。

角色包可以有多个表现版本。一个版本对应一组资源和一个渲染 Provider，同一 Provider 也可能对应多个版本。
用户选择的是本角色实际提供的版本，不能直接把所有已安装渲染插件当成可用版本。插件安装依赖按所选版本检查，
未选择的版本缺少插件不阻止角色运行。配置格式、插件接口版本与资源格式版本分别校验，不建立通用版本协商平台。

用户已选版本被作者更新删除时，保留覆盖并显示失效原因；若使用包内明确的回退版本，界面同时显示实际结果。
不能静默删除个人选择或把回退结果写成新的永久选择。

### 2. 配置源与运行状态同时可见

统一快照需要表达角色身份、作者默认、用户选择、实际选择、候选项、可用性和失败原因。
设置、运行时和提示词消费同一次解析结果，不各自推断 Provider 或回退规则。
公开 DTO 使用逻辑资源标识，不暴露角色绝对目录；Core/Rust/前端的严格字段校验同步演进。

## 二、设置页怎样调整

保留现有导航结构。在“角色”页增加“表现方式”，在现有“语音”页完善选择来源。
“外观”继续承载缩放、位置、主题等显示偏好；模型资源映射只在工坊编辑。

| 页面 | 字段与行为 | 保存位置 |
|---|---|---|
| 角色 | 当前角色；表现选择为“跟随角色包”或具体版本；显示实际版本和可用状态 | 当前角色配置与个人表现覆盖 |
| 外观 | 公共显示参数；需要时按角色/版本保存独立的构图参数，避免跨格式套用 | 对应用户配置 |
| 语音 | 跟随角色包、关闭语音、指定 Provider；显示实际引擎及来源 | 个人语音选择 |
| 语音提供者表单 | 保留现有表单能力；只编辑所选 Provider 参数，显示继承或覆盖 | Provider 对应个人配置 |
| 插件管理 | 插件安装、启停、版本与故障；由选择页面提供定位入口 | 插件安装和启用状态 |

第一轮只有立绘时显示“跟随角色包（立绘）”及当前状态即可，不展示不可执行的 Live2D/3D 选项，不让用户
为了维持旧行为重复选择一次。选择来源与可用性属于产品信息，插件内部服务名不放入正常使用流程。

统一应用流程：

1. 下拉选择只修改设置草稿，恢复默认也只是草稿操作。点击应用前不改 active character 或持久化选择。
2. 汇总本次涉及的角色/表现/语音草稿，校验字段、目标资源和依赖；失败保留草稿，定位具体项目。
3. 成功校验后保存本次配置。沿用已有分项保存结果，部分成功必须准确呈现，不能宣称整批原子成功。
4. 提供者参数保存失败时不提交其新的 active 选择。对本地个人覆盖可采用单文件原子替换，不扩展成跨插件事务平台。
5. 所有已授权保存完成后集中决定是否重载，最多发起一次受控 Core 重启，避免每个页面分别重启。
6. 等待新 generation 的角色、选择和表现一致，再解除切换锁并显示“已应用”。已保存但运行失败单独显示，
   保留恢复默认、重新配置和显式重试入口。

新表现草稿纳入现有角色级 dirty 检查。暂存另一个角色时继续锁定当前角色的外观/语音/表现编辑，
避免把 A 的参数保存到 B。第一轮新增表现选择不提供悬停即挂载模型的实时预览；现有角色静态预览继续保留。
后续模型预览必须有独立资源 scope，不切换正式聊天、TTS 或记忆，也不能污染正式命中区域。

## 三、角色工坊怎样调整

工坊编辑作者默认与资源；设置页编辑用户使用偏好。不能复用一个写入接口后仅靠页面名称区分用途。

| 当前工坊部分 | 第一轮调整 | 第二种渲染器到来时 |
|---|---|---|
| 基础信息、人设卡、配色 | 保留主要结构 | 按实际模型预览需要补充，不重做公共外壳 |
| 立绘 | 放入“表现”下的立绘编辑区域，复用图片列表、导入和标签；显示作者默认版本 | 增加版本列表、模型导入、默认/回退选择、表情与动作映射 |
| 语音模型 | 增加默认 TTS 选择；把现有 GPT-SoVITS 参数归属明确化；接入 Genie 的可携带参数 | 新 TTS 提供者按相同合同贡献字段 |
| 参考语音 | 保留已有编辑器；按 Provider 的适用资源展示，复用关系明确声明 | 不假设每个引擎都支持同一种参考音频或参考表 |
| 保存、发布、导出 | 扩展草稿和资源引用，复用现有发布机制 | 新格式继续走同一发布与校验路径 |

编辑器扩展先支持本次实际需要的字段、资源选择和校验，不先做完整的任意页面插件平台。
可复用运行设置的字段描述，但工坊读写必须绑定 `workspaceId` 和草稿修订，不能直接调用运行时
`character.update` 修改已安装包。插件只拥有自己的配置与资源声明，发布、归档和目录安全检查由宿主完成。

自动保存要保留扩展配置与资源引用。旧草稿仍能恢复；版本转换以副本读取和现有备份机制为基础。
插件缺失时保留配置及资源，显示只读状态；允许编辑不相关的人设或主题，不能因未知配置而清空整个版本。
新增或修改需要该插件解释的配置时，未验证状态不能冒充校验通过；导出已有内容与宣称新配置可运行分别处理。

当前未被引用资源的清理依赖立绘/语音字段。改造时扩展引用集合；对不理解的插件区域采取保留策略，
不能在保存主题、切换默认 Provider 或关闭语音时删除仍被其他版本引用的模型和参考音频。
发布采用已有 staging、比较、取消和恢复机制；未变化的包不触发重载，当前包确有运行相关变化时统一重载。

## 四、运行时与渲染插件边界

增加统一角色表现描述。旧 `portrait.default/expressions` 在入口解释成立绘版本，中文标签和原有回退顺序保留。
Assistant 输出使用表现字段，包含持续表情状态与可选一次动作；当前立绘没有动作资源时不向模型宣称支持动作。
提示词和输出校验使用同一份实际能力列表，普通聊天与主动回复共用它。无效表现只影响该表现，不丢弃有效回复。
保留现有日语朗读、中文翻译和语气默认，本轮不同时重做语言协议。

旧历史与旧回复的 `portrait` 继续可读，新写入和事件使用统一描述。静态历史回看默认不重放一次性动作。
Timeline、TTS 分段授权、Rust IPC 和前端 reducer 一起修改，不能只替换提示词里的单词。

渲染插件由同一个安装包携带注册/配置部分和前端渲染模块。前端模块运行于宿主明确管理的渲染环境，
不是从 Python 进程远程操作 DOM。现有 Plugin Runtime v4 的 Python 进程隔离并不自动赋予前端代码同样的隔离。
实施前在 ADR 中明确模块来源、资源协议、CSP、桥接权限及实例撤销；不能通过关闭 CSP 或向角色资源开放任意
宿主调用来实现加载。角色包包含资源和声明，插件代码通过插件安装路径提供。

宿主合同只包含加载/就绪/销毁、应用表情/动作、运行与音频播放事件、视口变化、布局锚点与命中信息。
公共选择协调与窗口能力留在宿主；图片选择、过渡等立绘实现进入预装插件。新 Provider 不增加聊天层类型分支。

沿用实际音频开始播放作为分段同步点；关闭 TTS 时按文字分段推进。高频嘴型、动画和物理计算在渲染侧完成。
准备过程有界，渲染失败不能无限阻塞字幕或 TTS。取消、切换和停机立即失效旧实例结果，清理 GPU 资源、
动画循环和事件订阅。默认立绘插件随发行包离线可用，支持按现有插件规则停用后由替代实现接管。

第一轮更换组合复用受控重启；角色 ID 不变时不清空历史和记忆，不假称本轮实现了无中断热切换。
新选择失败不自动改写原选择或循环重启。启动时可显示包内明确回退或宿主占位，语音不可用时保留文字聊天。

## 五、导入导出与兼容范围

继续读取当前 `.char`、`.voice` 和旧目录包；不把“缺少 renderer”当成损坏。
新版本中的资源根和版本声明必须由统一加载、工坊校验与归档逻辑共同理解。
第一轮旧能力包沿用可兼容的导出表示；需要新字段时保留旧字段的正确投影，而非让不同字段长期独立漂移。
新增读取兼容是长期行为，内部迁移期的两套渲染接线则应在切换完成后移除。

完整包导出作者默认与可携带资源，不自动把用户覆盖、API 凭据或机器绝对路径混入包。
暂不新增“把个人设置打包发布”的产品流程。无语音导出包含全部表现资源，移除语音配置/资源时不得留下
被声明为可用却缺少资源的默认组合；旧导出选项的兼容表示需用实际回导入证明。
旧 `.voice` 按既有语义读取，不在本轮强行扩展为任意 Provider 的通用模型容器；如后续确需新格式，新增版本并保留旧读取器。

共享音频或模型被多个版本引用时不能按当前引擎选择删除。资源声明和文件检查共同决定复制范围，保留未知
扩展区域的既有文件，遵守现有归档大小、路径穿越、符号链接与取消限制。

## 六、实施切片与交付检查点

下表是依赖顺序与相对工作量，不是日历工期；先完成前一切片的证据，再决定后续接口是否需要调整。

| 切片 | 主要工作 | 用户可观察结果与完成条件 | 相对工作量 |
|---|---|---|---|
| P0 兼容基线与契约 | 整理旧包/草稿/归档/历史样本；冻结数据归属、失效与恢复规则；提出渲染扩展 ADR | 明确哪些是既有行为，建立复现路径；未改变现有使用流程 | 中 |
| P1 组合解析 | 角色默认与个人覆盖；旧字段归一化；有效配置和可用性快照 | 现有角色/TTS 保持相同有效选择，加载不强迫用户迁移 | 中高 |
| P2 TTS 与设置闭环 | 复用两个 TTS Provider 接入有效配置；设置来源、dirty、保存、重载；工坊默认选择的最小编辑 | 旧立绘角色可换 TTS、重启保持选择、恢复默认；作者编辑和个人使用不串写 | 中高 |
| P3 表现协议与立绘适配 | prompt/解析/历史/IPC/reducer 统一表现；先用现有立绘实现适配 | 分段表情、字幕和语音保持现状；旧历史能读；无新模型功能 | 高 |
| P4 立绘插件化与表现设置 | 渲染模块宿主、资源/命中边界、预装插件；表现选择接入统一保存 | 所有旧包通过预装插件运行；设置显示真实可选版本；缺失/失败可诊断 | 高 |
| P5 工坊与归档闭环 | 表现与 Provider 编辑区域、草稿升级、引用清理、发布/导出；收拢临时适配接线 | 从创建/编辑到发布/导出再导入可完整使用；未知扩展和旧草稿不丢失 | 高 |
| P6 后续第二渲染器验证 | 单一真实 Live2D 样本和必要编辑能力，验证动画/命中/清理 | 在不修改聊天类型分支的前提下完成第二表现与现有 TTS 组合 | 后续单独估算 |

交付检查点 A = P0–P2，完成现有 TTS 的作者默认/用户选择闭环；不用等渲染插件化才验证这部分。
交付检查点 B = P3–P5，完成现有功能的插件边界、设置和工坊全过程，是本轮整体目标。
检查点 A 对外发布前必须完成涉及字段的旧工坊保存和归档回归，不能以 P5 尚未开始为由发布会丢数据的中间态。
检查点 C = P6，另行进入 Live2D 功能开发，3D 和无中断热切换在其后按实际需求推进。

P3/P4 开发期间可短期通过内部分支验证新路径，但不要求普通用户在新旧协议之间选择，也不长期保留两个生产渲染流程。
未通过真实窗口验证不切换默认启动路径。回退到上一可运行实现时保留用户覆盖和角色包，不删除新配置来制造兼容。
不能承诺任意旧版二进制能读未来新格式；这里保证的是新版读取旧包，以及本轮旧能力包的兼容往返。

## 七、验收按用户旅程组织

| 旅程或故障 | 核心证据 |
|---|---|
| 升级后使用旧包 | 仅默认立绘、多表情中文标签、旧 voice、已有扩展 TTS、无语音都直接加载并互动 |
| TTS 替换 A→B→A | 人格/表现不变，各引擎参数保留，重启后选择一致，恢复默认后重新继承 |
| 设置应用/取消 | 取消不持久化；部分保存准确呈现；失败不激活未保存选择；一次应用最多重启一次 |
| 角色 A/B 与草稿 | A 的覆盖和预览不写入 B；旧回调无效；保存未完成不宣告切换成功 |
| 工坊旧草稿恢复 | 自动保存、关闭、重开、发布保留编辑内容和未知扩展；不清理其他版本使用的资源 |
| 发布与回导入 | 旧 `.char`/`.voice` 可读；完整/无语音导出语义正确；导出不夹带个人覆盖和凭据 |
| 字幕、语音和表现 | 按实际分段启动，禁用 TTS 仍能表现；历史可读；无效表现不丢有效文本 |
| 插件故障 | 缺失、停用、配置无效与启动失败区分；无静默永久换引擎；文本路径仍可用 |
| 渲染生命周期 | 快速切换/取消、尺寸变化、鼠标穿透、预览撤销、销毁后无残留动画和资源 |

优先扩展现有 character packages/archive/studio、voice runtime、Timeline、portrait controller 和 character switch 测试，
按最接近用户行为的一层提供主要证据。使用隔离临时根，不读取真实聊天或用真实包做故障注入。
资源/IPC/原生窗口跨边界风险分别验证；UI 不用 CSS 数值或完整文案断言代替交互验证。
真实桌面检查覆盖布局、点击穿透、音频停止和预览恢复；针对受影响平台执行，未验证的平台明确记录。

## 八、文档和范围管理

本计划不改变现行 Spec。各切片随实现更新角色加载/表现、设置、工坊、聊天事件/存储和插件 SDK 的对应合同，
前端模块执行边界及作者默认/用户覆盖取舍记录到 ADR，未实现设计不得标为已支持。
新增 Live2D/3D、通用工坊页面扩展框架、任意模型格式转换、无中断热切换、全程序插件化均不进入第一轮。
原有 Mem0、ASR、手机和浏览器插件保持既有功能，只有确有共同合同变更时才调整调用，不顺带重写。
