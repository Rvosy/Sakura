# 聊天、截图与屏幕感知

Sakura 的普通消息、截图消息和主动搭话共用一条聊天链。发送期间，输入栏会显示当前状态；取消会中止本轮模型请求和仍在执行的工具，但不会删除已经完成的对话。

## 发送消息和截图

直接在输入栏输入文字并发送即可。点击输入栏左侧的 `+` 可以选择截图：

- “截图”截取当前屏幕；
- 框选截图会打开覆盖层，拖出区域后把图片附到下一条消息；
- 插件也可以在这个菜单注册自己的动作。

截图先由桌面端处理，再以一次性资源交给当前 Core。聊天完成、取消、失败或 Core 重启后，临时资源都会失效。图片不会作为文件路径写进聊天记录。

带图片的请求需要视觉模型。在“设置 → 模型”中选择“视觉对话模型”；没有单独设置时，Sakura 会尝试使用当前对话模型。模型不支持图片输入时，本轮请求会明确失败，不会改成只发送文字。

## 主动屏幕感知

“设置 → 隐私 → 主动屏幕感知”包含这些选项：

- 是否启用；
- 主动检查间隔；
- 两次主动发言之间的冷却时间；
- 单次最多发送的截图数；
- 全分辨率、720p、1080p 或 2160p。

到达检查时间后，Sakura 截取鼠标所在的屏幕。固定分辨率只会等比缩小，不会放大小屏幕。聊天、截图或上一轮主动请求仍在运行时，本轮检查会跳过；从睡眠恢复后也不会补跑积压任务。

主动截图按批次暂存在内存中。真正发起请求时，Sakura 只取当前批次允许的最新图片。模型判断无需开口时，界面保持安静；这类请求不会播放空回复。

## 对话记录与上下文

聊天记录保存在 `data/chat_history/timeline.sqlite3`。每条记录带有角色、类型、来源和时间，文字、截图观察与 TTS 留存可以属于同一轮对话。Sakura 不把图片二进制写入 Timeline，只保存经过清理的文字说明和必要元数据。

发送新消息时，Core 会从近期对话、长期记忆和当前运行上下文中挑选内容。内容超过模型预算时，优先保留系统提示、当前输入和最近完整对话，再裁掉较早或重复的信息。被裁掉的内容仍在本地记录中，只是不进入这次模型请求。

## 隐私与故障

主动屏幕感知默认由设置开关控制。截图可能包含其他应用、通知和账号信息，启用前应确认当前桌面内容适合发送给所选模型服务商。

遇到问题时先检查：

1. 视觉对话模型是否已配置并支持图片；
2. 系统是否授予截图权限；
3. 主动感知是否处于冷却或忙碌状态；
4. [`sakura-runtime.log`](RUNTIME_LOG_TROUBLESHOOTING.md) 中是否有 `Screen`、`Chat` 或 `API` 失败。

不要手工编辑正在使用的 Timeline 数据库。需要排查数据问题时，先退出 Sakura，再备份整个 `data/`。
