# API 模型服务与模型

Sakura 默认通过“OpenAI 兼容模型服务”插件连接模型 API。配置一套连接需要服务商提供的 API 地址、API Key 和至少一个模型名称。

API Key 保存在本机配置中，设置页不会回显完整密钥。日志会对已知密钥和常见凭据格式脱敏；分享日志前仍需检查错误详情。

**版本差异：** 1.3.1 需要填写 API Key；免认证服务可留空 Key 的行为适用于 1.3.1 之后的源码版本，正式安装版请以对应 Release 说明为准。

## 添加模型服务

首次配置按[图文教程](SETUP.md#配置模型服务和模型)完成。本文说明后续修改和排查时需要的细节。

### 密钥与保存

新服务填写自己的 API Key。修改已有服务时，输入新 Key 会替换旧密钥，留空则保留；已有凭据时可点击“清除凭据”删除。

“获取模型列表”和“测试连接”可以使用尚未保存的配置，点击后会立即请求服务商，可能消耗 API 额度。完成修改后，点击“应用”或“保存并关闭”。

Sakura 可以保存多套模型服务。修改其中一套不影响其他连接；模型选择与连接密钥分别保存。

源码新版允许名称留空。重复添加同一模型时，列表不会保留重复项。

保存连接或模型参数后，新配置通过重载模型插件生效。正在运行的请求仍使用原配置；源码新版在当前对话未结束时允许先保存，等对话结束后再应用。
应用期间刚启动的后台整理或连接测试可能被取消；已保存的记忆会保留，未完成的整理留待后续处理。

需要调整生成效果时，展开“模型 → 高级参数”。这里可设置上下文上限、创造性（temperature）、用词多样性（top_p）和回复长度上限（max_tokens）；首次配置先保留默认值。

## 模型用途

“模型”页至少包含两个固定用途：

- 对话模型处理日常聊天、工具调用和角色回复；
- 视觉对话模型处理截图和其他图片消息。

记忆、语音等插件可以在同一页面添加各自需要的模型选项。停用插件后，对应选项会从页面移除，其他选择不受影响。

可选用途勾选“继承”时随对话模型使用同一选择。模型服务停用或模型被删除后，原选择会标为不可用并保留，
重新启用服务或更换选择即可恢复。Memory 的整理模型不可用时，只停止自动整理，已有记忆仍可管理和召回。

需要使用联网等插件工具时，所选对话模型也需支持工具调用。

视觉模型必须支持图片输入。只支持文字的模型仍可用于普通聊天，但收到截图时会返回明确错误。

## 获取模型服务信息

在服务商的开发者控制台或 API 接入文档中，确认以下三项来自同一服务：

- API 地址（Base URL）；
- 为该服务创建的 API Key；
- 账号可以调用的准确模型 ID。

网页聊天会员不一定包含 API 额度，请单独查看服务商说明。拿到信息后，回到[添加模型服务](#添加模型服务)。

使用中转服务时，API 地址、密钥和模型 ID 都以该服务的接入说明为准，不要混用不同服务商的信息。

## 验证与排查

连接测试只检查该连接列表中的第一个模型，成功后会显示模型名称。测试结果不代表其他模型或图片输入能力可用，视觉用途仍需选择服务商明确支持图片的模型。
失败状态显示错误码，可结合运行日志查看原因。

- `401`：检查 API Key。
- `403`：服务拒绝访问，检查账号权限或服务限制。
- `404`：检查 API 地址是否包含正确的 API 前缀，模型名称是否存在。
- `429`：服务商限流或额度不足，稍后重试或更换模型服务。
- 视觉用途配置：确认所选模型支持图片输入。

代理由系统环境和 Runtime 的网络库读取。排查时不要把带密钥的配置、完整请求头或 Agent Trace 发到公开 Issue。
