# API 供应商与模型

Sakura 通过 OpenAI-compatible 接口连接模型。配置一套供应商需要 Base URL、API Key 和至少一个模型名称。

| 配置项 | 内容 |
|---|---|
| Base URL | 服务商提供的 API 地址，通常以 `/v1` 结尾 |
| API Key | 服务商生成的访问密钥 |
| 模型 | 服务商模型列表中的准确名称 |

API Key 保存在本机配置中，设置页不会回显完整密钥。日志也不会记录它。

## 添加供应商

1. 打开“设置 → 供应商”。
2. 新建供应商，填写名称、Base URL 和 API Key。
3. 保存后运行连接测试。
4. 打开“设置 → 模型”，为各用途选择供应商和模型。

Sakura 可以保存多套供应商。修改其中一套不会重写其他供应商，也不会把模型选择和密钥合并成一个配置。

## 模型用途

“模型”页至少包含两个固定用途：

- 对话模型处理日常聊天、工具调用和角色回复；
- 视觉对话模型处理截图和其他图片消息。

Memory、TTS 或其他插件可以在同一页面注册自己的模型用途。插件停用后，它拥有的项目会从页面移除，其他选择不受影响。

视觉模型必须支持图片输入。只支持文字的模型仍可用于普通聊天，但收到截图时会返回明确错误。

## 验证与排查

连接测试成功只说明供应商端点和凭据可用。完成设置后再发送一条普通消息；若要启用截图功能，还应发送一张图片验证视觉模型。

- `401` 或 `403`：检查 API Key、账号权限和服务商额度。
- `404`：检查 Base URL 是否包含正确的 API 前缀，模型名称是否存在。
- `429`：服务商限流或额度不足，稍后重试或更换供应商。
- 图片请求失败：确认视觉用途没有选到纯文字模型。

代理由系统环境和 Runtime 的网络库读取。排查时不要把带密钥的配置、完整请求头或 Agent Trace 发到公开 Issue。
