# 匿名统计与远程诊断

Sakura 默认发送少量匿名统计，用来定位程序错误、了解版本兼容情况，并检查模型请求的 Context 是否过大。它不依赖账号，也不会读取
完整日志后上传。

你可以在“设置 → 系统 → 匿名统计”关闭“发送匿名统计数据”。关闭后，错误报告、基础使用统计和模型运行指标会一起停止；聊天、
语音、Memory、插件和更新不受影响。Sakura 不会在首次运行时弹出确认页。

## 会发送什么

发生 Sakura 自身错误时，报告可能包含：

- Sakura 版本、发行渠道、操作系统版本和 CPU 架构；
- 稳定错误码、错误类型和经过清理的代码位置；
- 错误前最多 40 条结构化状态，例如组件、事件、结果和耗时；
- 随机诊断 ID、单次报告 ID，以及本次运行或操作的随机关联 ID；
- 新安装、升级或迁移状态。

错误报告也覆盖部分 TTS 内部故障，例如本地语音进程提前退出、合成产物无效或已生成音频无法读取。没有音频设备、端口被占用、
缺少 Python 或权重、第三方语音服务不可用和普通超时不会生成完整错误报告。

基础统计只记录启动、启动完成、迁移结果，以及本次运行是否用过聊天、语音、Memory、工具或插件。Sakura 不发送心跳、使用时长、
点击路径、角色名、插件名称或工具名称列表。

每次真实模型请求可以记录 token 数量、Context Window、请求用途、耗时和结果。Provider 返回的 token 用量与 Sakura 自己的估算会
分开记录。自定义模型名统一记为 `custom`，不会发送原始模型 ID 或 Provider URL。

## 永远不会自动发送什么

匿名统计不会自动发送：

- 聊天内容、Prompt、Memory、模型回复或角色内容；
- 工具参数、工具结果和工具 schema 正文；
- `sakura-agent-trace.log` 或完整的 `sakura-runtime.log`；
- API Key、Cookie、Authorization、账号和其他凭据；
- 绝对文件路径、用户名、机器硬件标识；
- 图片、音频和其他二进制内容；
- 原始异常消息或自定义模型名称。

如果以后增加“发送详细诊断报告”之类的功能，它必须有单独的用户操作和说明，不能沿用当前开关自动上传更多内容。

## 诊断 ID

设置页会显示一个随机 UUID，称为“诊断 ID”。它不来自账号、硬件或 Windows/macOS 的机器标识。升级 Sakura 时该 ID 保持不变，
方便维护者把同一安装的多次错误放在一起排查。

你可以复制诊断 ID，也可以重新生成。重新生成只影响以后发送的数据，不会自动删除服务器上的旧记录。关闭匿名统计后，已有 ID 仍会
显示，便于查询旧报告或申请删除。

诊断 ID 不是密码，也不能证明请求一定来自官方 Sakura。提交 GitHub Issue 时只需提供诊断 ID 或单次报告 ID，不要附带聊天、
Agent Trace、密钥或未经检查的完整日志。

## 网络与保留时间

数据通过 HTTPS 发送到 `telemetry.cialloo.cn`，由多吉云 CDN 转发到 Sakura 的 VPS，再写入专用 SQLite 数据库。CDN 在建立连接、
转发请求和限制滥用时会接触客户端 IP 等网络信息。Sakura 的数据库不保存 IP 或 User-Agent，源站 Nginx 和 FastAPI/Uvicorn 的
访问日志也已关闭；服务端不会从转发头中提取 IP 写入遥测记录。

原始错误、运行事件和模型指标最多保留 90 天。关闭开关不会删除已经发送的数据。如果需要查询或删除，请在
[GitHub Issues](https://github.com/Rvosy/Sakura/issues) 中提供诊断 ID，并说明要查询还是删除。维护者会按该 ID 处理三类记录。

## 发送失败时

匿名统计使用短超时和内存队列，不写磁盘重试。网络不可用、服务超时或队列已满时，记录可能直接丢失。Sakura 不会因此弹出错误、
阻止启动或影响聊天。
