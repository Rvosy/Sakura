# 运行统计与错误报告

Sakura 默认发送运行统计和错误报告，帮助维护者定位程序 bug、检查版本兼容性和模型请求情况。不需要登录账号，也不会扫描完整日志后上传。

你可以在“设置 → 系统 → 匿名统计”关闭“发送匿名统计数据”。关闭后停止全部遥测发送，并删除本机尚未发送的错误报告；聊天、语音、Memory、插件和更新不受影响。

## 错误报告包含什么

错误发生时，报告可能包含：

- 原始报错、异常原因链、调用栈、源码位置，以及恢复操作的错误；
- 失败的实际文件路径、模型名称、请求目标 URL、HTTP 状态和子进程 stderr；
- 有关插件的 ID/名称、失败阶段、系统错误码、退出码和耗时；
- 错误前最多 40 条相关事件及诊断文字；
- Sakura 版本、构建、系统和 CPU 架构，以及随机关联 ID。

原始报错可能带有本地用户名、目录或失败数据片段。这些内容能帮助区分缺文件、权限错误、重复导入或提供商参数问题。API Key、Authorization、Cookie、密码、token 和 URL 登录凭据会按具体值替换，其他报错内容保留。

同一运行中的完全重复错误可以累计次数，不反复发送相同样本；不同底层原因保留各自报告。此前没有登记过的异常也可以上报。

## 运行统计包含什么

基础统计记录 Shell/Core 是否就绪，聊天、语音、迁移和回复修复的结果，以及功能是否使用过。模型指标记录用途、耗时、结果、token 用量和 Context 估计，服务端实际用量与本地估计分开。

这些统计不默认采集整段聊天、Prompt、Memory、完整模型回复、工具输入输出、图片、音频或局部变量，也不上传完整 `sakura-runtime.log` / Agent Trace。错误报告里的原始异常和失败片段按上一节处理。

## 暂存和保存期限

错误报告发送前暂存在 UI 配置同级的 `telemetry-pending-errors` 目录，最多 64 份、每份 128 KiB、最长 7 天。成功发送后删除；网络失败时保留，下次启动或运行中空闲时重试。容量满时移除最旧记录。普通运行统计和模型指标不落盘补传。

诊断 ID 随机生成，与账号和设备硬件无关。重新生成 ID 会清理旧 ID 的待发报告，只影响后续数据，不删除服务器历史记录。服务器原始记录最多保存 90 天，仅通过受保护的管理端查看和导出。
