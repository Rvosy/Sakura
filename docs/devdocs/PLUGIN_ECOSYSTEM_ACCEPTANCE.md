# 开放插件生态初版验收

本指南用于检查独立插件能否接入原有对话入口，以及 Context 内容能否由插件提供。
日常验收可以直接使用已有角色包和配置；需要空白环境时，再使用独立数据准备脚本。

## 使用已有角色包和配置

先从托盘菜单退出正在运行的 Sakura，再运行仓库中的
[`scripts/start-existing-data.bat`](../../scripts/start-existing-data.bat)。
Windows 默认使用 `%LOCALAPPDATA%\Sakura Development`，这是仓库开发版的日常数据目录。
原来的角色选择、角色包、模型配置、插件开关和聊天记录都从这个目录读取；启动器不创建验收角色，也不重写这些配置。

如果平时使用的是安装版，Windows 安装版的数据位于其程序目录，可明确传入那个已有目录：

```powershell
scripts\start-existing-data.ps1 -UserRoot 'D:\Sakura'
```

启动器只为本次进程指定数据目录。验收中的聊天和设置保存会直接写入所选目录；它们就是日常使用的数据。
程序仍保持原来的互动方式。要体验计时，在插件管理中安装并启用 `dist/focus_companion-0.1.0.sakplugin.zip`，
再到“设置 → 模型 → 互动方式”选择“专注陪伴”。切回默认 Assistant 后继续使用已有模型配置。

首次打包插件的方法见[专注陪伴 README](../../plugins/optional/focus_companion/README.md)。
下面计时、停止和重载步骤同样适用于已有数据；其中“没有 API 配置”的预期只适用于独立环境。

## 新建独立验收环境

这条路径使用仓库开发版、插件和 Sakura 图标，在新目录内创建空白数据。
准备脚本不会读取现有用户配置、角色或聊天记录，也不会启动窗口。

在 Windows 仓库根目录运行：

```powershell
runtime\python.exe scripts\prepare_plugin_acceptance.py
```

脚本默认创建 `temp/plugin-acceptance-日期时间-随机标识`。也可以用 `--user-root` 指定新目录；目录已存在时拒绝写入。
它通过正常安装器安装“专注陪伴”和“对话规则”，启用“专注陪伴”与内置“立绘”，关闭其他预装插件，
创建“Sakura 验收”角色和空 Timeline。环境没有 API 配置，默认互动方式为“专注陪伴”。“对话规则”已安装但未启用。

脚本会启动真实插件进程，检查 Assistant 就绪和立绘资源加载，然后关闭这些进程。
生成的 `acceptance-environment.json` 记录目录与检查结果；`guiVerified: false` 表示这一步还没有检查窗口体验。

先从托盘菜单退出正在运行的 Sakura，再双击生成目录中的 `启动验收.bat`。Sakura 使用单实例，启动器检测到已有进程时会提示退出。
也可以用 PowerShell 运行同目录的 `启动验收.ps1`。启动器只对本次进程设置 `SAKURA_RUNTIME_USER_ROOT`，工作目录使用仓库根目录。

启动器使用 `desktop/src-tauri/target/debug/sakura.exe`。可执行文件缺失或需要更新到当前代码时，在仓库根目录编译：

```powershell
cargo build --manifest-path desktop/src-tauri/Cargo.toml --locked
```

准备脚本和启动器均不会自动编译。验收角色使用 Sakura 图标作为立绘，因此外观较简单；计时与回复走实际产品入口。
这个环境未启用语音插件，以下步骤主要检查气泡、操作状态和聊天记录。

## 无模型互动

| 操作 | 应当看到的结果 |
|---|---|
| 打开聊天，发送“你好” | 收到专注计时的用法提示，无需配置模型。 |
| 发送“专注 10 秒 整理桌面” | 显示剩余秒数，输入处于忙碌状态；实际计时结束后只出现一条完成回复。 |
| 计时中查看聊天记录，完成后再查看 | 剩余秒数不成为助手历史条目；最终完成回复只记录一次。 |
| 发送“专注 1 分钟 阅读”，中途点击停止 | 停止实际计时，回到可输入状态；一分钟到点后也不应出现迟到的完成回复。 |
| 再次发送短计时 | 新任务正常完成，取消的旧任务不会接着运行。 |

进度是当前操作的临时显示。原来的用户输入可能已记录，取消不会删除这条输入，也不会伪造助手完成回复。
仅观察窗口不能单独证明线程退出；实际停止与线程回收另由自动回归测试验证。

## 切换与重载

1. 启动一分钟计时，打开设置，把互动方式改为默认对话。设置应显示切换等待当前操作结束；当前计时继续使用原插件。
   可等待结束，也可回聊天点击停止。当前操作退出后，默认对话才生效。
2. 此环境没有 API 配置，默认对话应进入需要配置模型的状态。设置仍能打开，立绘仍可显示。
   把互动方式切回“专注陪伴”后，应恢复就绪，再发送十秒计时确认可用。
3. 在插件管理中停用“专注陪伴”。当前选择应显示不可用，不应自动切到默认对话。
   再启用插件后，在互动方式旁点击“重试”，确认同一个服务选项可以恢复使用。
4. 重复发送一次短计时。旧进程的结果不能补写历史，新进程应只为这次输入返回一次完成回复。

若需要查看落盘结果，先退出验收程序，再检查报告中 `timeline` 指向的数据库。
该目录也包含本次验收产生的日志；保留它即可继续同一轮验收。需要重新开始时，重新运行准备脚本创建另一套目录。

若出现“无法确认互动插件已停止”，本次清理没有成功确认，程序会拒绝继续发送或应用执行器切换。
从托盘退出 Sakura 后重新启动验收环境。这个异常路径由故障注入测试覆盖，正常计时验收无需人为制造清理故障。

## 对话规则

这部分检查 M1 的默认模型对话。离线计时插件不消费 Context，不能用计时结果判断“对话规则”是否生效。

先在这套验收环境内自行配置可用模型，再切换到默认对话。启用“对话规则”，在它的“上下文”输入框中填写：

```text
接下来陪我练习日语。我用中文提问时，先给出一句自然的日语表达，再用中文解释。
今天练习的话题是整理房间。
```

保存后发送“怎么说‘我先整理桌面’”。检查默认模型对话是否采用所填内容；模型输出有波动时，结合本次请求的 Trace 检查实际上下文。
插件只有一个上下文输入框，文本可以同时包含要求与资料，不需要选择用途分类。

把内容清空、保存并停用后再启用，应继续保持空白。已有旧版配置的保留与两字段合并由自动回归测试覆盖；
准备脚本创建的是新配置，不会复制真实用户配置来演示迁移。

相关设计见[开放插件生态总计划](../plans/runtime-v2/open-plugin-ecosystem.md)，插件接入见[Plugin API v4 开发指南](SAKURA_PLUGIN_SDK.md)。
