# ADR-0051：移除未使用执行器实验，明确 Collection 归属

## 背景

ADR-0050 保留了已经撤回入口的执行器实验。正常产品只使用默认 Assistant，但 Session、初始化、聊天提交与桌面进度仍维护另一套开发路径。
审查还发现该路径取消后可能无限轮询，坏的可选表现控制会使有效文字丢失并触发整插件停止。没有当前消费者，继续修补这条备用路径会增加维护负担。

Collection 的运行实例需要统一保护，但全局记录并不属于当前角色。上一版把所有打开的编辑器当作角色草稿，导致查看记录也阻止切换，且无法保存全局草稿跨角色使用。

## 决策

删除执行器 Catalog、适配器、备用 Session 接口、专用进度与终态分支，以及专注开发样例和仅服务该实验的测试。
正常聊天只调用现有 ChatPipeline，保留动作校验、取消仲裁、历史、表现与 TTS 的实际保护；仍有消费者的真实 Core 夹具迁入其实际使用的测试。
TTS、ASR 已使用的普通服务绑定及精确实例回收继续保留。未来迁移默认对话时，用一个真实公开边界替换当前调用链，不长期维护双轨。

Collection 直接比较可编辑字段与打开时的原值，打开编辑器不等于修改。改回原值解除草稿阻断，写入仍由 Collection 自己的操作提交。
新增可选声明 `scope`，仅有 `global` 和 `character`：角色归属只影响角色草稿门禁及换角色时的页面清理；全局草稿跨角色保留。
Core 转场期间所有 Collection 都停止使用旧请求身份，保留删除确认复核和回执隔离，不自动重放写入。

旧 Collection-v0 缺省 `character`，保留已安装 Mem0、便签及其他旧角色集合的保护；新贡献应明确声明归属。
宿主不从 surface 或插件名称推断 scope，也不改写插件数据库。明确声明新字段的插件需与支持该字段的宿主配套使用。

“应用”允许保留全局 Collection 草稿并提交其他设置；角色草稿仍须先保存或放弃。“保存并关闭”仍阻止未保存记录，不能让用户误以为集合已保存。
用户停用或卸载插件若会使仍在修改的集合失效，先要求处理受影响插件的记录，复用现有依赖关系判断，不另建草稿存储。

## 未采用的方案与后果

- 将执行器实验搬到另一生产目录：仍需维护没有产品消费者的运行路径。
- 为实验补通用重试、任务恢复或授权平台：扩大当前宿主，不能解决维护边界问题。
- 继续将所有集合视作角色数据，或用 Memory 页面判断归属：限制全局插件，也把呈现方式与数据语义绑在一起。
- 未声明 scope 就改成 global：旧插件无需升级就会失去角色草稿保护，可能把旧角色内容带入新角色。

本决策部分替代 [ADR-0050](0050-thin-host-and-plugin-owned-policies.md) 中保留执行器实验及所有 Collection 统一按角色清理的条款；薄宿主、插件拥有业务和默认策略的方向不变。
