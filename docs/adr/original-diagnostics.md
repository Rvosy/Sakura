# ADR：统一记录操作步骤并保留原始诊断

## 问题

聊天、插件、模型和窗口跨多个进程协作。只有笼统的“失败”无法定位步骤，每层重复包装又容易遮住最初原因；普通轮询大量打印会淹没有价值的信息。

## 当前决定

Rust 统一接收并写入运行日志。Core、插件和前端沿各自既有入口提交诊断，共用操作身份、顺序和格式。按用户操作的实际步骤记录对象、开始、进度、结果和必要耗时，普通无变化轮询留在调试级别。

错误在产生处保存原始消息、原因链和栈，跨层传递继续保留。恢复错误作为附加诊断，不覆盖首因；取消和正常重载按实际状态表达。

Agent Trace 与普通日志分开，记录默认 Assistant 实际使用的模型输入和输出。远程诊断复用同一错误捕获链，通过用户开关控制发送；只移除具体凭据，不把其他诊断压缩成通用错误码。

## 理由

一条完整的操作链比多层重复日志更容易回答“哪一步失败”。一个写入者也避免不同进程对同一文件争用、交错或各自维护不一致的轮转规则。

普通诊断和正文 Trace 的用途及隐私范围不同，分开后用户可以选择需要的排查深度，也不会误以为关闭远程统计就等于未在本机保存 Trace。

## 影响与代价

原始异常可能包含路径和失败数据片段，因此分享范围必须如实说明。已知凭据在诊断边界清洗，不能依赖每个调用者自行改写错误文本。

日志、Trace 和远程发送失败不能改变聊天、保存和关闭结果，也不能据此重试业务。诊断需要沿实际异常链验证，而不是只检查一条固定文案。
