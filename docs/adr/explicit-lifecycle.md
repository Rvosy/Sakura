# ADR：局部应用变化，明确失败后由用户重试

## 问题

普通设置或角色切换若重启整个 Core，会同时丢掉模型、语音和其他插件的可复用状态。后台自动重启又可能掩盖首个错误，令结果未知的请求被重复执行，或让旧异步回调写入新的角色和窗口。

## 当前决定

运行时变化由明确操作驱动。配置能够热应用时在原实例内完成；必须重启时只处理目标插件及相关硬依赖。角色切换退役旧会话和授权，保留可复用的 Core、引擎及无关插件。

Core 崩溃或启动失败后保留窗口、草稿和具体原因，清理旧进程树，由用户明确重试。插件故障只停止该插件与实际依赖它的消费者，不以后台循环反复恢复，也不因为下一次聊天到来而补做设置应用。

请求、回调和资源绑定所属 Core generation、插件 scope 或界面会话。关闭、重载和切换使旧身份失效；迟到的成功与失败都不能覆盖新对象。

## 理由

用户修改的范围通常小于整个应用。让资源拥有者处理自己的变化，可以保留昂贵的加载结果，同时使失败归因于实际步骤。

结果未知不等于操作未发生。对模型请求、工具和写入自动重放会制造重复副作用，明确失败与手动恢复更符合现有使用规模。

## 影响与代价

瞬时故障有时需要用户再点一次重试。长任务必须提供真正的取消和资源回收，不能把调用超时当作已经停止；新的实例也不能复用旧句柄继续查询。

保存与应用分别报告。已写入的配置不会因为运行态应用失败就被误报为未保存，当前仍有效的内容与未完成草稿继续保留。具体持久化和恢复行为由所属模块规定。
