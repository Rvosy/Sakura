# ADR-0003：Runtime v2 用户数据兼容与 legacy Qt 回退

> 状态：Proposed
> 日期：2026-07-15
> 适用范围：Runtime v2 与 legacy Qt 入口共享的角色、配置、历史、Memory 和用户目录数据

## 背景

Runtime v2 在开发分支中提前切换默认 Tauri 入口，同时保留 legacy Qt 作为显式回退。保留源码本身不能保证回退可用：如果 v2 修改共享数据格式、迁移失败或两个入口同时写入，Qt 可能已经无法读取用户数据。

本 ADR 定义首轮迁移期间的数据安全底线。目标不是建设通用迁移平台，而是保证逐步替换桌面层时用户数据不被新入口破坏。

## 不可妥协的约束

- Phase 1–3 不执行破坏性用户数据迁移。
- 现有角色资源、Core 配置、历史、Memory 和用户目录优先原样复用。
- legacy Qt 仍受支持期间，共享数据写入必须保持 Qt 可读且不会破坏旧入口启动。
- v2 专属桌面/UI 配置使用独立文件或独立命名空间。
- Tauri 和 legacy Qt 使用同一应用锁，同一用户会话中两个桌面入口不能同时运行，也不能出现两个共享数据写入者。
- schema 迁移必须有版本、迁移前备份、原子切换、失败恢复和明确回退策略。
- 迁移或兼容验证失败时，保持原数据并阻止危险写入，不能带病继续。

## 数据分类

```text
共享且优先原样复用
├─ characters / 角色资源
├─ core 配置
├─ history
├─ memory
└─ 现有用户资源目录

Runtime v2 专属
├─ desktop.*
├─ ui.*
└─ Tauri 窗口与 Shell 状态

所有权待 Phase 4 确认
└─ audio.*
```

v2 专属数据不得写入 legacy Qt 会误读的键或文件位置。

## 应用锁

- 两个入口使用同一个稳定 lock identity，不按可执行文件名区分。
- 锁由桌面生命周期根持有，从启动前检查持续到窗口、Core 和写入任务全部退出。
- Tauri 持锁时启动 legacy Qt，或 Qt 持锁时启动 Tauri，都应显示明确提示并安全退出，不进入第二套 Core。
- Core 子进程不另行竞争桌面应用锁；它的写权限来自当前持锁的桌面根进程。
- 异常退出后锁必须由操作系统自动释放，不能依赖易残留的普通标志文件作为唯一判断。

锁的具体 Windows 实现由 Phase 1A 技术验证决定，但不能弱化“同一用户会话只有一个桌面根”的结果。

## Schema 变更与迁移协议

Phase 1–3 原则上只允许：

- 只读复用。
- Qt 可忽略的向后兼容字段。
- v2 独立命名空间中的新增数据。

确需修改共享 schema 时，必须先提交独立设计并满足：

1. 为源格式和目标格式定义明确 schema version。
2. 在同一文件系统内创建可验证的迁移前备份。
3. 写入临时目标并完成解析、校验和关键记录计数。
4. 使用原子替换切换到新数据。
5. 任一步失败都恢复或继续使用原数据。
6. 明确 legacy Qt 是继续读取、通过兼容层读取，还是从该版本起不再作为回退；最后一种情况必须由用户单独批准。

不得在应用启动过程中静默执行不可逆迁移。

## 兼容门禁

Phase 0 记录实际数据样本和路径基线。Phase 3 前必须自动化或半自动化验证：

```text
legacy Qt 创建/修改角色、配置、历史和 Memory 数据
-> 退出 Qt
-> Tauri v2 获取同一应用锁并读取数据
-> 使用原数据完成基础聊天并写入允许的兼容数据
-> 退出 Tauri，确认 Core 和写入任务全部结束
-> legacy Qt 重新获取应用锁
-> Qt 可启动、读取原角色/配置/历史，并识别允许的新增记录
```

还需覆盖：

- 两个入口同时启动时只有一个成功持锁。
- v2 专属配置不会改变 Qt 行为。
- 迁移前备份失败时不修改原数据。
- 临时写入或校验失败时原数据仍可读取。
- 进程在写入中断后，原文件或已提交的新文件至少有一个完整可读版本。
- 不支持的未来 schema 会进入 diagnostics/只读安全状态，而不是尝试降级覆盖。

## 结果与代价

收益：

- legacy Qt 是可验证的真实回退，而不是仅保留源码。
- Runtime v2 dogfooding 不会以用户数据为代价。
- 后续停止 Qt 回退时有明确决策点，而不是被格式变化意外切断。

代价：

- Phase 0 需要补充真实数据基线和兼容夹具。
- Qt 回退期内，共享 schema 演进受到向后兼容约束。
- 双入口不能同时运行，开发调试需要显式退出前一个入口。

## 允许调整的范围

可以调整锁的具体 API、备份命名和迁移工具，只要以下结果不变：

- 同一用户会话只有一个桌面生命周期根和写入者。
- Phase 1–3 无破坏性迁移。
- 迁移失败不损坏原数据。
- Qt → Tauri → Qt 兼容门禁通过。

## ADR 状态门禁

本 ADR 在 Phase 1A 的共享应用锁验证通过后可更新为 `Technically Validated`，在 Phase 3 的 Qt → Tauri → Qt 真实兼容门禁通过后更新为 `Accepted`。停止支持 legacy Qt 或引入不兼容 schema 时，必须以新的 ADR Supersede 本文。
