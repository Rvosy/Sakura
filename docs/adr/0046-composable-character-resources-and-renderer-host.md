# ADR-0046：表现插件负责编辑、控制说明、解析与渲染

## 状态与背景

2026-09-12 接受此决策。完整立绘链路已迁入同一插件，宿主组合公共提示词、解析回复、路由控制并管理播放、窗口
和文件事务。接口与实施证据见[表现插件合同](../specs/runtime-v2/visual-plugin-boundary.md)和
[实施计划](../plans/character-composition.md)。数值插件已验证参数与一次动作链路；真实模型引擎与平台体验另行验收。

迁移前，公共 Profile、提示词、桌宠、工坊和归档均直接依赖默认图片与标签。仅移动图片控制器会保留这些耦合。
[设置 Demo](../../desktop/frontend/prototypes/settings-demo/README.md)和[工坊 Demo](../../desktop/frontend/prototypes/studio-demo/README.md)
用于评审交互，不定义正式资源或控制协议。

不同表现需要各自的控制方式：立绘可以按标签切图，Live2D 可以调整参数和触发动作，3D 可以操作动画、姿态或视线。
选择当前资源与控制该资源分开；工坊能加载自定义编辑器，也不等于模型已经能控制该形态。
首个完整实现仍是立绘，但公共扩展边界必须允许插件定义控制数据，不能等待真实模型接入时才拆除固定选图假设。

## 决策

### 立绘能力覆盖运行、编辑与资源交换

将立绘格式解释、图片校验、控制说明、专属输出格式、解析校验、图片映射、渲染、相关设置、工坊编辑和归档适配
归入同一个插件。提示词与解析是立绘插件的配套能力，不要求用户再安装独立的提示词或解析器插件。
宿主保留角色身份、人设、公共回复解析与路由、聊天与历史、播放调度、窗口、通用路径安全、草稿持久化和发布事务。

公共角色模型只持有资源描述。资源实例 ID、格式 type 与插件 ID 分开，避免同一插件以后只能对应一份资源。
旧格式识别保留在明确的兼容边界；图片业务不继续散落在 Core、通用工坊或通用归档器。
旧包在读取时归一化，不启动即批量搬迁文件，也不激活过去未生效的 renderer 字段。

第一阶段同时只使用一份当前表现资源。完整包保持兼容往返，并支持单独导出立绘组件、导入另一角色的草稿，
以验证资源、编辑和文件边界已完整拆分。通用资源列表已接入；复杂组合策略和多音色留到后续。

### 插件定义控制语义，宿主组合与路由

静态能力入口绑定具体资源后，由插件提供当前资源可用的控制项、规则、参数范围、缺省值和专属输出格式。
宿主将这些贡献组合进提示词，继续管理人格、语言约束、分段和 TTS 语气。普通聊天与主动回复使用相同绑定快照，
插件不能任意覆盖整体系统提示词；资源切换后撤销旧贡献和执行目标。

解析分两层：宿主解析公共回复、有效文字及控制载荷的目标和版本，插件解析专属字段、校验参数并处理回退。
表现解析失败不能丢弃合法文本或阻断语音。公共层不按具体表现类型解释载荷，不把解析扩展等同于执行任意模型代码。

手动情绪标签和“显式选择 → tone 对应图片 → 默认图”属于立绘插件。其他插件可以使用结构化参数、动作或状态，
不必提供图片标签，也不要求服从统一的 `expression/motion` 枚举。插件按实际资源暴露能力，不把某类引擎可能支持的
所有参数都声明为当前角色可用。

旧 `portrait` 继续兼容读取并交给立绘插件解释。ChatSegment、Timeline、IPC 和播放链路需要同步承载插件控制数据，
不能以保持旧字段为由保留唯一选图通道；新旧编码、版本和共存优先级随实现写入 Spec。旧历史不批量重写，
缺少插件仍能查看文本，静态查看不执行控制指令。

### 宿主管理执行时机，插件管理表现行为

宿主路由经过校验的控制数据，按实际播放或静音分段时机派发，并在打断、切换、停用和销毁时撤销旧实例的指令。
合同明确持续状态与一次动作的生命周期；一次动作不因 UI 重绘或事件重复交付而重放，插件负责状态恢复与资源释放。
具体时序、字段及方法签名由表现插件 Spec 定义。持续状态和一次动作分别传递。

语言模型不是唯一控制来源。按实际需要，音频播放和交互事件也可交给插件处理，口型、鼠标跟随、呼吸、物理和插值
可在渲染端持续运行。宿主提供必要事件和边界，插件决定专属参数如何协调，不通过 Python IPC 或模型调用逐帧绘制。

### 复用 v4，增加受管理的前端入口

插件安装包携带现有 Python 注册/适配部分，以及预构建的渲染模块和工坊编辑模块。
静态 manifest 与 Inventory 描述资源类型、服务、控制贡献与解析能力及模块入口，未启用时也可诊断缺少什么能力。
现有 presentation 分类字段保持展示用途，不参与资源匹配；不新增另一套插件管理器或通用运行时。

RendererHost 管理挂载、就绪、控制派发与取消、事件、视口、布局/命中和销毁。现有立绘控制器迁入插件，
保留预加载、过渡和 generation 隔离。公共宿主不按插件 ID 硬编码实现。
预装立绘插件离线可用，但可以按现有规则停用或由兼容插件替代。

原生窗口、拖拽和鼠标穿透机制保留，插件提交经过验证的布局/命中数据。
现有 Rust 图片处理可作为立绘适配使用的宿主工具，不为了目录归属重写成熟平台代码；
公共资源描述不要求任意未来表现都提供图片宽高或 alpha mask。

### 保持数据写入与执行边界

工坊保留资源列表、命名、默认选择、移除和保存流程，按可用插件及编辑能力提供添加入口。
专属编辑区由插件贡献前端模块，可以使用自己的布局、控件与交互；简单配置也可使用声明式表单，
不把固定立绘页面或字段清单作为其他形态的编辑上限。扩展范围是形态编辑区，不是任意接管整个工坊。

沿用 [ADR-0044](0044-character-studio-same-app-window.md) 的 studio 窗口和 Core 唯一写入者。
插件编辑器读写绑定工作区、资源 ID 和草稿修订的区域，发布、目录替换、取消与恢复由宿主完成。
不能让工坊模块直接写已安装角色包。作者资源、个人显示偏好与运行结果分开，现有语音行为本阶段保持。

代码入口来自用户安装的插件，角色包只提供数据。前端模块按可信插件代码处理；同一 WebView 中的模块
不具备 Python worker 的进程隔离，不能宣称为恶意 JavaScript 沙箱。保留 CSP，限制正常桥接接口，
不执行角色资源中的脚本，不依赖运行时 CDN。实例撤销时同时撤销资源授权、回调、订阅和计时器。

## 备选方案与理由

只迁移渲染控制器或只让插件提供标签候选，仍会把提示词规则、解析和控制载荷固定为选图，不能实现完整能力替换。
因此把编辑、控制说明、解析和执行的类型责任一起迁移，底层通用文件事务和成熟窗口机制继续复用。

强制所有插件使用相同情绪或动作词表，仍会限制参数与状态控制。选择公共封装和插件专属语义，先用非标签控制夹具
验证边界，再以真实模型验证引擎和交互差异；不把完整 Live2D/VRM 实现作为当前拆分的前提。

让插件替换整个聊天解析器，会把文字、语言、历史和其他能力绑到某种表现上。选择公共解析与专属解析分层，
使表现扩展独立于有效回复文字，并能兼容旧历史。

让 Python 插件逐帧远程操作 DOM 会增加高频 IPC；另换通用插件框架又会重做已有安装和生命周期。
选择 v4 管理插件、前端模块实际绘制，按已有需求提供小的宿主合同。

将前端编辑器接到角色包的任意脚本入口虽然省事，但混淆数据导入与代码安装，也绕过草稿写入边界。
代码仍通过插件安装，角色资源和草稿通过宿主管理。

## 后果与接受条件

改造跨越角色加载、提示词与回复解析、Chat/Timeline、播放、Core/Rust/WebView 表现协议、工坊与归档。
立绘运行与制作由同一插件负责；同时需要明确控制贡献、载荷版本、错误隔离、模块生命周期和草稿资源接口。
不要求把每段底层图片代码都移出 Rust，但要求公共业务不再直接理解立绘字段或拥有隐藏回退实现。

完成依据是旧包正常运行与编辑、portrait 选图和 TTS 行为保持、插件可停用/替换、工坊草稿可恢复、
立绘组件可跨角色往返，以及受影响平台的真实立绘窗口验收。
停用立绘插件后，公共程序不选图、不要求替代插件提供图片或标签；非标签替代插件需通过编辑贡献、提示词、专属解析、
数值/动作载荷传递、播放执行与撤销的完整链路。只验证挂载或搬迁目录不算完成。
该夹具不能证明 Live2D/3D 可用；真实模型仍需验证资源加载、持续参数控制、动作、播放同步和原生窗口。
缺失插件时保留包和公共编辑入口；未知字段、语音及其他资源不得因普通保存而丢失。

本文记录已采用的职责与接口取舍。前端模块、工坊、控制封装和播放时序均已写入 Spec；平台验收状态由实施计划说明。
当前不取代已接受的插件内核、原生窗口或工坊决策；后续新形态若改变这些取舍，另行记录。
