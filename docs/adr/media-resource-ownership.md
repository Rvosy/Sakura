# ADR：合成、播放、录音与临时资源各有拥有者

## 问题

同一份音频会经过合成、桌面播放、历史保存和远程传输。若其中任一步结束就删除原文件，会破坏历史回放；如果所有模块都保留副本，又容易泄漏资源。截图和麦克风录音也需要在取消后及时失效。

## 当前决定

语音 Provider 管理合成与自己创建的引擎进程；TTS Hub 管理提供方和合成任务。Core 授权历史段落、消费合成产物并保存持久录音，Rust 管理桌面设备和播放副本。

手机等插件取得可释放的音频副本，不枚举 Provider 缓存或接管桌面播放。历史录音、播放副本与跨插件 Artifact 有各自生命周期，释放副本不删除原录音。

截图与采集录音由宿主创建并授权，绑定实际操作和会话。跨进程传资源描述，读取结束或任务失效后由拥有者回收；插件不靠猜测本地目录取得文件。

## 理由

合成完成、播放完成和历史留存是不同业务事实。按资源用途划分所有权，可以保留收藏与回放，同时让取消和退出有明确清理范围。

采集、合成和播放都涉及平台设备或外部进程。复用已有宿主能力能避免插件重复实现设备管理，也避免一个提供方停止时影响其他资源。

## 影响与代价

模块间需要传递角色、历史条目、段落和任务身份。取消不能仅更新界面状态，还必须撤销未消费授权并等待实际写入结束。

有效历史录音可直接回放，无需重新启动引擎；缺失或损坏时才按当前配置合成。后台补齐不能抢占前台请求或反复唤醒休眠引擎。

具体接口与数据归属见[语音](../specs/voice.md)、[屏幕感知](../specs/screen-awareness.md)、[SakuraTTS](../specs/sakuratts.md)及[SDK Artifact](../development/plugin-sdk.md#artifact)。
