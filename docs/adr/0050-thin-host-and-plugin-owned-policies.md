# ADR-0050：薄宿主与插件拥有的默认策略

## 状态

已接受。M1 已删除 Context 用途分类，并将旧可选内容裁剪移到默认消费者；当前合同为 Context schema 2。
M2 在 `f9fde091` 实现的主设置“互动方式”和正常聊天选择入口已按用户要求撤回；底层执行合同、进程绑定、取消及
“专注陪伴”开发样例保留。正常聊天使用默认 Assistant，旧 `chat_executor` 被忽略，`settings.executor` 端点移除。
M3/M4 是尚未实施的长期方向，不自动进入下一轮产品改造；默认能力拆分和界面等待真实需求与用户方案明确。
这次调整保留薄宿主目标，撤回的是预设的产品入口。范围见[开放插件生态总计划](../plans/runtime-v2/open-plugin-ecosystem.md)。

## 背景

记忆、TTS 与表现形式已拆为普通插件；TTS 与表现已有不同实现，记忆替换仍需第二实现验证。
这些能力说明 Sakura 具备可继续使用的插件底座。
作出这一决策时，聊天在宿主初始化中直接创建模型客户端、AgentRuntime 和 ChatPipeline；上下文选择与提示词组织也固定在这条链内。
只继续增加贡献字段和 Hook，会让业务实现能够参与聊天，却仍难以替换负责执行聊天的实现。
M2 曾通过设置选择器验证替换，但用户没有认可这套产品呈现；框架有执行能力，不意味着主设置应增加一个模式。

Context 初版按规则和资料分类，并由宿主决定分区与部分预算行为。2026-09-14 的讨论明确要求：
插件自行组织内容，宿主不解释角色卡、记忆或活动关系。当前角色信息和附加扮演提示可以共存，
不需要宿主检测冲突或自动切换默认角色贡献。

## 决策与实施范围

沿用现有 API v4 和独立插件运行机制。宿主负责服务连接、身份、生命周期、受理、取消、资源及公开结果提交；
插件负责领域状态、内容和执行策略。传输大小边界保护运行；模型窗口中的选择、裁剪与排序由对话实现负责。

正常聊天继续使用现有默认 Assistant、模型和工具。`f9fde091` 的选择器与对应配置端点撤回，
不平移成隐藏配置、插件开关或 Agent 模式。已有角色、模型、插件开关和上下文文本不因这次调整自动改写。
日常验收复用已有数据，检查默认对话与插件自身的“对话规则”设置。
现阶段不新增或改造主设置，插件自己的配置优先使用已有插件设置入口。
不同插件的复杂呈现等待实际需求与用户方案明确，不由框架预定统一模式或页面。

底层执行服务和 `PluginExecutor` 保留给开发消费者，专注样例不再通过聊天框可选。
模型适配器和默认对话的进一步迁移仍可作为未来方案，但须有真实需求和明确的用户方案；
届时通过真实调用链证明默认与第三方的公共接口对等，不能仅凭目录或包装类声称完成。

执行器加载、服务登记和业务就绪分别表达；宿主受理前固定操作、会话和实际进程实例，后台工作显式携带这份关联。
`caller_id` 只属于当前 RPC，保存其字符串不代表持续授权。调用超时不等于工作已停止；取消必须传到实际任务，
重复受理不重复启动，重复读取终态不重复提交历史或触发播放。在途操作保留原绑定，
失效实例的结果不得由同 ID 新进程接续提交。当前 `describe/begin/read/cancel` 合同见
[Plugin Runtime v4 §6.5](../specs/runtime-v2/sakura-plugin-runtime-v4.md#65-可替换互动执行器)。
沿用现有操作及提交保护，不新增持久任务平台。这份合同支持文字及可选事件，截图输入未开放；
它不定义产品入口。公共工具消费与默认对话工具选择保留在 M4 的长期设想中，当前未实施。

若未来拆分默认对话，其实现内部应拥有 Agent 循环、上下文组织、预算、复用、工具选择及模型回复解析。
Context 贡献只提供内容与必要的调用信息，不设规则/资料等宿主语义类别，也不创建必装的上下文管理插件。
既有范围、完整性和失败字段作为默认消费者的约定过渡，执行机制随默认对话迁出。
M1 已把旧 16 条可选片段/8192 字符限制及截断移到默认消费者；必需内容完整保留，只受模型预算约束。
Host 保留身份与传输检查，传输超限明确拒绝。`describe()` 返回 schema 2，不再公布旧 `fragmentKinds`；
旧 `kind` 返回 `CONTEXT_SCHEMA_INCOMPATIBLE`，不按可选失败忽略。默认消费者代码此时仍在现有进程内。

若 M3 进入实施，模型槽应支持中立的模型能力引用和调用路径，不要求提供者还原为 HTTP URL 与 Key。
旧 `resolve()` 保留原字段及 HTTP 语义，对无法表达的提供者明确报不兼容；主聊天与至少一个现有辅助消费者
通过新路径使用同一非 HTTP 提供者，验证选择与继承。原配置仍由默认适配器解释。

未来模型迁移所需的公共 Trace 桥应复用现有宿主记录器、存储和脱敏规则；默认对话迁移时补齐上下文选择与处理信息。
实际传输者记录请求及响应，执行器关联同一模型调用；后台辅助调用也有明确归属。默认与第三方使用同一入口，
不导入 `app.*`，不将正文塞入普通日志，不新增跟踪数据库；记录失败不改变产品结果。

若 M4 进入实施，还需证明默认对话可被小插件增强：保留默认实现、模型与工具，上下文增强和输出转换通过少量公共入口一起生效，
移除任一插件后其余功能仍可使用。第三方不必复制默认对话实现，宿主无需建设中央 Hook 平台。

记忆可以通过多种贡献并存，TTS 保留适合多引擎的 Hub/Provider，表现保留资源与渲染器合同。
不同能力的组合由提供者和消费者定义。普通插件可以公开自己的扩展服务；Runtime 不维护所有业务类别。

### 默认 Assistant 与未来插件场景

默认形态保持使用受限工具集的桌面 Assistant。未来 Agent 只是可能的插件场景，本决策不预定 Agent 模式或选择流程。
安装、启用或公开服务不自动扩大默认 Assistant 的模型工具集合，也不接管聊天。
规划、任务、命令、工具选择和业务授权由 Agent 或配套插件实现，框架只提供通用连接和运行机制。
受保护操作的检查由实际能力入口落实；只隐藏工具或插件自报 `risk/capability` 不构成授权。

执行合同支持有界进度、结果与取消；插件停用或实例失效后，旧绑定不能重新取得提交资格。
取消传递到插件实际任务与子进程回收，不等于回滚已发生的外部效果。M2 已使用无副作用的专注插件和真实进程回归
验证执行器接入、进度、取消与生命周期；这些证据作为开发基础保留，不证明选择入口应继续存在。
不同工具选择的公共调用验证属于未来方案。Agent 尚未实现，
不提前建设通用权限、任务恢复或逐条工具审批平台。实际 Agent 授权与撤销设计遵循
[ADR-0031](0031-retire-runtime-v2-tool-confirmation.md)，不恢复已删除的确认协议。

当前 Python 插件继承当前用户系统权限，`permissions` 是遗留元数据，独立进程不提供 OS 沙箱。
工具选择是消费插件的产品行为，operation 身份不自动授予操作权限；若未来要求强制限制任意插件的系统访问，需单独选择并验证隔离环境。
不以提高整个宿主的系统权限作为 Assistant 升级为 Agent 的默认做法。

复杂插件可以内部拆分模块、调用其他插件或管理子进程，宿主不要求把这些内部结构登记成自己的业务类别。
只有实际运行、通信、资源或界面接入出现缺口时才增加基础机制，复杂功能本身不成为扩大宿主职责的理由。

## 未采用的方向

- 继续以业务专用 Hook 和宿主语义分类为主线：宿主会不断承担插件的内容与策略判断。
- 只把实现文件搬到插件目录：真实调用者若仍依赖具体类、私有属性或备用实现，可替换性没有成立。
- 每个模块都立即拆成进程或通用服务：增加调用和维护成本，缺少当前消费者。
- 重建插件内核、中央扩展点系统或自愈调度平台：已有底座能够承载主要工作，这些机制不是当前阻塞点。

## 后果与既有决策

这一方向继续落实 [ADR-0037](0037-replaceable-default-plugins-and-isolated-python-runtimes.md) 的官方与第三方对等原则，
并保留 [ADR-0033](0033-host-typed-timeline-and-lightweight-context-building.md) 的 Timeline 所有权与数据保护。
当前历史和输出路径继续共用，不为追求目录形式而立即重写存储。

对 ADR-0033 的替代只涉及其“Host 组装最终 Prompt”及上下文投影、选择、预算和排序的宿主策略职责。
M4 默认对话插件接管真实调用链并通过验收后，这些策略才归默认对话实现；M2 的入口包装不构成迁移完成。
Timeline 唯一写入者、真实来源、完整 generation、资源不入库、Memory 独立消费及旧数据保护继续有效，
`human/observation/system` 的 Timeline 来源语义也保留，不与 Context 用途分类一并删除。
届时在 ADR-0033 相应位置增加窄范围后继说明，并在
[WP-4-07R](../specs/runtime-v2/WP-4-07R-typed-timeline-adaptive-context.md) 区分宿主数据约束、默认对话策略与 Memory 行为。
本决策不提前改写这些当前契约，也不整份归档 ADR-0033。

M1 已替代 [ADR-0049](0049-unified-context-instructions.md) 中用途分类、分区渲染及 Host 内容裁剪政策的部分。
身份、取消和必要的失败归因继续保留；因此 ADR-0049 保留为部分仍有效的历史决策，并标明被替代范围。
Spec、SDK、能力说明、示例及回归按 schema 2 同步调整。M2 的产品入口已经撤回；保留底层合同也不代表模型和默认对话策略已经迁出。

能力替换不等于自动迁移不同插件的私有数据库或配置；需要继承数据时提供显式转换。
模型、Agent 和界面跨进程接入需要真实链路验证，包装类和接口定义本身不算完成。
