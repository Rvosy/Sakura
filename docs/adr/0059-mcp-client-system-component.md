# ADR-0059：MCP 客户端作为可复用系统组件

## 背景

用户需要供后续插件复用的 MCP 支持能力。各服务插件应能注册服务器并使用其功能，基础组件本身不做管理平台。
旧 Core Bridge 已按用户要求清理。重新在 Core 加协议分支会绑定 SDK 与应用生命周期；
各插件自行实现客户端又会重复依赖、认证与回收工作。

## 决策

新增内置基础组件 sakura.mcp，复用 Plugin Runtime v4，官方 Python SDK 负责协议与传输，依赖私有分发。
参考 VS Code 的配置/连接实例分离、Cherry Studio 的生命周期管理，不复制其实现代码。

基础组件只提供 Service：没有设置页、导入、持久服务器列表或 Assistant 工具贡献。
消费插件持有配置，决定业务接口、模型工具、授权及交互界面，并调用组件注册所需服务器。

公共接口使用调用者 scope 下的连接和操作句柄。长操作不占用同步 IPC，结果可分段读取，
未知方法保留 SDK 原始请求入口。Runtime 只传递通用调用 scope 与关闭事件，不维护 MCP 名单。
OAuth 协议由 SDK 处理，授权 URL 通过事件交给消费插件，组件不自行打开浏览器。

## 后果

后续服务插件可复用同一套协议、认证与进程回收能力，不必携带 SDK 或服从统一管理界面。
协议升级集中在一个组件内验证。默认无连接，不恢复旧记录，不内置具体服务。

业务插件需要处理目录分页、操作查询和用户交互。图片、音频及扩展结果保留原结构，
由消费插件决定如何呈现。专用认证扩展需有明确消费者后再增加公共接口。
当前合同和验证边界见 [MCP 组件 Spec](../specs/runtime-v2/mcp-system-component.md)。
