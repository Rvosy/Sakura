# ADR：配置归属与设置页面分开

## 问题

插件化改变配置的管理者，但不应迫使用户在多个窗口重复编辑同一字段，也不应让连接测试、状态刷新或取消弹窗顺便保存其他输入。

## 当前决定

配置由实际使用它的模块或插件拥有；宿主管理页面框架、导航、公共组件和窗口草稿。功能设置按用户工作流放在功能页，运行环境与维护动作放在对应插件设置，安装和启停留在插件管理中。

插件通过现有设置贡献接口放置区块、注册页面或提供受管理模块。区块只有一个主要编辑位置，移动页面不产生第二套配置或保存回调。模块来源于已安装插件，生命周期由宿主管理。

普通字段的“完成”接受弹窗草稿，外层“应用”才保存；测试连接和发现模型使用草稿。下载、诊断和记录增删按动作本身立即执行，取消设置不撤销已经发生的动作。

## 理由

页面组织与数据归属是两件事。分开它们可以在开放插件能力时维持一致的导航和保存体验，也让多个提供方共用现有模型选择、资源状态等组件。

一个主要编辑入口和局部写入，减少同一数据在多个窗口互相覆盖的机会。

## 影响与代价

插件需要声明自己的区块、作用域和可放置区域，不能任意接管其他插件页面。自定义前端模块有更大表现空间，但必须沿用宿主草稿、取消和销毁接口。

部分保存和应用失败需要逐项反馈真实结果。刷新只读状态不覆盖编辑内容；角色或插件实例变化后，旧操作不能回写新页面。
