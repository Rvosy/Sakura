# ADR-0047：联网搜索与网页抓取由内置插件提供

## 状态

决策已接受，尚未实施。本次只确定能力归属、兼容边界和验收要求，不表示当前安装包已经提供联网插件。
现行 MCP 和 Plugin API v4 Spec 继续描述已实现行为，实施时同步更新相关契约与用户文档。

## 背景

当前网页搜索和网页抓取实现在 `app/agent/mcp/web_search_server.py`，经本地 MCP Server 注册为
`web__web_search` 与 `web__fetch_url`。Assistant 的工具路由仍引用这两个名字。

当前 MCP Spec 明确规定不内置、不发行 MCP Server，缺少 `user_root/config/mcp.yaml` 时禁用 MCP。
首次安装的 `ensure_user_layout` 只初始化插件配置和目录；`ensure_default_configs` 虽保留默认 Web
MCP 配置生成代码，但没有生产调用点。因此，不能将缺配置简单归因为启动函数漏调：联网工具的既有实现、
路由提示与当前分发边界已经脱节。

旧版导入会写入 MCP 配置。源配置缺失时生成 `enabled: false` 和空服务器列表；有效的旧 Web 配置会保留并
转换脚本路径。文件存在并不代表联网可用。已持久化的禁用空配置也没有足够信息区分自动生成与用户主动关闭。

公开网页搜索和读取是面向普通用户的能力。它们需要与其他内置插件一样具有明确的默认启停、故障状态和设置入口，
不应要求用户配置 MCP 才能使用。

## 决策

### 能力与运行边界

随安装包提供“联网”插件，负责公开网页搜索和网页抓取。复用现有搜索、正文抽取及网络访问约束，
通过 Plugin API v4 的工具贡献入口注册到 Assistant，使用既有插件 Worker、配置和生命周期机制。
插件代码与依赖归插件所有，不通过导入 `app.*` 私有实现继续依赖 Core。

目标调用链为 `Assistant → 插件工具贡献 → 联网插件 Worker → 搜索或抓取`。移除内置 Web 专用的 MCP
协议适配和额外 Server 启动路径；插件 Worker 的隔离、取消和退出回收仍然保留。

通用 MCP 客户端继续接入用户配置的外部工具。没有 MCP 配置、MCP 被关闭或某个外部 Server 失败，都不影响
联网插件。MCP 状态只说明外部工具接入状态；联网插件状态单独显示，未配置 MCP 不应被呈现为整个联网能力故障。

浏览器操作继续属于浏览器插件。本次不加入浏览器自动化、多搜索 Provider 框架、自动故障切换或新的插件平台。

### 工具兼容与可用性

保留 `web__web_search`、`web__fetch_url` 的模型可见名称，以及现有参数和结果语义，减少路由与调用方变化。
这两个工具的运行来源改为插件，日志和可用工具列表必须反映实际来源；关闭或失败后不得仍向模型声明可用。
实施时核对现有工具贡献入口的命名和冲突规则，只做承接所需的最小调整，不引入全局别名注册平台。

迁移后的内置 Web MCP 与联网插件不得重复注册同名工具。无法确认来源的自定义 MCP 工具继续保留，发生冲突时
明确报告冲突并由用户选择，不静默覆盖。旧调用记录继续可读，不重写历史工具来源。

网络超时、响应大小限制、公开 HTTP/HTTPS 地址约束、重定向目标检查与结果截断继续适用。
工具已注册只代表可调用，不能据此宣称公网可达；请求失败应返回具体失败状态，不伪装为空搜索结果。

### 安装、升级与旧版导入

新安装默认启用联网插件，并随发行包准备所需依赖。普通启动不静默安装依赖；依赖缺失明确归因到联网插件，
恢复沿用现有安装或显式重试入口。

已有联网插件启停设置具有最高优先级，后续升级与旧版导入不得覆盖。尚无插件设置时按以下规则初始化：

| 可用的旧状态 | 联网插件初始状态 |
|---|---|
| 新安装，或既有用户根中没有 MCP 配置 | 默认启用 |
| 本次旧版导入的源 MCP 配置不存在 | 默认启用，不再先生成禁用空配置丢失来源信息 |
| 能识别为旧内置 Web 服务，且 MCP 总开关与服务开关均启用 | 启用，保留可表达的工具限制 |
| MCP 总开关关闭，或旧内置 Web 服务明确关闭 | 关闭 |
| 已持久化的禁用空配置，来源无法辨认 | 保留关闭，用户可在插件页启用 |
| 只有自定义外部 MCP 服务、没有旧内置 Web 项 | 总开关关闭时保守保持联网插件关闭；否则默认启用 |
| 配置损坏，或旧内置 Web 有无法承接的自定义行为 | 保留原配置，明确提示处理，不自动激活替代实现 |

只有确认属于旧内置 Web 实现的项才参与迁移，不能仅凭服务器名 `web` 判断。自定义服务、凭据和其他 MCP
开关保持原样。旧 Web 项的工具白名单、黑名单及其他有效限制不得在迁移中悄悄丢失；无法等价承接时保留配置并报告。

插件设置成功持久化且旧内置项停用后，才将工具交给插件注册。迁移必须可重复执行，失败时不删除原配置，
也不让两套实现同时接管工具。只沿用现有配置写入和导入事务，不增加内容摘要、后台调和或自动重试机制。

## 候选方案与理由

| 方案 | 判断 |
|---|---|
| 恢复默认 Web MCP 配置生成 | 能恢复部分用户的工具，但仍保留两套启停和状态入口，也不能解决已有禁用空配置的意图区分 |
| 将搜索与抓取直接注册成 Core 内置工具 | 调用链短，但把可替换的联网领域实现和依赖留在 Core |
| 使用内置联网插件 | 采用；符合现有官方功能插件化方向，统一用户入口，并复用现有进程与工具生命周期 |

本决策延续 ADR-0037 的官方插件边界，不替代通用 MCP 的生命周期决策。具体搜索引擎选择不在本次范围内。

## 后果与实施验收

联网不再依赖 MCP 配置，维护者可以删除退役的内置 Web Server 适配、默认配置生产者及其专用测试。
通用 MCP parser、Bridge、外部 Server 状态和对应测试继续保留。插件化本身不保证网站可达或搜索结果质量。

实施需要同时接好分发、插件启停、迁移和工具路由，不能只搬动搜索文件。主要验收覆盖：

- 从隔离的空用户根启动真实初始化链，联网插件可用，不要求存在 MCP 配置；关闭后工具从可用列表撤回。
- 按上表验证升级与旧版导入，证明显式关闭、工具限制、自定义 MCP 配置和重复迁移都得到保留。
- 通过真实插件工具调用链验证中文搜索、网页抓取、截断、超时和非公开目标拒绝；外部 MCP 失败不影响插件。
- 验证停用、Worker 退出和应用关闭后撤销工具及回收调用；同名外部工具冲突不覆盖任何一方。
- 使用发行环境检查插件依赖与设置页状态。公网搜索人工验证单独记录，离线测试不能代替真实联网验收。
