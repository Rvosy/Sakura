# ADR-0048：以原始错误证据为遥测主体

## 背景

生产遥测能给出错误码和影响范围，却经常没有足够信息提出修复建议。同一个迁移错误码可能对应缺表或主键冲突；路径压成 basename 后，也无法区分主程序和插件 Runtime。main 加强了本地异常诊断，但遥测 DTO、服务端校验和导出器继续丢弃这些证据。

## 决策

- 扩展现有诊断链路，v3 错误报告保留原始消息、异常链、栈和有关上下文；代码与统计用于索引。
- 凭据按具体值处理，保留诊断路径、URL 和模型名。取消“原始异常只能留本地”的旧约束。
- 保留 Rust 单出站、FastAPI/SQLite 和现有管理端，v2 事件及模型指标不升级为任意正文载荷。
- 错误报告使用有容量和期限上限的磁盘待发区，以 reportId 幂等补发；关闭和重置 ID 清理待发报告。
- 分组比较实际字段，首份样本的关联 ID 随机生成，不计算自制内容摘要。分组不能遮盖不同底层错误。

本文替代 ADR-0043 中关于“客户端不落盘、不重试、无错误原文”的约束；ADR-0043 的部署、鉴权和数据面隔离决策继续有效。

## 取舍

Sentry 和 Bugsnag 的共同做法是保留异常 message、类型、链和栈。采用这一信息结构，并不要求现在迁移整套服务。源头已经丢失的信息无法靠换服务器恢复，因此先贯通已有采集和导出。需要成熟的 issue 管理、发布回归或符号处理时，再评估 Sentry，避免自行复刻整个产品。

报告比旧版大，也会包含实际路径和原始错误片段。设置说明必须准确，具体字段、长度限制、待发上限和兼容行为由 [Spec](../specs/runtime-v2/remote-diagnostics-telemetry.md) 定义。旧数据已经丢失的原文无法补回。
