# ADR：程序更新与用户数据分开管理

## 问题

安装包可以替换程序，但用户会持续积累角色、聊天、记忆、模型和插件配置。旧版导入和插件迁出也可能遇到同名目录、不同平台资源和已经编辑过的数据，不能用清空目录或重新安装解决冲突。

## 当前决定

程序根和用户根按归属划分，即使 Windows 将两者放在同一物理目录，也由安装和更新清单区分。更新只替换程序域，保留用户域及显式偏好。

插件代码与依赖成对准备和切换，私有数据独立保存。旧内置插件迁出与发行配套更新使用离线材料，失败保留旧目录和恢复入口；未安装的可选插件不会因此被主动安装。

旧数据目录由用户明确选择后只读检查，导入保留目标独有内容。同一身份冲突按本次选择处理，通过事务保护已有目标；普通启动不扫描其他目录执行导入。

## 理由

文件属于谁决定它能否被替换，不能仅凭目录里出现某个名称推断可删除。分离程序和用户数据也让安装版、Portable 与跨平台路径共享同一保留原则。

先准备再切换，可以在取消和失败时保持已有安装可用。离线材料使已有用户的兼容处理不依赖启动时临时下载和解析依赖。

## 影响与代价

发行需要维护平台依赖和必要迁移材料，并验证旧用户的数据往返。移除兼容材料时需要明确调整支持范围，不能把缺少材料解释成用户需要删除数据。

事务恢复可能暂时阻止使用处于混合状态的数据，但非关键旧文件清理失败不阻断其他功能。原始失败与恢复失败分别保留，不能把恢复开始当作恢复成功。
