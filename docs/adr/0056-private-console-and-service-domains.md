# ADR-0056：统一服务域名与独立私人控制台

## 背景

维护者需要在现有故障后台管理版本清单，后续还会分发插件、角色卡与角色形态。当前只有一个管理员，
杭州服务器带宽为 3 Mbps；近期先改善国内更新检测，文件下载仍在 GitHub。

## 决策

本决策 supersedes [ADR-0055](0055-domestic-updater-manifest.md) 的新客户端清单域名，以及
[ADR-0041](0041-static-sakura-service-control-plane.md) 将管理操作限定为 CI 推送的部分。
保留公开清单静态读取、受限 CI 发布通道、本地功能独立与现有安装包验签合同。

采用 `sakura.cialloo.cn` 产品域下的短名称：`adm` 为私人控制台，`api` 为客户端接口，`hub` 为后续公开工坊，
`dl` 为后续对象存储/CDN。只启用已有消费者所需的 adm 与 api；产品站与旧客户端入口继续保留。

服务源码集中到 `services/sakura/`。FastAPI 接收端和私人控制台分别运行，使用不同系统身份与监听端口。
控制台以只读权限查询故障库；发布草稿和操作记录使用独立 SQLite。延用现有 Nginx Basic Auth，
不在个人维护阶段增加账号系统、消息队列或分布式数据库。

版本由 CI 自动推送或维护者从固定 GitHub Release 导入、核对、发布。两条路径共用发布锁与字段校验器，
公开请求始终读取本地快照，不在客户端检测时请求 GitHub。无需额外索引仓库作为另一份线上状态来源。

## 后续资源分发

工坊开放后，资源资料、版本、审核与上下架状态由服务器数据库维护；已审核快照供公开查询。
第三方提交自己的仓库和版本，由维护者审核。源代码仓库保留开发历史，可安装文件以固定版本归档包交付。
对象存储保存版本文件，国内 CDN 通过 dl 域名分发；3 Mbps 服务器只承担管理和元数据请求。
资源发布先确认文件可用，再公开对应版本。不得把用户提交的仓库代码直接运行在管理服务器。

此处确定演进方向，不表示已实现第三方投稿、插件目录、云存储接入、下载统计或公开工坊。

## 取舍与迁移

保留旧域名增加少量 Nginx 配置，但无需依赖用户立即升级。遥测 POST 通过源站转发保持协议，不能改成跳转。
新清单域名先上线，再进入后续客户端发行配置；现有安装包不会因服务端迁移自动改变检测地址。

后台发布记录只包含后台操作；CI 记录由 Actions 保留，实际线上文件状态统一在控制台展示。
两个公开 JSON 分别原子替换，失败后通过同版本修复，不额外建立事务或自愈平台。

合同见 [Sakura Service](../specs/runtime-v2/sakura-service.md)，实施与回退见
[运维与发布](../devdocs/SAKURA_SERVICE.md)。
