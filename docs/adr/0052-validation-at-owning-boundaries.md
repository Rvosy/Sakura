# ADR-0052：由实际消费者负责解析，删除重复业务校验

## 背景

角色表情数、配置容量和资源大小在插件、Core、Rust、前端分别限制。正常角色包通过导入后仍会在加载或保存时失败；放宽单个数字不能解决后续拦截。

## 决策

外部配置由所属服务解析，插件格式由插件解释。内部调用直接消费已解析的数据，不再要求字段集合完全相同，不重复序列化验证。可变状态需要隔离时使用普通复制。

移除角色、表情、表现资产、动画、皮肤、Provider 和模型列表等业务数量上限，以及显示名称、配置、导入文件的任意长度或容量门槛。归档和工作室仍使用原有事务、取消、路径授权和失败清理，不修改原始包或用户数据格式。

Core 负责资源绑定和生命周期，Rust 负责授权访问及原生能力，前端负责展示和交互。各层保留自己实际需要的字段访问、路由身份和过期结果检查，不维护同一份数据的完整校验副本。插件控制只投影 state/actions，绑定身份由宿主写入。

RPC 在入队时编码一次，编码后的字节不会被调用方后续修改。保留插件 1 MiB、Core 8 MiB 通信帧预算、解码内存预算、并发容量和真实 GPU 能力约束。移除业务门槛不表示无限资源承诺。格式解析、文件读写或服务调用失败时保留原始原因和稳定错误码。

凭据由配置服务保管并生成公开投影；不依赖前端扫描字段名称来避免泄漏。签名验证、路径越界保护、进程回收、取消与代际隔离保持独立，不因简化业务逻辑而删除。

## 影响与验证

不更名接口、不迁移持久化字段、不要求重装资源。内部响应允许增加字段；外部写入只执行已声明的字段及操作。

测试通过真实插件、工作室发布、资源授权和持久化往返验证行为。删除只用于重复检查内部字段或旧任意阈值的测试；保留坏资源、越界、通信超限、原子失败、凭据不泄漏和进程回收证据。

协议详见[表现插件边界](../specs/runtime-v2/visual-plugin-boundary.md)和[Plugin API v4](../specs/runtime-v2/sakura-plugin-runtime-v4.md)。
