# ADR：角色由可组合资源构成，格式由插件解释

## 问题

立绘、骨骼动画和语音模型拥有不同的控制与编辑方式。公共角色模型如果固定为图片标签，扩展一种表现就需要同时改写聊天、工坊、归档和桌面窗口。分享角色时也不能把作者的设备或语音开关强加给接收者。

## 当前决定

角色包保存可分享的人设、主题和资源。资源实例 ID、格式类型与提供插件 ID 分开；本机当前显示方式、语音启用和引擎选择保存在应用配置中。

表现插件负责自己的格式解析、控制说明、控制解析、渲染与编辑。公共宿主管理角色身份、文字回复、执行时机、窗口能力、草稿和文件事务。角色包是数据，代码只能来自已安装插件。

工坊通过绑定的草稿编辑资源，宿主负责发布。保存只改本次编辑拥有的字段，未知扩展和其他插件资源继续保留；缺少插件时仍可处理角色公共信息和文字。

## 理由

把一种资源的读取、编辑和执行责任放在同一插件，才能真正替换表现能力。仅开放渲染器仍会把编辑和控制语义固定在公共层。

资源数据和本机偏好分开后，导入导出可以保持角色内容完整，同时尊重每台设备的能力与用户选择。

## 影响与代价

插件必须提供与自身资源匹配的编辑和控制接口，不能只声明理想能力。宿主只理解公共封装，表现解析失败时保留有效文字，不替插件猜测私有字段。

持续状态与一次动作需要分开：历史翻阅恢复已经展示过的状态，不重播声音或动作。角色和形态切换撤销旧绑定，迟到结果不能控制新资源。
