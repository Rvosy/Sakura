# ADR：聊天受理由 Core 统一，生成策略由 Assistant 提供

## 问题

桌面输入、手机输入和主动互动需要共享当前角色、取消和历史。若每个入口各自维护聊天状态，同一回复可能重复提交，取消可能落在尚未建立的任务之前，插件替换也容易绕开已有数据规则。

## 当前决定

Core 的唯一聊天入口负责受理、固定角色与操作身份、取消仲裁、Timeline 写入和最终完成状态。不同输入入口只解析自身输入，再进入同一用例。

Assistant 是可替换的普通插件服务，负责上下文选择、模型和工具循环、回复格式及 Agent Trace。Core 提供会话、历史页、工具、Context 和资源能力，不保留失败时偷偷接管的备用 Agent。

模型服务独立提供连接和请求。一次操作固定配置与服务实例；任务由 begin、poll、result、cancel、release 协作，输入和结果较大时使用宿主管理的 Artifact。

## 理由

受理和最终写入需要一个裁决者，才能明确取消与完成谁先发生、哪份结果能够保存。生成策略属于可替换能力，不应把模型实现或默认 Prompt 固定进宿主。

共享入口也让手机聊天、桌面字幕和历史指向同一条事实，而不是为不同界面建立独立对话副本。

## 影响与代价

替换 Assistant 必须遵守相同的会话和任务契约。服务实例失效后，旧结果不能冒充新实例输出；请求结果未知时不自动重放，用户可以明确重试。

Core 保存正文不等待可选表现解析和语音。桌面播放仍按段落同步字幕、音频和表现，两者是不同完成点。语音或表现故障不应抹掉已保存的有效文字。
