# ADR：桌宠使用稳定锚点与原生命中能力

## 问题

桌宠的可见区域、透明区域和可交互控件并不重合。仅用网页样式关闭鼠标事件不能把点击交给其他应用；内容变化若直接推动窗口位置，也会让缩放、换表情和长回复使角色漂移。

## 当前决定

布局以角色稳定锚点为基准。表现资源提供可见范围与命中信息，前端负责控件和布局，原生窗口负责系统层命中、定位和材质。

可见范围、窗口包围范围与鼠标命中分别处理。文字选择、输入框、菜单和按钮保留交互，透明区域按平台能力穿透。布局与表现更新绑定当前对象，旧几何结果不能覆盖新状态。

Windows、macOS 使用对应原生能力。Linux 按当前窗口系统提供可实现的定位和命中范围，准确说明限制。材质不可用时保持可操作的基础显示与用户偏好。

## 理由

锚点表达用户放置角色的位置，内容大小表达本轮显示需求，二者分开才能在多屏和不同缩放下保持稳定。原生系统决定跨窗口输入行为，WebView 不能替代这层责任。

平台适配放在宿主，表现插件只提交它实际拥有的资源信息，避免每个插件重复实现窗口和设备逻辑。

## 影响与代价

各平台实现不同，截图和浏览器模拟不能证明系统穿透、DPI 和真实材质正确。相关修改需在对应环境验证。

几何更新要兼顾过渡画面和控件范围，不能为了收缩窗口裁掉正在显示的内容。平台缺少能力时应保留明确的可用行为，而不是伪装完全一致。
