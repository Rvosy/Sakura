# ADR-0052：统一 Context 支持行为规则与参考资料


本文保存旧生态分支的讨论。当前整合取舍见 [ADR-0054](../../adr/0054-retire-executor-experiment-and-scope-collections.md)，以下已撤回方案不作为当前合同。

## 状态

已接受，部分由 [ADR-0053](0053-thin-host-and-plugin-owned-policies.md) 在 M1 替代：用途分类、信任派生、
分区渲染和 Host 执行内容裁剪不再适用。统一贡献入口、真实来源、取消和失败归因继续有效；活动互动内复用、
排序与完整性保留为默认对话实现的消费约定。本文保留初版理由，不作为已替代部分的当前合同。
当前合同见
[Runtime v4 §6.4](../../specs/runtime-v2/sakura-plugin-runtime-v4.md#64-context-行为贡献)。

## 背景

已有 Context 插件可以检索资料，但 Host 与组装器会强制把片段归为可选、不可信事实，渲染也要求模型只当事实使用。
教学、写作风格和角色活动插件无法通过公开接口表达行为规则；仅在返回值中增加字段无法打通实际模型请求。

一个规则可能影响包含工具调用、最终总结和格式修复的整次互动。逐步读取正在更新的插件配置，会让同一次回复使用
不同规则。可选资料的静默截断和失败跳过，也不适合必须完整提供的规则。

## 初版决策

扩展已有 `sakura.host.context`，以 `kind` 区分 `instruction/data`，以 `required` 表达片段必须完整进入上下文。
规则和资料分别渲染，来源由 Host 调用身份决定；插件不能通过返回值冒充宿主或其他插件。用途不等于代码权限，
外部资料不会因插件已启用而自动升级为规则。行为规则仍遵守宿主执行边界和公共回复格式。

注册级 `scope: turn` 在活动互动内缓存整个回调结果；`step` 保留原动态检索方式。本轮固定贡献者集合和顺序，
已采集的结果持续到互动结束。注册级 `failurePolicy` 表达回调失败时跳过还是终止，避免只能从尚未返回的片段
判断贡献是否必需。取消始终传播。必需片段放不下时报错，可选规则整条选择或丢弃，可选资料保留原预算行为。

用 `describe()` 公开这组能力，行为插件缺少所需能力时明确停止启用。继续使用 API v4，不为单个扩展建立通用版本
协商框架。示例插件“对话规则”只调用公开 SDK，设置和启停使用现有插件界面，不加入业务名称分支。

不采用教学、Cosplay 等各自专用的行为入口，也不允许插件替换整份宿主 Prompt。这样可继续组合多个贡献者，
并保留格式、工具执行和来源边界。

## 后果与边界

旧插件缺少新字段时仍贡献可选资料；同一插件的多个 Provider 继续分别使用原有额度。新增规则能够进入真实模型请求，
失败可定位到贡献插件，但模型对自然语言规则的遵从程度仍需实际体验评估。

本轮缓存是活动调用的局部状态，不是历史缓存或新的上下文运行时。
[ADR-0033](../../adr/0033-host-typed-timeline-and-lightweight-context-building.md) 的 Timeline 所有权和无状态历史投影继续适用；
[ADR-0037](../../adr/0037-replaceable-default-plugins-and-isolated-python-runtimes.md) 的独立插件进程和 SDK 边界继续适用。
本决策扩展 Context 的用途，不取代这两份 ADR 的整体决策。

输入输出转换、历史扩展字段、记忆筛选、跨插件广播、模型与执行器替换及通用插件窗口仍属于后续阶段，
不能从本次 Context 支持推定为已开放。
