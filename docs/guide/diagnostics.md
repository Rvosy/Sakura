# 运行日志与故障排查

从桌宠右键菜单或托盘打开运行日志，也可以到用户数据目录的 `data/logs/` 查看文件。

| 文件 | 内容 |
|---|---|
| `sakura-runtime.log` | 启动、窗口、聊天、模型、工具和插件安装加载等宿主事件 |
| `sakura-plugins.log` | 插件主动接入的业务过程与错误，可在窗口按插件筛选 |
| `sakura-agent-trace.log` | 最终模型输入、上下文、工具调用和回复，含私密正文 |

运行日志按步骤记录处理对象、阶段、结果和必要耗时。长操作先记录开始，完成后记录真实结果；例如依赖下载安装完成不代表整个插件安装成功。轮询和内部同步只在需要时进入 debug。

## 定位问题

1. 记下出现问题的时间和操作，找到对应对象最后完成或失败的步骤。
2. 按同一 `op` 关联查看，模型请求还可通过 `trace`、`call` 找到调用记录。
3. 展开原始报错、异常原因链和子进程输出，按具体原因修复配置或资源后重试。
4. 需要分析模型行为时查看 Agent Trace；不希望保留正文时，可在系统设置关闭。

插件普通输出不会自动进入插件日志，因此没有业务日志不代表插件未运行。安装、依赖和进程错误应查看宿主日志。

运行与插件日志约 10 MiB 轮转，各保留 5 份旧文件。Agent Trace 按完整操作写入，约 32 MiB 轮转；中断的调用会标出实际状态。

## 常见情况

- 角色或模型未配置：完成首次设置。
- 可选记忆或语音未就绪：检查所属插件资源，普通聊天可继续。
- 请求所属后台已经失效：等待当前后台连接恢复后重试，旧请求不会自动重发。
- 外部命令无法启动：检查插件配置的程序路径及依赖。
- 已有实例运行：回到原窗口，不要删除锁文件或结束无关 Python 进程。

报告问题时提供版本、系统、复现步骤和相关日志片段。普通日志保留原始错误，可能含路径、用户名或失败片段；已知凭据会脱敏，分享前仍需检查。Agent Trace 含对话与记忆正文，远程诊断发送范围见[隐私说明](privacy.md)。
